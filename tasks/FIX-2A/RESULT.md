# FIX-2A 结果

loomd 将裁决请求、Leader 异常退出、BLOCKED 批次、波次或续作超时、投递不明及项目完成写入持久日志。托管 Super 每批收到一条排队输入，外部 Super 由本机 osascript 通知。默认查询是预览，Super 可用 `--take` 标记领取，`--history` 保留已领取内容。 [协议 v2](../../docs/PROTOCOL-v2.md)

`spawn --handover-from` 把前任简报附到首轮，绑定继任并保存路由后退休前任。波次、续作和未尝试的队列投递改向继任，原派工身份和投递 ID 仍可追溯。曾尝试提交的输入继续按原生会话对账。同角色、同项目的较新活动会话可接收意外退出会话的在途队列。续作复用整批与部分结果截止时间、BLOCKED 合并、STUCK 最近活动和晚到补投。 `ls`、`state` 都可查看在途续作和投递。

Super 在首次 spawn 前写入项目策略。示例按角色配置首选，合并角色与全局拒绝规则，常驻默认 TUI，Worker 默认 headless。Git 排除规则只写项目仓库的本地 `info/exclude`。Auditor 的常规结论走 Leader，满足四种升级条件之一才走 Super 裁决通知。 [策略示例](../../examples/policy.json) · [角色手册](../../skills/loom/SKILL.md)
