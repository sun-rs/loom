# STATE-GATE-1：关键状态转换门禁与 Auditor 窄取证入口（2026-11-28，用户已批准）

设计依据：`docs/research/2026-11-28-skill-adherence-deep.md` 第 D 节，采用方案 Ⅱ 中的两块。

本卡在 ROLE-RULES-1 之后做。提示词预算约束与 ROLE-RULES-1 相同：新增命令的说明只能在被调用时输出，不得写进常驻 skill；常驻 skill 最多加 1 行指向命令名。

## 范围
1. **状态转换门禁。** 以下转换要核对候选 SHA、`rulingsVersion` 和证据：
   - gate 结论
   - 合入
   - 卡结案
   - 别名切换
   - 裁决变更

   缺少可靠终止信号或正文回执时，保持冻结，并挂一条待办，写明缺哪项证据。

   进度、普通回复不受此限，照常投出，标为"未确认"，对应待办保持打开。

   Claude 的 Stop 如果带着未结束的后台任务，一律视为未确认。
2. **格式解析只在可靠终止时进行。** 违规时保留原件和机器原因，阻止状态结案和 gate 流转。不发自动纠正消息。
3. **窄取证入口。** 这些入口要覆盖 Auditor 读文件、搜索被拒的大头：
   - `loom status --card <卡> [--evidence] [--log tail]`
   - gate 包内容
   - 候选 SHA 相对基线的 diff --stat，以及指定文件的 diff
   - 卡的验收命令和最后一次执行结果

   对应的读和搜索不再触发 senior-tool-denied。通读源码、亲自跑测试或构建、仓库级任意搜索、集成操作，仍走一次性例外。
4. **指标。** 误拒单独列为一项指标，并比较前后数值。senior-tool-denied 和 override 的目标是显著下降。

## 验收
- 测试先行。
- 用两个 pilot 的历史拒绝样本回放：误拒率下降，受保护操作的违规执行为 0。
- 固定 Node 26，全量测试 0 fail、0 cancelled、0 skipped。
- 每条消息不得增加模型请求。

## 命令面约束（用户 2026-11-28）
"能合并进 loom status 的就合并，别搞太多的 loom xxxx，最后用户记不住，高级角色调用聊天也乱；可以通过 -- 参数区分内容。"
- 本卡**不得新增顶层子命令**。查询类能力一律作为 `loom status` 的参数，例如 `--tui`、`--todo`、`--card`、`--json`、`--project`、`--owner`、`--overdue`。
- 旧命令保留为兼容别名，帮助里标注"已并入 `loom status --…`"。
