## Git 与提取

- 轮次 diff 比较两次工作树快照。轮前已经存在且内容未变的脏文件和未跟踪文件不计入改动。轮内继续改动已有脏文件时只计增量。隔离测试覆盖未提交改动、轮内 `HEAD` 移动、未跟踪文件、测试断言、路径越界和完整净行数。
- Git 记录每个文件的增删和重命名，检查重命名前后的保护路径及可写范围。`.project/evidence.json` 的 `allowedPaths` 可以按任务覆盖，未配置时 L1 显示未知。测试差异列出删除或修改的断言行，以及新增 `skip` 和 `only`。凭据与 loomd 运行文件从快照排除。临时索引与实际索引隔离。
- agy 解析器识别编辑工具内嵌的验证回包，保留失败和后续成功。Codex 按原生命令及其外层 `exec` 回包关联同一执行，保留真实重跑。证据卡识别带原生 shell 前缀的 `node --test`。
- 限流依据原生错误或运行时终态。普通工具输出中的限流术语和测试文件名不产生限流标签。探查命令的非零退出保留在诊断里，整轮仍可完成。后续同一命令成功时标 `recovered`。L1 的非零诊断只渲染一次。没有可确认的验证命令时，`DONE` 的验证结论为 `UNVERIFIED`。
- Claude 预览剥离 `<pasted_content>`、`<hc>` 和 `[loom:…]`。L1 显示轮中输入数及可确认的中断方。L2 默认省略逐请求 `calls[]`，保留总用量与每项工具的序号、时间。可用 `--with-calls`、`--only-failed` 和命令过滤器展开证据。新 OAR 日志有工具调用记录，原生记录缺失时可用于验证和历史。
- Worker 三行分别是状态与任务 ID、一句结论、`Leftovers & deviations`。有需要时另写设计取舍、旧断言修改原因与替代覆盖、未验证项目与原因。最后一次验收完成后直接回复。

## 对两份 L1 评审的处理

1. **调度与送审。** 新 L1 可判断轮次完成、失败是否恢复及最新验证结果。历史样本的文件边界仍需当时的 Git 证据。新轮次可以直接检查文件清单、越界与断言护栏。决定合入仍需独立验收。
2. **补充证据。** 文件增删、净行数与保护路径来自 Git。摘要保留测试序列和最后退出码，具体错误、设计取舍及完整工具输出在 L2、原件和回报正文中。Orca 自述回执仅用于定位。
3. **误报与漏报。** agy 退出遗漏、Codex 双计、假限流、探查失败污染整轮、重复诊断、包装预览、旧证据卡漏测和预存文件误归属均有定向回归。失去原生记录的 headless 轮次可用新版 OAR 日志中已观察到的工具记录。
4. **过滤与体积。** `--outcome failed` 涵盖轮次失败、显式 `FAILED` 或未恢复的验证失败。已恢复的非零命令可用 `--outcome recovered` 选出。L2 提供失败工具过滤及首三行和末尾摘录，逐请求用量按需展开。
5. **缺边界和证据卡。** 新轮次使用预先记录的 Git 快照。轮前已有未跟踪测试文件的样件未被算作改动。旧证据卡保持原归档，以便区分留存证据和新计算。
6. **中断和追加输入。** Claude 五轮轨迹在 L1 可见。需要核对中断原句时看第 3 轮的 Bash L2，核对追加输入原文时看第 5 轮的 prompts 或原件。
7. **三行回报。** 采纳机械事实由守护进程记录。回报保留结果、偏离、阻塞决策及适用的设计和验收说明。历史缺边界、Git 之外的副作用、未经配置的任务写范围仍需用制品、原件和回报核验。
