# HERDR-LAYOUT-1 — one project = one Herdr space, fixed visible tabs

Base: main @ current HEAD (≥ a7bd0c27). User design (2026-11-26): each loom project lives in one Herdr space; Auditor and Leader are permanent tabs at known positions findable through hc; a third tab runs a read-only loom status TUI for the project. Super and a global loom TUI live in a separate space of their own.

Facts (from a read-only survey; verify yourself): spaces/tabs/panes are drawn by Herdr.app (`~/.local/bin/herdr-app`, home `~/.config/herdr-app/`). A terminal labelled `herdr.space=<id>` and `herdr.tab=<id>` appears there, also when started by `hc run`; only `herdr.space` → new tab in that space; unlabelled, pane-less terminals stay hidden (why t3fn/t3fw are invisible). `herdr-app do space.new --name … --folder … --tab … --argv … --focus false`, `tab.new --space …`, `tab.rename`, `terminal.keep --place tab|right|down`, `terminal.park`; `herdr-app ls` lists ids. Read `herdr-app --skill`, `herdr-app commands`, `~/.config/herdr-app/AGENTS.md`. `hc run --bg` only means "don't wait", not hidden. Closing a pane/tab/space ends its terminals. `terminal.keep` turns on core `keep` (shell replaces a lost program) — check how that interacts with holder exit detection before using it; prefer labels at `hc run` time.

1. **Layout record.** loomd owns `.project/loomd/layout.json`: space id/name (`Loom <project-name>`), tab ids for Leader, Auditor, Status, and the current terminal address and hc name per tab. Create the space/tabs on first `loom up`/spawn if missing (`--focus false`, never steal focus), reuse them afterwards, detect user-deleted tabs/spaces and recreate rather than fail. Stable hc names per project (e.g. `<slug>-leader`, `<slug>-auditor`, `<slug>-status`) so `hc get <name>` always finds the live one; `loom status` prints space/tab and current terminal for each role.
2. **Rotation keeps the position.** A successor Leader/Auditor opens in the same tab (split pane while both live, or a temporary tab), takes over the stable name once the handover is acknowledged, and the predecessor's pane is retired so the tab ends with exactly the live role. No hidden role terminals.
3. **Status tab** (`loom tui --project P`, new): read-only, zero model tokens, refreshes from loomd. Shows: roles and lifecycle, delivery state (queued/typed/stalled/refused/awaiting-user, oldest age), headless workers and their cards/waves, gates and the last verdicts, notifications pending for Super, cost pyramid, release paths, and lets the user open `loom hist` (role/task/grep) and memory views in a pager. Keys only navigate; it never types into role panes. Must stay light (no busy polling; reuse the loomd socket or a cheap interval) and survive loomd hot upgrade (reconnect).
4. **Headless workers stay hidden** (no labels, no pane); they are visible through the Status tab only.
5. **Super space.** `loom super` (or documented manual steps if Super is a user-started terminal) places Super and a global `loom tui --all` (all projects summary) in one space `Loom`; do not move or relabel existing user terminals automatically — offer a command the user runs.
6. **Migration for live pilot-2**: a command that adopts the existing t3fn/t3fw into the new space without restarting them, but do not run it — Super decides when. Document whether adoption has any side effect (keep, pane close = kill).
7. Tests with a fake herdr-app/hc; one real manual probe on a throwaway space you create and delete yourself (never touch other spaces, especially Solars, Loom_next, VPN, Research).
