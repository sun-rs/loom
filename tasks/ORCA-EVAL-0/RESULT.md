## 10 · 无 `worker_done` 时，最终回复能否成为任务结果

### 10.1 · 从 Stop 到 coordinator

1. **取回复。** Claude 和 Codex 的 Stop 可携带 `last_assistant_message`。对有 transcript 补读路径的 Stop，hook server 先接纳状态，再异步读取和重试，把找到的回复补进同一轮的 `lastAssistantMessage`。更新受 Stop 行与 pane 身份约束。内部另保有按 lead turn 对齐的 `acceptedReply`。OSC 7501 只给状态和单行说明，缺少 assistant 正文。 【源码 src/shared/agent-hook-listener/providers/claude/claude-tool-fields.ts:52–71；src/shared/agent-hook-listener/providers/codex/codex-tool-fields.ts:30–43；src/main/agent-hooks/server/server-stop-transcript-reply.ts:58–75、92–141、163–237、242–281；src/main/agent-hooks/server/server-accepted-reply.ts:5–37；src/main/agent-hooks/README.md:3–21、76–80】 【文档 [Agent hooks](https://orca.dev/docs/agents/hooks-memory)】
2. **生成信件。** `TerminalWorkerTurnStops` 订阅状态边沿，按是否需要输入或出错区分 `needs-input`、`errored`、`finished`，并确认仍是同一 Dispatch 和进程。正常结束优先用交付时最新的 `lastAssistantMessage`，再用初始行的同一字段，缺失时尝试读取脱敏屏幕尾部。有的正常结束会受安静窗口或子任务影响。最终 `Last output` 取状态预览的尾部至多 2,000 个 JS 字符单位，经过 capability 脱敏。预览本身还有 8,000 的上限。该分支并未检查 `lastAssistantMessageIsToolOutput`，也未用内部的全长 `acceptedReply`。因此可能拿到完整的短回复、回复片段、屏幕尾部，或只有状态文字。 【源码 src/main/runtime/construction/orca-runtime-agent-transitions.ts:254；src/main/runtime/push/notifications/terminal-agent-turn-news.ts:15–28、63–97；src/main/runtime/orchestration/workers/turn-stops/terminal-worker-turn-stops.ts:127–203；src/main/runtime/orchestration/workers/turn-stops/worker-presence-report.ts:30–31、219–230；src/main/runtime/orchestration/workers/turn-stops/worker-turn-stop-wording.ts:77–130；src/shared/agent-status/contracts/agent-status-types.ts:223–227、330–336】 【文档 [Orchestration](https://orca.dev/docs/cli/orchestration)】

### 10.2 · 任务状态

- **Stop / idle。** `observeWorker(at-rest)` 记录 `resting` 或 `prompt`、确认此前未知的启动并决定是否发信。没有 Task 成功迁移。正常发出的 stop 信也明确说明 Dispatch 仍开着。进程实际退出或丢失是另一路径，本地会失败结算，视重试断路器把 Task 放回 `ready` 或标成 `failed`。 【源码 src/main/runtime/orchestration/workers/turn-stops/worker-presence-report.ts:76–141；src/main/runtime/orchestration/workers/turn-stops/worker-turn-stop-wording.ts:237–239；src/main/runtime/orchestration/workers/lifecycle/worker-exit-observation.ts:29–69；src/main/runtime/orchestration/db/dispatch-context/dispatch-completion.ts:148–205】 【文档 [Orchestration](https://orca.dev/docs/cli/orchestration)】
- **成功报告。** `worker_done` 提供当前 task、dispatch 和 `succeeded|failed`，接受前核验 assignee 与进程。结果保存的是该信的 `subject/body`、来源与可选文件/报告路径。接受后才在事务中改 Task 和 Dispatch、解锁后继、安排可选清理，再唤醒收件方。远端也只在收到有结算权限的报告时走 `settleWorkerReportInTransaction`。外部协调器对活着的受监督 Dispatch 执行 `task-update --status completed` 会被拒绝。 【源码 src/main/runtime/rpc/methods/orchestration/messaging/send-point-to-point.ts:120–199、240–272；src/main/runtime/orchestration/workers/lifecycle/lifecycle-reconciliation.ts:250–313；src/main/runtime/orchestration/db/dispatch-context/worker-report-settlement.ts:162–257；src/main/runtime/orchestration/db/dispatch-context/attempt-task-settlement.ts:34–46；src/main/runtime/orchestration/legacy-remote-home/federation-relay-import.ts:87–105；src/main/runtime/orchestration/db/tasks/task-status-transition.ts:43–69】 【文档 [Worker contract](https://orca.dev/docs/cli/orchestration#worker-contract)】
