# HARDEN-PS-1 — a `ps` miss must not mean "dead"; tests must never reach real CLIs via PATH

From pilot-2 goal-5 merge gate (decision-goal5-merge.md, ruling R24). Base: main HEAD.
1. `daemon/hardening.test.mjs:359` (3 subcases + parent) fails on baseline under the worker sandbox / integration `ps` wrapper. Underlying defect: when `ps` does not list a process, loom treats it as dead and starts another session host, so old receipts no longer match. On the host, a `ps` row miss can trigger it too. Fix: liveness must use positive evidence of death (kill(pid,0) ESRCH with pid+start-time identity, holder socket gone, exit record) — "not listed by ps" alone is "unknown", never "dead". Never start a second session host for the same session while death is unproven; surface `liveness-unknown` instead. Make the test pass in the worker sandbox and on the host; regressions for ps miss, EPERM, pid reuse.
