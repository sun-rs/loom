Problem (pilot-1 evidence): loomd hot-swaps fine, but loom-pty (owns the inner PTY between the hc holder and the CLI, and also does grid/screen parsing, draft verification, overlay/trust handling) and the headless session-host (owns the CLI child) never take new code until the session ends. PILOT-FIX-1..4 could not reach running sessions; the Auditor had to be rotated twice.

Deliver (RESULT.md, Chinese, `STATUS: done`):
1. **Inventory**: list every function now inside loom-pty and session-host; classify each as (H) must stay in the holder (owns fds / must run at byte time) or (D) can move to loomd. Target: holder = PTY fd + raw byte ring buffer with absolute offsets + write(bytes) + resize + signal + exit status + minimal frozen protocol (versioned, tiny). Everything else (xterm grid, screen/adapter recognition, draft verifier, overlays, trust dialogs, submit confirmation, human-input detection timing) in loomd, which rebuilds the grid from the byte stream (snapshot + offset). Identify timing-sensitive pieces (e.g. 800ms human-input pause, writeIf) that need a holder-side primitive and define that primitive minimally (e.g. conditional write guarded by "no input bytes since offset N").
2. **Spike 1 — grid rebuild in loomd**: prove loomd can reconstruct an identical @xterm/headless screen from the holder's ring buffer after a loomd restart mid-session (Claude, Codex, agy, OpenCode TUIs in isolated HOME with absolute binaries; compare cell-by-cell with the live loom-pty grid).
3. **Spike 2 — holder in-place handoff**: old holder spawns new holder version passing the PTY master fd (TUI) or the CLI child's stdio pipes (headless) via stdio inheritance / fd passing, then exits; CLI keeps running, no SIGHUP, output continuity by offset. Check whether node-pty can expose/adopt the master fd; if not, the smallest native helper and its build/ship cost on macOS arm64 + linux. Also: does the hc holder's view (outer PTY ↔ loom-pty stdio) survive the handoff (the new holder must inherit loom-pty's own stdin/stdout to hc)? Measure gap duration and lost/duplicated bytes.
4. **Design**: protocol for holder v3 (frozen surface), migration path from v0/v1/v2 wrappers (they stay until sessions retire), upgrade test matrix (4 CLIs × idle/busy × loomd upgrade / holder handoff / rollback; assert native session id unchanged, acknowledged input count continuous, zero manual action), estimated size of phase B, risks.

Red lines: isolated HOME, absolute CLI paths (never PATH — CCP wrapper), local mock endpoints where possible, only hc terminals you create, no credentials, no Solars/CCP/loom-next, no global config changes. Stop and report BLOCKED if fd handoff is impossible without root or SIP changes.
