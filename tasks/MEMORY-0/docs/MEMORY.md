# Loom 记忆设计草案

记忆归 Loom，按稳定的项目 ID、逻辑角色和访问范围寻址。CLI、模型和原生会话 ID 只标记来源。用户定授权与红线，角色写入并裁决，loomd 只负责存取、索引、限额注入、搜索和引用机检。`loom switch` 沿用同一记忆目录和索引，继任绑定前保留前任的转录及索引游标，随后可继续增量采集迟到事件。继任从同一入口读取。切换不覆盖旧记录或重置保留期，换用任意受支持的 CLI／模型均可取回已保存的内容。[调研与复盘](../RESULT.md)

## 三种范围

- **Super。** Loom 私有数据目录的 `super/INDEX.md` 与 `super/items/<id>.md` 保存在本机，且不进 Git。用户确认或纠正时，Super 更新偏好、红线与生效模型策略入口。项目立项、迁移或关闭时更新登记（项目 ID、规范路径、Auditor）。项目复盘确认可迁移后，Super 提炼教训并显式共享。首轮 ≤400 tokens，优先注入红线、模型策略及登记入口，详情与教训按需查。
- **项目。** Auditor 持有 `.project/charter.md` 和 `.project/rulings.md`，记录带理由及替代关系的正式决定。Leader 在复现、结案或里程碑切换时，将已证实的坑、环境条件和当前任务／验收入口写入 `.project/memory/{INDEX.md,items/<id>.md}`，引用 Worker／Reviewer 提供的证据卡。Auditor 裁决争议。项目笔记沿用 `.project/` 的本地 Git 排除约定，引用 Git 中已有的决策、代码及验收证据。Leader／Auditor 首轮 ≤400 tokens，加载适用红线、章程和裁决入口、当前任务或 ref 指针。Worker／Reviewer 从任务卡和指定证据获得适用约束。
- **会话。** 沿用原生转录投影、会话索引及 `loom hist`。前任在任务边界写简报，继任首轮注入 ≤1500 tokens。旧轮次按角色、波次、轮次或关键词查询。压缩后找不到入口时重读角色索引或简报。

每个新 Markdown 文件存一条事实（≤200 tokens），写稳定 ID、范围、责任角色、原件和核对日期，必要时写到期日或替代 ID。索引每条一行，首轮只加角色对应的一块。经授权的 `loom memory search` 按标题／关键词返回最多 5 条、合计 ≤500 tokens，正文按需打开。最新用户指示与正式裁决解决冲突，旧条目退出默认搜索。路径和 SHA 在写入、注入或引用前复用证据卡 fact-check 核存在。声称目前有效时另查目标 ref、现行策略或环境版本。核对失败或过期的条目退出首轮及默认搜索，责任角色核实后修正。实际进度查 `loom status` 与 Git。必读红线超首轮预算时，角色在行动前读全原件，有缺失或冲突就请有权者裁决。

## 搜索用户问答

- **采集。** 原生适配器扩展现有 `loom hist` 投影。从用户面向 Super 或 Auditor 的直接消息及其可归属的对外回复提取正文，以 Loom 项目、角色、会话地址、原生事件 ID 或偏移去重，记录时间、发送方、回复关系和原件定位。内部派工、工具载荷和模型推理不入索引。只凭原生作者标识或 Loom 投递证据确认身份并配对。缺时间或关联证据时标缺口，找不到对应回复时显示待答或未知。索引与原 CLI 的进程寿命解耦。
- **查询。** `loom hist` 拟支持用户问答过滤、主题词或短语、起止时间及角色／项目。复用本地 SQLite 索引查正文，支持中文子串及日期范围。先限制可访问范围，再返回问题与答案的短摘录、日期、角色及来源。每次最多 5 组、合计 ≤800 tokens，按相同权限按需展开一组或原轮。首轮只给查询入口，摘录注明是历史，不能作为当前授权。
- **隐私与体积。** Super 只查其有权的用户问答，Auditor 限本项目及显式共享内容。索引本地私有、排除 Git 与外部嵌入服务。项目或会话可关闭采集，排除凭据及用户标为不留存的内容。默认以每范围 90 天或 50 MiB 为上限，先触及先淘汰最旧条目。删除同步清理索引和派生摘录、阻止旧转录重入。查询标出覆盖期及采集缺口。原生转录按自身的权限和保留规则管理。

## 三次接续

1. **Leader 换班。** 旧 Leader 的简报指向任务卡及验收证据。继任查 `loom status` 与集成 ref。旧 SHA 仍存在但分支已前进时，按当前 ref 重核验收范围。在任 Auditor 核对交接与在途任务。
2. **Super 一周后换 CLI 重启。** 首轮读 Loom 红线与登记，现查目标项目状态。用户问「上周为什么暂停发布」，Super 按日期和「发布」查到旧 CLI 的提问与当时的回答，再查有无后续裁决，只带入相关摘录。
3. **项目 A 的教训用于 B。** A 的 Leader 复现浅克隆缺历史对象导致验收失败。Super 引用原证据提炼并共享。B 的 Leader 按「浅克隆」查到后，先查自身克隆深度和目标对象，再决定是否采用。A 的裁决仍留在 A。

首版省去自动摘要、专职记忆 worker、向量库、知识图谱、强制压缩重注、跨机同步、平行账本和哈希链。用真实换班和换 CLI 案例比较现有交接基线，记录成功找回的有出处问答、过时误用、重复追问和首轮用量。
