# WORKER-REAP-1 结果

STATUS: done

## 会话生命周期

- 无头 Worker 等待最终结果的原生投递回执。空闲且没有在途消息或待续作时，loomd 按 `workers.warmMs.<cli>` 下线进程，默认缓存窗口为 10 分钟。`loom release` 可提前释放。`spawn --keep-warm` 为计划中的一次续作保留进程，续作获回执后解除保留。
- `offline` Worker 可通过 `assign --resume-attempt` 或向任务排队发信原生恢复。原会话 ID、任务、工作树、转录、历史和证据卡均保留。Auditor 对合入门禁回复 `APPROVE` 后，loomd 在投递结算后关闭该波次已有的 Worker。显式取消也会关闭 Worker。
- 一卡交同一 Worker 做完，包含续做及 R1/R2 不改接口的局部返工。跨卡复用通过 `loom send --next-card` 标明，只限 Leader 确认的同领域同工作树紧邻小卡。默认已用 ≤60%、累计压缩 ≤1，上一卡无已核实事实错误或越权。loomd 按卡记录原生事实矛盾和 Git 越权证据，续卡沿用项目级 Git 保护规则。缺少窗口遥测时显示未测量。换领域、方向被否、R3、造假或越权时新建 Worker，修复卡附精确 RED 复现。
- 卡内已压缩且压缩后新读数显示剩余上下文再次低于 15% 时，在步骤边界交接。loomd 提供含任务、分支、SHA、WIP、裁决和已有验收证据的草稿。Worker 用 `loom worker-handoff` 提交完整交接单，原生结果送达后关闭旧会话。常驻角色默认在首次压缩后的卡片边界换班，Leader 和 Auditor 收到现有换班机制的提示。
- 活动轮次连续 10 分钟无进展，或确认造假、越权时，可中途换人。Leader 可用 `loom worker-handoff <目标>` 获取草稿，确认造假或越权时附原因和证据。原 Worker 由 Leader 决定何时停止，原生记录与证据继续保留。
- 新 Worker 开局收到卡片约定、生效裁决摘录和相关项目记忆。loomd 在派工前验证分支、基线 SHA、WIP 行数和裁决摘要，Worker 修改前用 `loom worker-check` 复核并在首报确认。WIP 统计排除项目管理元数据。核对失败会阻断派工或将首报标记为 BLOCKED，保留原生历史和差异记录。
- Status、状态 JSON 和 Leader 摘要显示会话状态、缓存窗口倒计时、上下文比例、压缩次数、最新结果标签和复用判断。状态按门禁汇总新建、复用、原生恢复、关闭、TTL 下线及阈值退役，另列冷恢复首个模型请求的已记录 token 数和退役时的平均已测量上下文比例。`REJECT` 后新建和恢复两组各记录实际派工及随后裁决、获批的回合数，混合派工回合计入两组。Status 和 Cost 提供项目会话进程树的 RSS。
