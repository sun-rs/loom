## Orca 更新时如何保活

Orca 把 PTY 和 agent 子进程留给独立 terminal host。正常退出、桌面崩溃和自动更新会脱离客户端，存活的 daemon 继续收集终端输出。新客户端恢复 worktree、tab、split 与稳定 pane key，再用 owner 和 incarnation 重附着原 PTY，从序列和检查点继续读取画面。关机、daemon 死亡或明确的完全退出意味着原进程消失。保留的历史只够恢复显示；原生会话的继续工作需要单独的 resume 认领。 [Session restore](https://orca.dev/docs/model/session-restore) · [固定版 session restore](https://github.com/stablyai/orca/blob/b7fd7caa357a170f9fac6a49923f3b9ecf5ed0ea/docs/site/content/docs/model/session-restore.mdx)

桌面更新前落盘应用状态；headless serve supervisor 可以 park，待安装结果再重启。macOS 从签名 app 中准备稳定的 launchd host 副本，Linux AppImage 有代际启动路径。固定版当前协议 62，同时为 1–61 保留旧版路由。新终端由当前代承载；拥有旧 pane 的 daemon 继续响应兼容 attach 和退出，排空后按 owner 证明退役。旧版本双方按协议能力决定是否可请求重绘、查询前台进程或迁移历史。手工终止当前 daemon 需要 owner fencing，也保留各旧代的既有连接。 [协议版本](https://github.com/stablyai/orca/blob/b7fd7caa357a170f9fac6a49923f3b9ecf5ed0ea/src/main/daemon/protocol/daemon-protocol-version.ts) · [macOS host](https://github.com/stablyai/orca/blob/b7fd7caa357a170f9fac6a49923f3b9ecf5ed0ea/src/main/daemon/executable-host/macos/macos-daemon-launchd.ts) · [Linux 代际启动](https://github.com/stablyai/orca/blob/b7fd7caa357a170f9fac6a49923f3b9ecf5ed0ea/src/main/daemon/executable-host/linux/daemon-appimage-generation-launch.ts) · [serve park](https://github.com/stablyai/orca/blob/b7fd7caa357a170f9fac6a49923f3b9ecf5ed0ea/src/main/updater/lifecycle/serve-supervisor-install-park.ts)

## daemon 跟进卡的接口与验收

1. **持久绑定和 launch 幂等。** 每次逻辑启动持久化 `projectId, role, worktreeId, realCwd, operationId, launchDigest, paneName, nativeSessionId, launchState`。PTY 创建后持久化 `hc address, created_ms, pid, incarnation, socket, protocol, bookPath, exitPath`。同一调用者和操作 ID 返回既有结果，异正文冲突。crash 恢复按稳定名查找、比对目录/owner、核对控制握手后才能补录或宣告无法证明。写过首条消息的可能性存在时保留 uncertain。
2. **对账与监督状态。** 接收 TUI 的 readiness 和原生 epoch，跨组件持久按 `owner, incarnation, turnId/nativeSequence` 排序。恢复前对账老投递簿、root hook 和只绑定到该会话的转录，记录原证据的 source 和时间。保留 `delivery accepted`、`native turn stopped`、`worker result` 三个不同事实。
3. **Stop/outbox 和权限。** 用 `project/dispatch/incarnation/turnId/reason` 组成稳定 outbox ID，对权限开关额外绑定 approval ID。先持久化报告和角色转移，再通知上层。只在原生完成同一 turn 后给出经过过滤的 `lastAssistantMessage`，缺少正文时标记证据不足。取消、失败、等待子工作和会话死亡各自产生正确原因。重放上报须幂等。
4. **活 owner 优先，死亡后明确 resume。** controller 重启首先按旧记录连接活的 control socket 并核对身份，不发新输入确认存活。只有确证 owner 结束才消耗重启预算并发起持久化的替换操作。原生会话 ID、项目、目录匹配后调用已实现的精确 resume。新 pane 采到新的根证据后原子迁移角色和待投递指针。可能已写入的旧请求不自动再次粘贴。冲突、登录、权限、不可恢复会话或不确定旧投递交给现有升级路径。
5. **发布与失效验证。** 按版本保留 wrapper 和 hook 程序入口，记录支持的 socket 能力。旧代仍有活 pane 时保留可连接，退出且记录对账后再清理。验证 controller SIGKILL 和新版本重启时同三种真实 CLI 的原 PID、会话、pending/已确认 ID 不变；另测 wrapper SIGKILL、hc 重启、断链、纯排队、paste 后未按 Enter、Enter 后回执前以及原生配额错误。旧 owner 与新工作区并存时应零误发。跨代不使用旧画面作当前写入证据。

## 已复现和剩余失效路径

- **Claude 取消后恢复原稿。** 安装 2.1.331，提交带 ID 的长文本请求，在刚出现工作帧后中断。旧实现没有取消 hook，仍会看到 busy 轮和可编辑旧草稿。现已用新 paint 和 ID + 正文摘要识别取消，保留草稿。正式浸泡由脚本用 `hc keys` 清除它自己发出的确切原稿，之后恢复。没有匹配摘要的手工草稿仍需人工处理。 [旧行为](/Users/sun/Code/exp-relay/tui-orca-1/s-sZcGNz/claude/metrics.jsonl) · [修复复跑](/Users/sun/Code/exp-relay/tui-orca-1/s-nqOsI6/claude/metrics.jsonl)
- **空框清除与 Enter 结果不明。** 在粘贴和 Enter 之间插入人工键入或 resize，自动输入保留在屏幕，可用后续人工操作清除。已经发送 Enter 后屏幕若只保留旧 paint，或者无法得到完整草稿和 native 结果，同 ID 保留未确认，禁止重发。复现位于 socket 竞争、resize 和 held-draft 测试。 [回归实现](../../tui/pty-control.test.mjs)
- **折叠、裁剪和收到但未显示的人工按键。** 粘贴跨多屏或让 CLI 显示计数占位，或让外层输入在内核队列中延迟到 Enter 之后。显示证据不足时会保留待确认。原子检查覆盖进入 wrapper 的字节，没有办法观测尚在外层队列中的字节。生产若需更强保证，需要 hc 提供带 input watermark 的事务。
- **wrapper 与 CLI 同时失活，或 hc owner 崩溃。** 复现方式是控制意图落盘后、首次原生确认前强制终止 owner。已有 PTY-INTEG-0 的对账用例覆盖该断点，本卡 SIGKILL 针对原生 CLI，另行验证新的 owner 和收据。生产冷恢复由 daemon 认领和按状态重放，保留未确定结果。 [原故障注入](../PTY-INTEG-0/RESULT.md)
- **真实账号配额、人工权限与更换客户端版本。** 在隔离回环后端返回 429/400，CLI 可能先显示重试或模型不可用。保留失败状态直到当前边界清楚。真实账户没有主动制造配额耗尽。权限、登录或 hook review 仍需适用的人工决定。部署端还需按上节验收 profile、升级和停机。
