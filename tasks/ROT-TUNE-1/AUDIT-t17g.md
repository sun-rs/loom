# 换班方案 v2 与提示词只读审计（t17g）

1. **方案 v2 的漏洞与易误读处**
   - **B1 门禁放大换班**：未登记 `phase/goal` 时 `rotation-policy.mjs:107` 每过一道门禁就给双方高级角色打 `phase-change`，会把常规门禁变成高频换班；应明确仅显式阶段/目标切换触发。
   - **B3 跨 CLI 折算失真**：`rotation-policy.mjs:49` 用 `inputLastDay / compactionInputTokens` 折算 agy/Codex 压缩次数，但高缓存重背会话（如 `t17g` 95.8% 缓存）总输入远大于真实压缩，会严重误触发；应只计原生压缩事件或非缓存/窗口增量。
   - **F 节核验闭环缺唤醒与超时**：没写明谁唤醒“另一方”执行首报核实、超时多久自动回退前任，也没写核实通过后由 `loomd` 自动发一条解锁消息触发继任者执行“首个动作”。
   - **人工打标落空风险**：C 节 Auditor 每次签收记抽查分母、A 节 P0 登记均依赖手工命令，缺乏强绑定入口极易像 `loom-next` L3 `session flag-error`（0 次）一样无人使用。

2. **现行 `SKILL.md` 与方案 v2 的不一致（含行号）+ 应改由 `loomd` 机械执行的条款**
   - **`SKILL.md:78` 仍是旧阈值**：`loom_new` 写默认 `150000` 与 `rotateAt: "gate"`，`loom-rot-tune` 写“按压缩后剩余比例换班”，均与 v2 E 节（禁剩余百分比）和 B3 冲突。
   - **`SKILL.md:32, 44, 88`（及 `self-rotation.mjs:60,102,174`、`sessions.mjs:531`）与 v2 F 节正面冲突**：仍教前任“首次失败自行重试一次”，但 v2 与 `rotation-policy.mjs:209,254` 已锁死“同阶段失败 1 次即停下报 Super”，重试必撞 `rotation-phase-locked`。
   - **`SKILL.md:79-85` 与 `rotation-policy.mjs:29-36` 格式致命冲突**：SKILL 给的是“按需填写”的 5 条中文列表（且漏了 `判例账本`、`已否方案及原因`、`用户偏好与可信度判断`），但代码硬校验 5 个英文 Markdown 标题（`## Status` 等），照 SKILL 写 100% 校验失败。
   - **`SKILL.md` 全文缺失 v2 新条款**：未写 A（P0 冻结）、C（加严模式+抽查分母）、D（高水位只读）、F（另一方 `verify` 核实首报、换班当天禁改规则、当前事实卡）。
   - **应改机械执行**：60 行/必填段校验、前任只读与继任首轮写锁（`restricted`）、当天规则变更锁（`ruleChange`）、压缩/换班/长等后自动附“当前事实卡”、在途排队消息自动改投继任并写入简报。

3. **交班模板与简报（`brief.mjs` + `SKILL.md:79-86`）缺项与易跑偏句子**
   - **缺项**：模板缺 `已否方案及原因`（最易丢的负知识）、`判例账本引用`、`用户偏好与可信度判断`、`在途消息处置`；`brief.mjs` 未嵌入 `rotation-policy.mjs:284` 的 `当前事实卡`（甚至未显式打印 `HEAD`），且 `1500 tok` 预算易裁掉尾部关键裁决。
   - **易跑偏句子**：① `SKILL.md:79`“按需要填写”与必填校验打架；② `SKILL.md:87` / `sessions.mjs:523,538`“随后等待投递”若无核实通过后的自动唤醒，会导致交接完原地停工；③ `self-rotation.mjs:154` 的 `Take over this role...` 易诱发首轮抢跑干活。

4. **继任者首轮提示（`sessions.mjs:520-539`）评估**
   - **不足以可靠执行，存在 3 处硬伤**：① **首行标签冲突**——同条 prompt 中 `531` 行要求首行写 `DONE/PASS/...`，`538` 行要求首行原样写 `HANDOVER-ACK <uuid>`，极易因多写前缀导致首报失败；② **未明禁首轮决策与当天改规则**，却先灌了完整执行职责；③ **核对完“等投递”缺少解锁续跑机制**——应在另一方 `verify pass` 后由 `loomd` 立即向继任者投递一条“接管已生效，请按交接单执行首个动作”的唤醒信封。

5. **建议的提示词改写（原句 → 新句）**
   - **`SKILL.md:78`**：`上下文阈值默认 150000...`（或 `按压缩后的剩余比例换班...`） → `仅在阶段/波次收口的干净边界换班（不按轮数、时长或剩余百分比）；收到 loomd 换班提示、高水位只读提示或 P0 冻结时按以下流程执行。`
   - **`SKILL.md:79-85`**：`交接单不超过 60 行，按需要填写以下各项...` → `交接单 ≤60 行，须使用固定二级标题逐项必填（中英字段名须与 loomd 校验严格一致）：## 状态与在途（含当前目标、卡片 ID 与首个动作）、## 判例账本、## 已否方案及原因、## 未决事项、## 用户偏好与可信度判断。`
   - **`SKILL.md:32,44,88` + `self-rotation.mjs:182`**：`首次失败随正常投递收到原因，自行重试一次。` → `发起后前任进入只读等待另一方核实继任首报；交接失败即自动回退前任并暂停同阶段换班，报 Super 裁决，禁止自行重试。`
   - **`self-rotation.mjs:154` + `sessions.mjs:531,538`**：`Take over this role...` + 两条冲突首行指令 → `首轮仅做只读核对，禁止派工、裁决或写操作。本轮首行必须是文件末尾完整的 HANDOVER-ACK 行（不要加 DONE/PASS 前缀），随后列出核对过的当前事实卡 HEAD、在途事项与异常点并结束本轮；待另一方核实通过、收到 loomd「接管生效」通知后再执行首个动作，且接任当天未经老方或 Super 确认不得更改既定规则。`
   - **Auditor 节增补一句**：`收到继任首报通知后，对照当前事实卡与交接单核验并执行验证命令（pass/fail）；签收门禁时附带抽查结论（ok/error）与原件路径。`
