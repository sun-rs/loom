# SOCK-AUTH-1 — role identity on the loomd socket must not be self-declared

From pilot-2 goal-5 (ruling R24 ②). Today loomd takes `caller` from the request JSON; any process that can reach the project socket can claim Auditor or Super and e.g. approve memory proposals (R13/R18 only hold for well-behaved callers). Base: main HEAD.
Design and implement per-session capabilities: loomd issues each managed session a capability (e.g. an unguessable token passed only in that session's launch env, or fd-passing / peer-credential + session binding) and derives the caller role from it; requests without a valid capability act as "unmanaged local user" with explicitly listed allowed commands; Super's external CLI gets its own capability (file mode 0600 under the loom state dir, never in the repo). Rotation transfers capabilities correctly (successor gets its own; predecessor's revoked on retire). Check every RPC/CLI command for caller trust, list them in RESULT.md. Keep it simple and same-user (this is not a multi-user boundary), but self-declared roles must stop working. Regressions: spoofed caller rejected for approve/gate/escalate/memory write; rotation; hot upgrade keeps capabilities valid.
