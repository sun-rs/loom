本卡在 TODO-SLA-1 之后做。

## 用户裁决（2026-11-28）：提示词预算是硬约束
"不能最后工作内容没多少，提示一大把"。raft 被放弃，原因就是它做什么都要花传统会话数倍的消耗。

- 角色短核心不超过 15 行。现有 skill 只能删减或下沉为按需查询，不得加长。
- 其余裁决只在涉及其作用域时附带。规则版本过期时，搭在下一次正常投递里补发。不做空投，不发单独的机器题。
- 本卡必须给出各角色"启动注入"和"每回合平均注入"的前后对比，并量出 loom 注入的文本在每个角色总输入 token 中的占比。
- 要设回归上限，任何增长都要给出理由。

## 范围
1. **版本回执（方案 Ⅰ）。**
   - loomd 生成 `ruleVersion`（角色核心）和 `rulingsVersion`（按作用域生效的裁决），并按会话记录"已送 / 已标旧 / 未知"三态。
   - 以下情况把状态标旧：新会话、版本变化、可信的压缩事件。
   - 没有压缩事件的长会话，自上次送核心以来的 token 增量超过约 150k 时，标旧，在下一次正常投递里补发。
   - 状态在 `loom status`（含 `--tui`、`--todo`）里都要可见。
2. **交接屏障（方案 Ⅲ，只用于 Leader、Auditor、Super）。**
   - 继任者的验证并入它的首个真实工作项，即交接单里的"首个动作"；交接单没写首个动作就拒绝发起交接。
   - 释放旧别名需要以下 6 条全部满足：
     1. 新 incarnation 已绑定；
     2. 简报正文的哈希回执一致；
     3. 首个业务回合可靠终止；
     4. 回合中的事实与事实卡一致，且没有冲突动作；
     5. 旧会话已退出或处于只读锁；
     6. 规则和裁决版本都有回执。
   - 少一项就保持当前负责人，并挂一条 `handover-verify` 待办，按 TODO-SLA-1 计时。
   - 对 Claude 高级角色，"可续接"选项要同时满足 v2 的 5 条前置条件，并且由 Super 或用户选择后才生效；默认走新开。
3. **回放夹具。** 本周 7 次交接失败都要回放，结果必须是"通过"或"安全失败"，后者指前任保留、别名不切换。

## 验收
- 硬门槛：受保护操作的违规执行次数为 0。
- 注入预算回归测试。
- 7 次失败回放。
- 固定 Node 26，全量测试 0 fail / 0 cancelled / 0 skipped。
- 每条消息不得增加模型请求。

## 命令面约束（用户 2026-11-28）
"能合并进 loom status 的就合并，别搞太多的 loom xxxx，最后用户记不住，高级角色调用聊天也乱；可以通过 -- 参数区分内容。"
- 本卡**不得新增顶层子命令**。查询类能力一律作为 `loom status` 的参数，例如 `--tui`、`--todo`、`--card`、`--json`、`--project`、`--owner`、`--overdue`。
- 旧命令保留为兼容别名，帮助里标注"已并入 `loom status --…`"。
