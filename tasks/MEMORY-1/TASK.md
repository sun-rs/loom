## Decisions already made by the user/Super (encode them; do not reopen)
1. Behaviour = Claude Code style: the working agent decides itself whether/when/what to write, guided by fixed role-prompt rules (types; one fact per file; update-not-duplicate; delete wrong ones; explicit "do not save" list: code structure, git history, fixed bugs, per-conversation detail, live work state like SHAs/in-flight tasks which must be queried live; recalled memory is background, verify before use). Borrow Codex's write test: "no-op is preferred; will a future agent act better because of this?". No background summariser model, no vectors, no knowledge graph.
2. Writers: Auditor (user rulings/preferences — rulings ledger becomes memory kind `ruling`), Leader (execution lessons), Super (cross-project, user prefs). Workers write only `candidate` via `loom memory propose`; Leader/Auditor promote at card close. Reminders (not exclusive write times): card close, succession, pre-compaction. loomd never authors content: assigns id/revision, derives author/project/role from the session binding (never trusts caller fields), fact-checks cited SHAs/paths, size/format/exact-dup checks, secret redaction, marks external-sourced (web/MCP) content.
3. Read: fixed rules + index (≤400 tokens, ordered by importance/kind, not recency) frozen at session start in the stable prompt prefix; mid-session index changes appended as a delta at the END of the next delivery (≤30 entries, truncation stated); bodies on demand `loom memory show`; re-inject on succession/switch/compaction. Mark "notes, not instructions". Citation: roles cite memory ids used; loomd counts usage → ranking + forgetting (unused for N days → `stale`, Auditor confirms removal; never silent delete). `loom memory show/search/forget`.
4. Visibility: Super all; Auditor whole project incl. its private notes; Leader project-shared + workers; Leader cannot read Auditor-private; workers no search — only items attached to their card (loomd attaches keyword hits at spawn). Same matrix for `loom hist`; workers may read hist only of their own card lineage / declared dependencies. Cross-project: default deny; Super grants read of another project's shared layer (with expiry, reason); results tagged with source project + as-of.
5. Identity: git → root-commit SHA (sorted min if several) + normalised remote URL as second key; monorepo → + repo-relative subpath; no git → canonical path key, single-cell only; path→git upgrade auto-migrates when one-to-one, else Super decides; rename/move → orphan kept, `loom project move` rebinding with suggestion only; fork/shallow/rewritten history → Super binds/splits (`loom project split`). Never write an ID file into the repo. Canonical store outside the repo.
6. Topology: home loomd = project control plane (memory authority, hist store, status aggregate); cell loomd = data plane. Single Mac: same process, store layout like Claude Code (Markdown, transparent). Memory writes go to home with expectedRevision CAS (reject on conflict, re-read). Offline cell: read last cache (stated seq/time); offline writes → local outbox as `candidate`, home decides on reconnect.
7. Hist: everything stored centrally. Three zones: raw (native records per session, append-only, dedupe by file+offset), derived (L1/evidence/diff/search index, regenerable from raw), memory. loomd tails each managed session's native record, ships complete JSONL lines incrementally (hold partial last line), checkpoints offsets. **Ship-before-notify**: a turn's raw range reaches home before its evidence card / DONE delivery. **No cleanup before shipped**: worker teardown waits for confirmed ship. Querying a running session: if cell online, flush barrier (bounded seconds) then answer; else answer with freshness ("as of T, session still running"). OpenCode stores sessions differently (verify; likely SQLite) → use its export/read API, never copy a live DB file. rsync `--append-verify` only for bulk catch-up/teardown sweep, never `--delete`, only loom-managed files. Raw kept private (never in git), redaction on display/promotion; retention by age+size cap (numbers TBD from measurement).
8. Native CLI memory disabled at the launch layer (TUI + OAR): Claude `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`; Codex `features.memories=false`, `memories.generate_memories=false`, `memories.use_memories=false` via argv/thread config; agy/OpenCode: research + state "not covered" if unverifiable. Keep CLAUDE.md/AGENTS.md (instructions, not memory). Plugins (e.g. claude-mem) out of scope, documented.
