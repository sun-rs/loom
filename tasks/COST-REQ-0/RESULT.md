# COST-REQ-0 · 模型请求次数与 token 开销

**结论。** 两轮同任务 relay 实验的 42 个会话、525 次请求中，单用请求次数解释加权开销的 R² 为 **0.004**。会话总输出的 R² 为 **0.891**，每请求平均完整输入的 R² 为 **0.803**。在 491 个跨度更大的历史会话中，请求次数的 R² 为 **0.921**。协调角色也更接近后一情况，实验中 Leader 和 Auditor 各有六个会话，请求次数的 R² 分别为 **0.626** 和 **0.947**。请求次数值得监控，同时应保留每次请求的缓存读、缓存写和输出量。

实验中，最后一次实质编辑或测试之后的 78 次请求占 **14.9% 请求、7.9% 加权开销**。其中 25 次属于本报告可明确归因的精简对象，占全实验加权开销 **2.6%**。Worker 和 Leader 的节省量分别约为 **每会话 7.7k（2.2%）** 和 **20.6k（5.0%）**。Auditor 的主要机会是管控批次通知，而收尾阶段主要承担独立验证与裁决。

## 请求次数、输出与上下文

会话级 OLS 含截距。预测量为请求次数 N、会话总输出 O、每请求平均完整输入 C̄。每个会话等权。实验的留组验证每次留出一整臂的一轮，共六折，以下为汇总 R²。输出与加权开销有公式上的直接关系。会话长度、模型、任务难度、工具回包和缓存命中也共同变化，因此拟合解释观测差异，不能单独识别因果效应。
