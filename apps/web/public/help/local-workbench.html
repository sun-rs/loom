RAH OS 本机操作指南

适用于单 Human、多 Agent 的本机工作台。此指南随当前安装包提供，无需中央账户。

本机恢复 · Agent 配置 · 任务交付

本机恢复

  1. 先刷新工作台页面，区分页面连接失败和 Agent CLI 运行失败。关闭窗口不会停止后台工作。
  2. 在 RAH OS 项目目录执行 npm run doctor:local-core。根据实际检查结果处理 CLI 路径、工作目录或证书问题。Computer 页可复制不含凭据的诊断信息。
  3. 仅当工作台尚未运行时，执行 npm run start:local-workbench，打开终端打印的正式地址。不要对同一状态目录重复启动。
  4. 需要替换运行中的工作台时，先等待 Agent 活跃工作结束，保留状态和记忆。项目的 npm run restart:local-workbench -- --pid <准确PID> --state <绝对状态目录> --build <已验证build ID> 会检查空闲、备份和构建身份，再优雅重启；检查拒绝时不要强杀绕过。

默认持久状态在 ~/.rah/state；使用自定义数据根时，以启动日志的 stateDirectory 为准。不要删除 room.db、Agent 配置或记忆目录来解决连接问题。

Agent 配置

用户自行安装并登录 Codex、Claude、Kimi 或 OpenCode。RAH OS 发现并调用已安装的 CLI，不替你安装 CLI 或配置付费账号。角色与私有记忆属于 Agent 身份，切换模型、effort 或 runtime 不创建新身份。修改后从下一次执行验证配置；普通进程退出不代表任务完成。

任务交付

Room 是协作空间，不是文件目录。先明确任务负责人、助手和审阅者；普通讨论不会自动认领任务。提交后审查固定版本证据，驳回进入返工，最终由 Human 验收。文件预览失败或不支持的格式仍可下载；下载成功不代表 Agent 已读取附件。
