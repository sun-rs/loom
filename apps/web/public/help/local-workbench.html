RAH OS 本机操作指南

适用于单 Human、多 Agent 的本机工作台。此指南随当前安装包提供，无需中央账户。

本机恢复 · Agent 配置 · 首次配置 MCP · 任务交付

本机恢复

  1. 先刷新工作台页面，区分页面连接失败和 Agent CLI 运行失败。关闭窗口不会停止后台工作。
  2. 在 RAH OS 项目目录执行 npm run doctor:local-core。根据实际检查结果处理 CLI 路径、工作目录或证书问题。Computer 页可复制不含凭据的诊断信息。
  3. 仅当工作台尚未运行时，执行 npm run start:local-workbench，打开终端打印的正式地址。不要对同一状态目录重复启动。
  4. 需要替换运行中的工作台时，先等待 Agent 活跃工作结束，保留状态和记忆。项目的 npm run restart:local-workbench -- --pid <准确PID> --state <绝对状态目录> --build <已验证build ID> 会检查空闲、备份和构建身份，再优雅重启；检查拒绝时不要强杀绕过。

默认持久状态在 ~/.rah/state；使用自定义数据根时，以启动日志的 stateDirectory 为准。不要删除 room.db、Agent 配置或记忆目录来解决连接问题。

Agent 配置

用户自行安装并登录 Codex、Claude、Kimi 或 OpenCode。RAH OS 发现并调用已安装的 CLI，不替你安装 CLI 或配置付费账号。角色与私有记忆属于 Agent 身份，切换模型、effort 或 runtime 不创建新身份。修改后从下一次执行验证配置；普通进程退出不代表任务完成。

首次配置 MCP

  1. 先正常启动一次工作台完成状态初始化，再安全停止。准备你信任且可访问的 Streamable HTTP MCP 服务；RAH OS 不会启动示例地址上的服务器。
  2. 在当前状态目录创建 managed-mcp.json，仅允许当前用户读写（chmod 600）。文件最大 64 KiB、最多 64 个唯一 executorRef。示例中地址必须替换为你的真实服务： 
{
  "schemaVersion": 1,
  "executors": [{
    "executorRef": "my-tools",
    "transport": {"kind": "streamable-http", "url": "http://127.0.0.1:9000/mcp"}
  }]
}

远端地址必须使用 HTTPS。服务需要 bearer token 时，在对应 executor 对象加入 "bearerToken": {"source":"file","path":"/absolute/path/to/private-token"}。令牌文件必须属于当前用户、权限 600、不可为符号链接；不要把令牌值写入 URL、浏览器、截图或聊天。

  1. 启动或安全重启工作台。格式、权限或地址非法时会拒绝启动，不会假装已连接。
  2. 打开“设置 → MCP 服务器”，选择已登记的 executor，发现工具、保存服务器，再给 Agent 分配允许使用的工具。执行后的使用记录与目录配置是两个页面。
  3. 没有配置文件表示没有 executor；空数组表示明确清空本机 executor 配置。移除 executor 前先停用相关服务器和分配。修改配置后需要重启；已有 canonical 目录与历史不会被此文件删除。

此入口支持本机配置与文件凭据；OAuth、推荐集成商店和浏览器内凭据编辑尚不可用。

任务交付

Room 是协作空间，不是文件目录。先明确任务负责人、助手和审阅者；普通讨论不会自动认领任务。提交后审查固定版本证据，驳回进入返工，最终由 Human 验收。文件预览失败或不支持的格式仍可下载；下载成功不代表 Agent 已读取附件。
