# Raft 核实后的施工顺序

2026-09-08。依据用户要求和[上游行为复核](../audits/2026-09-08-raft-behavior-revalidation.zh-CN.md)，不再把八项内部反例统一当作 Raft 必修差异。

## 当前批次

1. **开放 Task 接手（A1）**：Raft 有明确的 unassign→open 产品依据。只修原 Task 投递授权；退出条件是原执行结束，另一 Agent 在只收到解除分配的新 Activation 中认领、开始并提交。范围外、未来 Task、已撤销执行仍拒绝；确定性真实子进程不能只 ACK 后退出。
2. **已有认证承诺（A2/A3）**：Worker 提交/MCP 与本地 LAN 重启使用现有 owner 重验等待后的当前凭据。无需新增认证、调度或商业账户体系。不得只改 HTTP 状态掩盖已经落账的副作用；已经执行的外部 MCP 操作如实记录，不承诺回滚。
3. **Agent 确认框串扰（A8）**：旧请求完成不得关闭另一 Agent 的新确认框。在原组件生命周期内修复，真实浏览器验证成功/失败迟到与新操作仍可完成。此项是本地界面可靠性，不宣称官方已解决相同竞态。
4. **统一集成和正式交付**：必需检查、正式 Web 构建、相关双浏览器门禁；确认正式实例空闲，备份、优雅重启、验证冻结构建和真实页面，保留持久数据与私有记忆。未运行的真实模型及官方同条件实验不列通过。

不重叠的 owner 可以并行施工，依赖链和集成验收顺序不变。每项先失败测试，再最小修复，最后验证完整结果；所有检查交由一个集成负责人核对。

## 暂不扩大

A4/A5（跨 Run 转换回执、unblock 历史回执）和 A6/A7（暂停过渡期与认领到期的 Task Artifact）保留已复现事实，先裁决本地合同或补上游实验，不在此批增加更强语义。已有认证、成员、执行围栏和记忆隔离继续保留。

## 当前批次之后

先继续核实并关闭 Task 适用行为：标题/描述修改、删除/关闭区别、负责人和状态的实际权限。按官方证据逐项决定首版范围，不根据路由数量推算完成率。随后按依赖推进 Agent 频道静音、Worker 搜索参数、消息附件交互与跨 Room/DM 寻址；每个页面族完成真实业务与双边状态对照才进入下一项。Wiki/Integration/Action card 仍需适用性裁决。
