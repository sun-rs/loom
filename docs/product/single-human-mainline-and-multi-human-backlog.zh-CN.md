# 首版主线与未来扩展项目

决策日期：2026-09-07。来源：用户明确要求把其他 Human 加入系统、多 Human 与多 Agent
聊天、不同 Human 的阅读/加入限制等多人功能整体打包为未来备选项目，当前尽快完成主线。
本决定取代此前“公开频道未收口不得推进其他页面”的施工锁定。延期不是已实现或已验收。

## 首版目标

单 Mac、本地 daemon、一个 Human 管理多个 durable Agent；Web/PWA 为同一业务入口。
在适用功能范围内对齐 Raft 的视觉、交互和可观察业务结果，不以完整多人产品对等作为发布条件。

- Agent 身份、角色和私有记忆独立于 CLI、model、effort；发现用户已安装且已认证的 CLI。
- Human 创建 Room、选择参与 Agent，指定主负责人、助手和 reviewer，进行讨论和协作。
- 显式 Task 的待办、执行、提交、审查、返工和 Human 验收结果持久、可追踪；普通聊天不强制变 Task。
- 消息、Thread、Search、附件和交付文件服务于上述工作链；刷新、重连与正式重启不丢状态。
- 本机 Computer、配置、诊断和必要 Settings 服务于本机实际使用。

一个 Human 使用多个客户端/自己的设备不等于多人协作。其认证和设备配对不能以本次延期为由删除。
Agent 的 Room membership、Worker scope、执行围栏、私有记忆隔离同样不属于被延期的 Human ACL 产品。

## 未来备选项目：多 Human 协作扩展

状态：deferred / 未启动；无首版日期承诺，不进入当前施工队列，不阻塞首版。
重新启动条件：用户明确要求支持第二个独立 Human，再对整个项目统一评审。

统一范围包括：

- 其他 Human 的加入、邀请、身份生命周期、移除和协作成员管理。
- 多 Human、多 Agent 群聊，以及 Human 与 Human 的私聊体验。
- 不同 Human 的 Room 可见范围、公开/私有发现、浏览与参与权限、加入审批和角色管理。
- 非成员公开频道的专属预览、本人加入/退出、退出后关注及其完整 UI/权限矩阵。
- 多 Human 下任务创建者/负责人筛选、个人通知/收藏可见性、操作归属和并发管理的完整验收。

届时复用现有 Principal、Membership、Room ledger 和认证 owner；不另建多人状态库。
先建立 Raft 同条件行为合同，再补身份生命周期、权限和 UI；沿用 TDD、撤权、重试、恢复验收。

## 已有代码如何处理

本次只调整产品范围与施工优先级，不删除数据、不回滚已验证修复、不新增功能开关或权限旁路。
已有公开阅读/加入等实现保留兼容和安全回归，停止为其单独扩展页面、菜单和多角色对照矩阵。
只在影响单 Human 主线的实际缺陷或安全问题时修改；不为尚未启用的多人场景继续增加工程量。
后续若需隐藏多人入口，应作为明确的单用户 UI 收敛变更测试，不能把规划变更写成已完成隐藏。

通用 TaskCard 阅读入口、共享 MessageArticle、附件/Thread 和导航修复仍服务主线，不随多人项目一起延期。
行为登记含混合范围的条目不能整行标记完成或不适用；当前发布只验收其中单 Human 适用行为，
多人子行为按本文件延期，旧审计保留历史事实。

## 主线施工顺序与出口

这是施工顺序，不是未经代码核验的缺失功能清单。既有 Kernel、AgentHost、Memory 和 Review
已有 owner 与证据，先核对实际接线，再修缺口；不重新建设已经存在的后端。

1. **Agent 配置到真实运行入口**：Agent 资料、角色、CLI/model/effort、工作目录、私有记忆与本机
   Computer 配置指向同一身份；启动/停止/重启/错误反馈消费现有执行 owner。
   出口：同一 Agent 更换运行配置仍保持身份与记忆，UI 与实际 Run 配置一致，失败可恢复。
2. **Room 多 Agent 协作**：参与 Agent、主负责人/助手/reviewer、消息/Thread 与精确唤醒接线。
   出口：讨论与显式行动准确归属，忙时后续工作不丢，不能把诊断输出或 CLI 退出当作回复/完成。
3. **Task/Review 交付**：单负责人、辅助/审查角色、冻结证据、驳回返工、Human 验收与待办投影。
   出口：从 UI 创建到完成是同一持久事实链，刷新和重启后仍成立。
4. **主线页面与本机使用收尾**：上述流程涉及的消息、搜索、文件、通知、本机 Computer 和必要
   Settings，逐个按官方源码/浏览器证据对齐共享组件、视觉和交互，不扩大到多人产品。
5. **首版验收**：正式冻结构建、确定性多 Agent 旅程、故障恢复、双浏览器与正式持久实例；
   真实付费 CLI 验收仍需用户明确授权，不用 fake-provider 通过冒充真实模型验证。

每个环节先列明适用行为和完成出口，按官方来源→当前 owner→失败测试→最小修复→浏览器与
业务结果验收推进；一事一闭，不按页面数量或施工 turn 宣称完成。当前第一至第三项的本地确定性闭环已验收，下一施工为第四项；
证据与未覆盖边界见[收口报告](../audits/2026-09-07-mainline-first-three-closure.zh-CN.md)。

## 追加范围决定：大文件与远程 Computer

2026-09-07 用户明确决定：以下两项与多 Human 一同归入未来扩展待开发，不阻塞当前首版，
不再以“待核实所以继续施工”进入主线：

- 大文件流式预览/传输优化。Raft 的直接 URL 加载不自动证明 Range/206 或按需分段能力；
  扩展启动时再核实官方行为。当前有界附件预览与已有下载继续保持准确限制和失败反馈。
- 添加远程其他 Computer、远程 Host 注册与跨机执行管理。

这不延期单 Human 从自己的浏览器/手机访问本机服务的已有安全 LAN 配对，
也不延期本机 Computer 的实际恢复与必要管理。完整 PDF 工具栏不是已证实的 Raft 自研能力，
从首版必做缺口中移除；现有 PDF 阅读适配保留，不据此继续扩张搜索/打印/批注。

当前进入验收驱动收口：先冻结单机适用行为，每项以源码和官网实操建立证据，
仅修复已复现的适用差异；尚未验证不是已完成，也不自动代表需要重写。

用户明确不需要消息/服务器翻译、界面语言选择或时区选择，全部排除当前复刻范围。删除占位控件，保留已实现的 12/24 小时显示格式；系统时间和 Reminder 时间语义不变。
