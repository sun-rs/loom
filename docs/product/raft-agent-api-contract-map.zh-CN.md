日期：2026-09-08。**这是 `672c596` 的源码审计快照，不是并行施工完成后的交付报告。**
映射时产品代码只读；基线表中的历史测试没有在映射阶段重跑。文末单列之后的施工与当前验证，不能与基线状态混用。
基线中已验证的行为优先回归，不重建 owner；新反例可以重新打开已收口项。

## 产品原则与范围

1. 当前一个 Human、本地 Mac、多个 Agent；审计由 Human 在 Room 对话中临时指派，
   不增设系统专职 reviewer/auditor。普通成员的可读权限不等于可改写他人 Task 或 Agent。
2. 先复刻经过源码/官网操作确认的适用行为，不新增未经确认的产品能力。
   本地认证、持久恢复和执行围栏属于必要适配，不因没有 Raft 服务端源码而撤销。
3. 每批关闭一个完整行为链，再推进下一依赖；独立合同核对、前端取证、已有门禁可并行。
   汇报完成的行为、实际验证层级、剩余差异或退步。未跑的门禁不列通过。

多 Human/非成员公开 Channel、远程 Computer、大文件流式待核实项目继续延期；
订阅/账单/额度/中央账号/应用市场不做；翻译、语言和时区选择页面不在首版。
Reminder 的时间计算参数与“新增语言/时区设置页面”是不同合同，不能删掉已有定时语义。

状态定义：`implemented-awaiting-verification`＝已读到owner/入口，仍需当前候选相应验证；
`partial`＝部分行为/参数或一侧入口存在；`defect`＝明确已发现反例；
`first-release-gap`＝本地单Human协作适用但尚缺；`deferred`＝用户已延期项目；
`approved-local-difference`＝有既有 owner、产品合同和测试支持的有意本地差异；
`not-applicable`＝已排除中央/商业等功能；`decision-needed`＝不能由审计者擅自新增或排除。
`first-release-gap` 是待实现范围，不表示本文件已经完成实现；`decision-needed` 不可改成“已完成”消账。

## 最小施工队列和退出条件

下列顺序依据最初基线；表中 `first-release-gap` 需与文末冻结增量合并读取，不能将已实现的读工具、assign/convert、unblock、profile 和附件重新列为未做。其余具体适用差异保持可追踪，不用“先做最低集”掩盖。

1. **先修已有主链缺陷**：Agent来源Task的Human responder、多Thread显式目标、消息原回执幂等重放、临时审计get/submission/文件可读与轨迹归属标签。维护当前写权限、freshness、lease与fence；安全重试不能因新的basedOnRoomSeq自动变冲突。完整临时审计链只有相关活动不足以证明已读交付文件。
2. **只读基础工具**：history before/after/around、精确message resolve、Room成员/handle、task-list和canonical task-history。复用L3/L5，参数/结果严格有界；不用新队列或浏览器缓存。message read不能自动ACK Inbox或完成Task。
3. **普通消息附件**：先同Room已发布附件读取，再Worker显式文件上传/取消/发消息关联/失败GC，复用L9。Task冻结Artifact的证据语义不因普通消息上传而削弱。
4. **剩余Worker自助基础动作**：task assign/convert/amend/delete/status、本人profile和attention，按表逐动作落实合法权限与实际需要；不得复制一条“成员都可改”总规则。帮助目录列完整语法，默认prompt只教当前必要规则，避免每个API都注入长提示。
5. **Computer/MCP与页面族**：后端动作owner齐全后完成网页真实入口；取证可并行，修复按页面族闭环。App.tsx拆分仅在本项owner需要时进行，不绑定全站改造。
6. **最终同一冻结候选验收**：相关确定性链→全仓既定检查→双浏览器主旅程→正式备份/重启/浏览器→有授权的真实CLI及有条件的设备/长期运行。源或产品代码再变更时，旧gate结果不能直接转移到新候选。

每项至少包括：正常结果、错误/拒绝、重复请求、分页或晚响应（适用时）、刷新/重启持久结果。
对照结果分别记录代码实现、自动化、隔离浏览器、真实CLI、官网同前置对照、正式部署六层。

### 已批准差异与尚缺语义分开计账

- `taskUpdateStatus` 的 Human 最终验收、Task/RunAttempt 分离以及有效 owner 执行围栏为 `approved-local-difference`，已有 [ADR-0020](../adr/0020-task-intent-single-owner-and-secondary-roles.md)、Task lifecycle/review owner 及相应测试。不能为补一个 Worker `done` 命令让 Agent 自行绕过最终验收。Worker 状态转换的其他适用差异仍分别核对。
- 多 Task 批量创建、短号而非稳定 ID 是参数/CLI 便利差异；连续调用已有单项创建能够产生多项任务，不等于“没有任务创建功能”。批量整体原子性或指定其他 Agent 等无法由现有操作得到的语义另列，不用便利差异遮盖它们。
- `assign/unassign` 与正文 `convert` 已完成并见下文冻结增量；仍缺 `amend` 与真正 `delete` 的完整语义。它们不能由已有 progress/closed 替代，也不能由只读通过消账。纯附件空正文转换仍有明确差异。

### Task 管理增量与明确未闭合的父任务

`assign/unassign` 与 `convert` 已在 Worker facade/CLI 实现并通过确定性真实子进程链，范围及独立审计状态见 [闲置任务管理](../audits/2026-09-08-worker-task-management-closure.zh-CN.md)。它们未修改 Human 最终 done。

最初 `taskUpdateStatus` 的具体 gap 是 Worker 仅能 block、不能恢复本人阻塞的父任务；该项已在下面的冻结增量关闭。先前真实三 CLI 门禁仍只证明两个子任务完成与返工、父任务 blocked，不追溯改写那次证据。
