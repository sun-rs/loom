# 当前 Raft 收口执行合同

起点 `672c596`。本计划用于组织 2026-09-08 并行施工，完成证据由各批审计及最终集成验收记录提供，不能用计划复述替代测试结果。

产品边界：一个 Human、本地 Mac、多个持久 Agent；不预设审计角色，Human 通过对话临时安排协作。既有角色数据兼容读取，新增工作优先补通用工具。多 Human、非成员公开频道、远程其他 Computer、大文件流式待核实项目继续延期；中央订阅与商业账号不做。

## 工作顺序

| 依赖顺序 | 完整行为链                                                            | 出口                                                                                                                                                                   |
| -------- | --------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1        | 官方 API 与非 API 合同审计                                            | [75 路由映射](./raft-agent-api-contract-map.zh-CN.md)逐行标来源、实际 owner、权限、参数差异；纠正 21 命令族为 18，不以路由数量计算完成率                               |
| 2        | 合并唤醒目标、幂等回放、Agent 来源 Task 请求 Human 输入、临时审计读取 | 普通同 Room Agent 能读真实 Task/冻结提交/附件，回复准确旧 Thread；变动参数冲突，重复请求不重复投递；写入保留执行围栏                                                   |
| 3        | Agent 查事实的基础工具                                                | 历史/精确消息、成员与 handle、Task 列表及 canonical 生命周期历史进入 Kernel→HTTP→CLI→prompt→真实执行出口；读不认领、不 ACK、不扩大写权限                               |
| 4        | 普通消息附件                                                          | 无 Task 的讨论上传→完成→显式发布消息→其他同 Room Agent 下载原字节；失败取消、GC、幂等与未发布/跨 Room 拒绝                                                             |
| 5        | 其他已确认的适用 Worker 差异                                          | 按接口映射逐条关闭 Task 修改、本人资料、消息搜索筛选等；先核对 actor 权限，不能把“同 Room 可读”推广为任何成员可改写                                                    |
| 6        | 前端页面族及其真实数据源                                              | 最新官网浏览器结果＋冻结源码参数→双边截图与状态差异→原组件/原 intent 修复→双浏览器复核；Skills、附件评论、Agent 静音等无现成 owner 的行为不能用空数组或 Human 偏好冒充 |
| 7        | 集成与正式验收                                                        | 独立反例审计、全仓检查、冻结 Web 构建、必要真实 CLI、持久内容备份与守卫重启、新页面实测；前端/后端/验证残项分列                                                        |

步骤 2 与 Computer 已有重启缺陷可并行；前端官网取证、来源核对与明确 UI 修复可以和后端并行。依赖后端的新按钮等后端出口成立再接线。同一已有文件同时只有一名写入者，新的独立模块先完成专项，再依次接入共享 facade。构建与正式重启由一个协调者统一执行。

## 对旧交接稿的纠正

- 75 个 Agent API 不覆盖全部本机 daemon、文件/记忆、Human 页面合同，必须和表外清单联合审计。
- “已收口”是某一提交上的证据；新复现的反例仍必须修复，不能禁止审查。
- 本机 install/launchd 依赖与未来远程 Computer 实验分开追踪；不依据文本检索结果把整个分发栈移入 `attic/`。本机使用中的 launcher、监督、安装和恢复代码保留原 owner。
- 保留资产真实来历：历史重建物不能重新贴成官方原始源码。新增采用片段单独登记官网 bundle、hash、位置、采用方式和本地 wrapper。
- 截图是视觉证据，真实点击、键盘、焦点、权限、重启持久结果单独验收。差异图不设置像素通过阈值；数据数量或视口/缩放条件不同必须显式标注。
- 不因经过某个页面而顺手大拆 `App.tsx`；仅为当前合同与源码规模限制做必要的 owner 提取。
- 附件评论和 Agent 自静音在起点没有现成 canonical owner；Wiki/本机 Integration/通用 Action cards 的范围另列，不借“不商业化”自动删掉所有本机适用行为。

## 证据工具

`scripts/render-ui-bilateral-captures.mjs` 消费真实官网及本地浏览器导出的 PNG 和记录条件的 manifest，核验图像 hash、实际宽高与 DPR，输出并排图、差异图及未验收状态。支持浏览器响应式模式导出的当前已登录官网视口，避免读取或复制私人浏览器身份凭据。现有 `run-ui-comparison.mjs` 继续承担冻结官方测量回放，二者不能互相冒充。

每个 capture 记录 `kind/path/sha256/capturedAt/url/browser/sourceRevision/environment/state/dataShape`；`environment` 包含 `width/height/dpr/zoom`。不明条件填 `null`，渲染报告会标条件不齐，而不是悄悄补成已测值。新工具只生成人眼复核材料，不自动修改或发布官网、本地业务数据。
