**已经建立“官方设计系统／锁定源码依赖 + 生成展示层 + Loom 适配”的架构，本次已登记迁移范围完成；不能宣称“整个官方 Web 已成为可原样升级的依赖库，Loom 全站只剩薄适配层”。**

当前清单见 [dependency-migration.json](../../frontends/raft/loom/dependency-migration.json)：`plannedMigrationComplete=true`、`openMigrationWork=[]`，但 `wholeSiteDependencyComplete=false`。前者表示约定范围完成，后者保留整站仍有本地组合的事实，不应通过改名或修改布尔值消除这个区别。

- **官方包**：`raft-ui` 提供设计系统和交互原语，按版本锁定，保持一个运行时。
- **官方原件**：选定源码闭包按原字节与 SHA-256 固定在私有分发包中，不在原件上打补丁；它不是官方提供的完整 Web npm 库。
- **生成展示**：生成器从原件提取声明／JSX，显式绑定 Loom 插槽。生成器本身是本地维护代码，升级可能需要调整，不能称作完全无适配的直接引用。
- **保留适配与组合**：SDK 数据、权限、生命周期、路由、Role/Instance 语义属于 Loom；资源型兼容移植、部分页面外框、移动端例外以及记忆/Fork/Side 等专属页面仍有本地展示组合。没有证据可把所有这些代码都概括成“很薄”。

因此当前可对外表述为：**“Loom 以官方 Raft UI 和锁定官方源码为展示基础，已完成本阶段依赖化迁移，保留显式的数据适配及已登记的本地组合。”** 官方依赖未被随意修改的证据，不等于全站最新官网视觉、行为完全一致的证据。

## 官网 UI 变化时的标准流程

1. **确认变化来自哪里。** 记录官网发布版本、相关页面及状态；分别查证官方 Web 源码提交、`@botiverse/raft-ui` 包版本、官网资源版本。三者可能不同，不以网页外观猜源码版本，也不把本地旧 checkout 称为最新。
2. **保存候选，先对比不覆盖。** 获取授权来源的独立候选 checkout／包，保留当前锁。运行 `npm run audit:official-web:upstream -- /官方源码目录`，检查候选提交及 dirty 状态，区分当前不可变依赖与历史 intake 的差异。本地漂移或缺失路径要先解释；历史缺失不自动变成产品待办。
3. **判断影响面。** 将改动沿“原件／recipe → 生成器或直接导出 → Loom 宿主页面”追踪；对照 `ui-contract.json` 和 `dependency-migration.json`。当前工具是字节级三方清单，**不会自动完整计算语义影响面**。包样式、字体及共用组件变化可能影响多个页面，不能只看单个源码文件。仅上游未采用功能变化时，无需扩展产品范围。
4. **分层升级。** 包升级更新依赖锁和资源来源；源码升级更新原件、source-lock 及必要导出，再运行受影响生成器；有接口变化时只调整适配和生成器。保留许可证，不直接改生成结果，不恢复官方云端业务 store。已批准例外仍显式登记；新的 UI 规则偏离按工程契约处理。
5. **验证变化，不重做全站。** 先补行为回归，再运行原件哈希／生成一致性／受影响 UI 契约、类型和构建检查；按影响面做桌面及手机的真实 DOM、焦点、键盘、命中区域及截图核对。共用基础层发生广泛变化时扩大范围。不能取消必要的视觉检查，也不默认重跑后端或付费 CLI 实验。
6. **发布并记录。** 产品变更通过后，按既有流程备份、检查活跃执行、安全重启并验证真实页面；分别记录提交、推送和部署。更新版本锁、来源分类及证据，保留可回退的上一版。仅文档／审计工具变化不重启产品。

若官网已变化而对应源码／包尚未发布，先保留当前可验证版本并记录差距；可取得的授权生产资源只作为独立、显式的兼容来源，不能伪称为新官方源码依赖。不要为了立即追外观而回到手写截图复刻。

## 怎么保证，以及不能保证什么

1. `source-lock.json` 与 `upstream-package.test.mjs` 校验原文件哈希；`upstream-diff.mjs` 对新官方 checkout 直接比对，独立报告本地漂移。原有 intake/ports 保留历史来源。
2. 各类 generated 文件必须等于生成器从锁定源码得到的声明正文；改 JSX 必须通过更新来源或显式外层适配，不能偷偷编辑生成结果。
3. `ui-version.test.mjs` 验证两种包名解析到同一官方运行时，避免组件上下文/样式重复。
4. `dependency-migration.test.mjs` 要求每个导航目的地都在清单中，所引实现文件必须存在。它保证范围不漏记，**不证明该页面功能完整或视觉一致**。
