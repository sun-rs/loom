# Role、频道实例与原生 Session：设计稿 v0.1

日期：2026-09-22。状态：**待评审设计，不是当前产品合同或实现完成报告**。

用户已确认总体方向和下列“已确认”决定。本稿把决定变成可实施合同；标为“建议”的默认值仍可在评审中调整。现行 Room、Agent、记忆策略保持运行，本稿不授权隐式迁移。

配套：[能力与来源核查](../audits/2026-09-22-role-session-capabilities.zh-CN.md)、[反例审查与落地门槛](../audits/2026-09-22-role-session-design-review.zh-CN.md)。

## 1. 目标与不作出的承诺

Role 是可重复实例化的配置。同一个 Role 在不同频道有不同工作实例；每个实例保持自己的原生 CLI session。跨频道不再争用同一上下文和执行通道，频道内成员通过持久消息 box 协作。平台记忆补充经验，不替代原生上下文。

这减少无关上下文混入和跨频道排队，但不保证总 token 降低：多个 session 的共同规则、模型调用和协作消息可能增加开销。单个频道仍可能积累过多内容；Provider 限流、自动压缩和上下文质量问题依然存在。

保留 Room-first 的事实权威：消息、任务、关注关系、交付、执行租约由平台管理；native session 保存模型工作上下文。它们是两种互补状态，不用 transcript 反推任务完成。常驻进程不是持续 session 的必要条件；进程可退出后恢复同一个 session，但不得悄悄新建替代。

本轮不引入多 Human、第三方 MCP 平台管理或自研模型 API harness。

## 2. 已确认决策

| ID  | 决定                                                                                                                               |
| --- | ---------------------------------------------------------------------------------------------------------------------------------- |
| D01 | Role 配置与实例身份分离；同 Role 可以在同频道出现多次，界面提示区分，不禁止。                                                      |
| D02 | 实例绑定一个频道及一条持续的原生工作 session；频道消息列、task 讨论不另开 session。                                                |
| D03 | Role 更新不修改旧实例。实例固定配置快照，显示“模板有新版本”或“实例配置不同”。                                                      |
| D04 | 实例可修改模型与 effort；不在原实例中切换 CLI Provider。配置支持不等于正在生成的请求可以立即改档。                                 |
| D05 | 普通私聊共用原实例 session 和注意力，必须排队，不 steer 正在执行的频道工作。                                                       |
| D06 | Side 是隔离的临时 session；不向主频道通知其存在和内容，不把回答合并回主上下文。                                                    |
| D07 | 持久 fork 在原频道增加新实例，复制历史上下文，不继承原实例任务、未完成交付和执行权限。历史私聊可能随上下文继承，用户已接受这一点。 |
| D08 | 会话损坏先报警；有可用原记录时有限次自动恢复/替代；完全丢失或尝试失败后，由用户选择是否按 box 重建。                               |
| D09 | Guide 默认开启，但受实际接入能力限制。忙时默认仅频道 Human 消息可 Guide；其他实例消息等空闲。                                      |
| D10 | 平台长期记忆独立于 session 生命周期；按授权后相关性读取。Role 等字段是来源信息，不自动等于访问边界。                               |
| D11 | 记忆读、写独立控制；频道默认、成员覆盖；不能仅靠 prompt 执行权限。                                                                 |

后续评审补充确认：普通私聊使用私有 box；Side 可读已授权记忆，但禁止写入记忆。

## 3. 实体和唯一 Owner

以下为逻辑模型，不提前规定数据库表形状。禁止在 adapter 增加另一套任务或消息队列。

| 实体                    | 主要字段与含义                                                               | 单一 Owner                                        |
| ----------------------- | ---------------------------------------------------------------------------- | ------------------------------------------------- |
| Role / RoleRevision     | 稳定 roleId；不可变 revision；CLI、model、effort、prompt、skills、权限默认值 | Kernel 管理配置状态；protocol 定义类型            |
| MemberInstance          | instanceId、channelId、roleId、roleRevisionId、实例配置版本、状态            | Kernel                                            |
| RuntimeBinding          | instanceId、bindingEpoch、CLI 身份、nativeSessionId、能力证据、恢复来源      | AgentHost；Kernel 保存有效 epoch 和执行授权       |
| Activation / RunAttempt | 本次工作目标、交付范围、实例执行租约、实际运行结果                           | 既有 Kernel/AgentHost 分工                        |
| ConversationTarget      | 频道、消息列、task 讨论、私聊或 side box 的唯一目标 ID                       | Kernel                                            |
| MemoryRecord            | memoryId、版本、正文/索引、授权范围、来源、有效/失效/替代关系                | Kernel 管理元数据和授权；AgentHost 管理受限材料化 |

RoleRevision 的变更与实例 model/effort override 分开记录。当前模型参数不是 session 身份键。替代 session 增加 bindingEpoch；新增 fork 则创建新 instanceId。身份从执行凭据推导，不接受模型自报 role 名称或实例 ID。

本次需要后续 ADR 明确替代当前“Workspace Agent 是持久记忆人格”的合同；不把旧 Agent 字段悄悄改名就称完成迁移。Room 账本、序号、鉴权、幂等和任务单一所有者继续复用。

## 4. 会话与调度状态

实例业务状态：active → leaving → removed；故障可进入 needs_attention。执行状态仍以现有租约及 RunAttempt 为准，不另存一份容易漂移的 busy 布尔值。

会话绑定可为 uninitialized、ready、recovering、unavailable。UI 将实例成员资格、执行状态、session 连续性分别显示。首次创建实例后可以延迟建立 native session；无消息时不靠模型轮询。

```text
显式消息/工作事件 → 持久 Inbox/Activation → 获取实例执行租约
  → 恢复同一 session → 提示可读的目标与交付范围
  → 实例读 box → 显式向目标发帖/更新任务 → 确认已处理交付
```

每个实例最多一个主执行 lane；它的频道工作和普通私聊共享此 lane。不同实例可并行，仍受平台并发上限与 Provider 限流约束。建议按实例公平调度，避免无限 drain 一个繁忙频道导致其他已就绪实例饥饿。

发送到消息列/task 的接收者必须是频道当前有效成员；加入频道不自动关注既有消息列/task。关注关系按 instanceId 存储；同 Role 的两个实例不能互相替代或合并计数。

消息可见、待通知、已展示、已处理、任务完成分别记录。模型读过不等于回答过；CLI exit/result 不等于任务完成。消息写入与派生投递保持原子性，通知可重复或丢失后重建。

### 忙时追加与读取窗口

| 输入                              | 忙时                                                   | 空闲后                                                   |
| --------------------------------- | ------------------------------------------------------ | -------------------------------------------------------- |
| 当前频道 Human，Guide 有效开启    | 向当前 turn 发 box 更新提示；Provider 拒绝则保留待交付 | 正常处理尚未完成义务                                     |
| 当前频道 Human，Guide 关闭/不支持 | 持久排队                                               | 按交付顺序处理                                           |
| 其他实例发言                      | 不主动 steer                                           | 按订阅和回复义务处理；不把每条旁听消息都变成一次模型运行 |
| 普通私聊                          | 必须排队，不能注入频道 turn                            | 切换明确的私聊 target，继续同 session                    |
| Side 消息                         | 独立 session 的 lane                                   | 不影响主 lane                                            |

重要：仅不发通知无法保证私聊排队。频道执行凭据不得读取尚未被调度的私聊 box；下一次私聊执行才授予该 target 的读取/发帖能力。对于公共同伴消息，默认“不主动 steer”不等于禁止模型自行查询最新公开历史；若要求严格冻结可见范围，需要单独的快照合同。freshness hold 仍保留，不能因延迟通知而放行过时的业务写入。

Guide 接受回执不能结清义务；回执跨越 turn 结束、压缩、断线时，Kernel 决定重投或后续激活，adapter 只报告实际结果。

### 协作不应变成消息风暴

建议默认：Human 的明确 @ 创建对应实例回复义务；无 @ 按频道显式参与策略投递。实例之间的普通回复更新可读记录；明确请求协作或已有任务义务才产生新的执行需求。终止、静默、订阅边界必须可解释，不靠模型“自觉别互相回应”。具体无 @ 默认策略需沿既有产品合同做差异评审，不能本稿直接改成全员每条必答。

## 5. 私聊、Side、Fork 的产品边界

三种操作均通过现有第三栏呈现，沿共享导航折叠合同。@ 保持公开分工，不能触发私聊。

### 普通私聊：已确认使用私有 box

私有 box 仅 Human 和目标实例可访问，工作仍进入原 session。沿统一显式发帖协议保存回复，避免把 Provider 最终输出变成另一条业务消息权威。并非必须复制整段历史到 prompt：发送目标定位和权限，让实例主动读取。

用户于本稿后续评审确认私聊采用私有 box。直接输入 session 并提取最终回复不进入本版实现范围；私聊仍通过显式 box 发帖形成业务回复。

普通私聊是**访问隔离，不是模型上下文隔离**：内容已进入原 session，后续公共回答可能引用它。不能向用户承诺模型永远不会泄露。需要上下文隔离时用 Side。fork 会继承截至分叉点的私聊上下文，但不继承继续读取原私聊 box 的权限。

### Side：隔离 session 还不够

采用 Provider 经验证的临时 fork 或等价隔离能力，标明复制截止点；不能用“新 session + 若干摘要”冒充完整 fork。原生不支持时显示不可用，文件复制作为单独验证项目。

已确认：Side 可以读取已授权记忆，不允许写入记忆，包括修改、删除及通过后台任务间接写入。工作文件默认只读、不具有公共频道发帖或任务认领权限仍为本稿建议。原因是即使不回写主 session，共享文件/记忆/外部动作也会改变主工作环境。要允许副作用必须显式扩展此边界。

Side 记忆禁写是用户确认的产品合同，不提供普通成员覆盖来放开写入。原生官方资料未证明所有 CLI 的 side 都禁止记忆写入，因此不能借其名义宣称隔离已实现；须验证原生自动记忆和文件访问同样受限。临时 session 不保证供应商日志无留存；关闭 Side 后撤销凭据并清理平台临时状态，保留最小操作审计，不把正文写进主频道。

### 持久 Fork：新成员，不是旧成员继续执行

1. 捕获源 instance、bindingEpoch 和确定的已完成 turn 截止点；正在执行的工具不作为已完成工作复制。
2. 先创建无执行权限的待初始化新实例，调用经过版本验证的原生 fork。
3. 验证独立 native ID，绑定新 instanceId；签发新凭据，撤销/替换复制环境中的旧平台凭据。
4. 注入新身份和“未继承任何任务所有权”的显式说明。不能依赖 fork 后 system 参数一定覆盖旧指令；不同 CLI 必须实证。
5. 原子激活成员资格和初始交付；最后向频道公布新成员。中途失败可重试/回收，不留下两个有效接收者。

已有任务只能走正常转交或 helper/reviewer 授权。上下文中曾出现的工具 token、旧命令和文件路径不能成为新实例权限。私聊历史随 fork 进入上下文这一事实显示在操作说明里，不逐次要求额外确认。

## 6. 模型调整、故障与恢复

模型/effort 切换采用现有能力，建议在当前执行结束后生效并显示待应用配置，不偷偷取消工作。记录期望参数、实际参数、native session ID、能力/版本；不支持同 session 调整则失败说明，不能回退新建。配置版本与 RuntimeBinding 身份解耦是迁移重点。

故障处理：停止新派发 → fence 旧 epoch → 核实原记录/认证路由 → 尝试受支持的恢复 → 必要时原生 fork 替代 → 原子绑定新 epoch → 按持久未处理义务继续。

建议每个故障事件最多一次原 ID 恢复和一次 fork 替代；相同错误不自动循环。这是建议上限，可调整。fork 不能修复无效认证本身，不能在未验证 Provider 兼容性的情况下复制文件绕过错误。凭据变化不暴露秘密，只记录认证配置指纹及路由。

原记录丢失或恢复失败时，进入 needs_attention，用户可选择根据 box 重建。重建标记 context_reconstructed，保留旧 lineage 和新 ID；禁止声称上下文连续。已有工作是否已经产生外部副作用未知时先核对幂等操作/工作树，不盲目重跑。

移除成员撤销后续读取/写入与调度资格，安全结束活动工作，保留账本和历史身份；任务走显式转交。移除后再添加同 Role 是新实例；恢复旧实例应是另一项明确动作。

## 7. 平台记忆

长期记忆独立于 native session。删除 session 不直接删除平台记忆；来源删除、用户删除记忆、撤销权限分别处理。不能将用户上一轮对常见产品的理解当作所有厂商的事实。

建议基础记录：memoryId、revision、title、正文引用、scope、sourceRoleId/revision、instanceId、channel/targetId、CLI/model/effort、session lineage、source message IDs、创建时间、作者、有效状态、替代关系。来源元数据由平台补充，模型生成的结论仍可能错误。

读取链：当前凭据授权范围 → 有界轻量入口/查询 → 相关条目 → 按需正文 → 有权时查询源消息。不要每轮注入全平台完整索引。索引不可把无权正文的标题和摘要泄露出去；来源 session 只作为可定位诊断/上下文证据，不作为必须存在的业务数据库。

建议默认：普通频道实例开启读写，作用于当前频道及显式授予的共享记忆；私聊产生记忆默认继承私聊可见范围，不能自动公开。跨频道知识通过共享 scope 明确授予；可以配置仅同 Role 来源，但不因改模型、prompt 或 RoleRevision 自动清空旧记忆。此默认是评审建议，不是已确定实现。

并发写用 memoryId + expectedRevision，保留冲突和版本；不能两个实例覆盖同一 MEMORY.md 最后写者胜出。允许纠正、失效、删除；索引更新与正文版本一致。用户撤销权限后立刻拒绝后续访问，但不能从已经载入的模型上下文里擦除知识。

**权限落实门槛**：应用服务对读/写分别鉴权；原始存储不能被受限实例通过 shell、路径跳转、符号链接或旧材料化目录绕过。需验证 OS 沙箱/文件代理/受限挂载的实际隔离，并处理 Provider 自带 auto memory 和全局配置目录。若当前同 OS 用户无限制 shell 仍能访问原文件，只能报告隔离未实现，不能显示“已强制关闭记忆”。这不要求接管用户 Provider 账户。

源码引用/历史查询默认通过平台授权工具，不向所有实例公开其他 session 的原始文件路径。原生 transcript 可能含私聊、凭据和内部配置；“互相查上下文”应是额外的授权能力，不作为通用默认。

## 8. 上下文、用量与质量观测

展示：native session 连续/恢复/重建状态；实际模型/effort；Provider 报告的当前上下文量和窗口；已观测压缩次数；最后更新时刻。缺失为“未知”，不是 0。压缩事件要去重，不能把重连事件或 watchdog 超时算作一次成功压缩；未能读取旧历史时只能叫“本次监测到的次数”。

分开统计当前上下文、每请求输入、缓存输入、未缓存输入、累计输入和输出；累计 70 万并不意味着单个上下文装了 70 万。Provider 不同计量口径必须保留原值及标准化定义。窗口/定价阈值从实际配置与能力证据取得，不写死某型号数字。

验收使用固定 Git revision 的真实有限范围审查：定位问题 → 比较优化方案 → 多轮追问证据 → 关闭恢复 → 再追问早期细节；增加两个频道并行互不相关任务、同频道协作和私聊/Side/Fork。原生 CLI、Raft、RAH 用相同模型档位、工具和工作材料，分别报告冷/热缓存、session 历史、记忆配置、生成次数、未缓存输入、延迟、遗漏/误报/有效引用。不能用新会话对旧会话的速度或一句你好宣布架构胜出。

## 9. 分阶段落地与迁移

1. **合同冻结**：评审本稿，补 ADR，列明现行 Agent 身份/记忆/session key 合同的替代范围。先完成能力探测和权限可行性的小实验；不调用模型也能验证部分协议/schema。
2. **身份与绑定**：RoleRevision、instanceId、bindingEpoch，测试同 Role 多实例、模型调整不换 session、恢复防双跑。只在隔离数据启用。
3. **频道执行**：沿原 Kernel 迁移接收者/关注/任务身份，完成同实例串行、跨实例并行、Guide/等待、故障交付与无消息零模型调用。
4. **私聊与分叉**：先私有 box，再逐 CLI 验收持久 fork、替代恢复与 Side。不支持能力准确禁用。
5. **平台记忆**：先存储、版本和真正读写权限，再入口/检索；默认策略通过实测后启用。不得把原 Agent 私有 notes 批量公开。
6. **旧数据迁移与发布**：维护 oldAgentId→Role/instance 映射，旧作者/任务引用永久可读。一个旧 Agent 跨多个频道的 native session 不能同时绑定给多个新实例；由迁移策略选择一个继承者，其他通过已验证 fork 或用户选择 box 重建，明确历史混合上下文与来源权限问题。

迁移前备份且静止相关工作；新旧执行器不能同时消费同一交付。记录迁移操作 ID、版本、回滚点。新模式已产生工作后不能靠旧二进制直接回滚新库；需要前向修复或停机恢复并说明新增数据处理。正式发布仍执行既有测试、真实浏览器和安全重启合同。

本稿不迁移数据、不改变默认 memory、Guide 或 session 策略，不重启服务。
