# 官方 UI 依赖升级与 Loom 接线方法

Loom main 的产品 UI 只有 `frontends/raft`。我们的目标是复用官方实现并保留
交互规则，自己维护业务接线；不是根据截图重新制作，也不是宣称整个官网已成为
可无条件替换的依赖包。现有所有权边界与升级程序由 AGENTS.md 和
[依赖迁移合同](official-dependency-migration.zh-CN.md)共同约束。

## 五层所有权

| 层                 | 本地位置                                       | 修改方法                                                                         |
| ------------------ | ---------------------------------------------- | -------------------------------------------------------------------------------- |
| 官方组件/设计规范  | npm alias `raft-ui`；`rui-resources.lock.json` | 升级精确包版本，核对 changelog、声明、CSS、字体与官方指南                        |
| 选取的官方页面源码 | `upstream/raft-web-source`                     | 原文件不可修改；用独立官方候选进行 diff，原样更新选取闭包及 source-lock          |
| 提取的展示代码     | `loom/Official*.generated.tsx`                 | 修改对应 `scripts/official-web/generate-*` 的提取/接线，然后重新生成；不手改输出 |
| 资源兼容移植       | `rui-v6-ports.json`                            | 保留原版本、摘要、差异与测试，不能随组件升级冒称新版页面源码                     |
| Loom 接线/专属页面 | `loom/`                                        | SDK 数据、事件、权限、路由与登记的例外；复用官方场景组件，不另造通用按钮体系     |

官方 stores 不接管 Loom 状态。Role 配置/不可变修订、冻结的实例身份和执行配置、
实例连续 CLI Session、Channel 消息盒及共享记忆分别遵守目标合同；Kernel 是持久
业务所有者，AgentHost 是 CLI 生命周期所有者。UI 更换不能改变投递、授权、因果屏障、
未知结果核实或私密隔离。原生 transcript 是诊断，不是 Room 事实。

## 每次升级的执行顺序

1. 分别核实官网 Web 构建、npm 组件包、公开源码、Computer 和中央 Server 版本。
   它们独立发布，不能用其中之一推定其他版本。下载到独立临时目录，不先改生产锁。
2. 对页面源码运行 `npm run audit:official-web:upstream -- /path/to/candidate`。
   先确认候选提交和干净状态，再看 sourceDependency；历史 intake 差异单列。
   exit 2 必须解释漂移/缺路径；exit 0 也不是页面验收。
3. 对组件包比较旧/新 changelog、导出声明、CSS token/recipe、字体、peer dependencies。
   列出破坏性变更以及实际 Loom 消费者。区分包已实现、页面需接线、仅规范新增。
4. 为实际变化补失败测试。更新宿主/页面 alias 和选取闭包的宿主 peer 元数据、npm lock、
   资源文件/指南摘要；官方原始 TSX 不修改。canonical/legacy 导入必须解析到同一实例。
5. 类型与构建检查后，按受影响范围检查消息、表单、移动端和分栏；验证点击、焦点、
   disabled/loading、Escape/返回、草稿保护和窄列布局。包共享样式变更可扩大前端检查，
   不因此启动全后端/付费 CLI 验收。物理手机与桌面390宽模拟分开记录。
6. 安全部署：确认无活跃执行/待清理工作，备份状态，生成不可变 Web 资源快照，优雅
   重启确切服务，比较业务数据/推送订阅并读取正式新页面。文档变更无需重启。
7. 更新验收证据与当前状态，提交/推送 main。回滚使用上一提交的成对包锁与资源快照，
   不清空数据库、浏览器消息、订阅或原生 session 来掩盖问题。

## 2026-10-26：0.10.5 → 0.35.1 的范围

官网 Web/Server 核实为 1.21.34；公开源码仍为 db5e399（1.21.23-source.1）。
独立 clone 对比：选取闭包90文件相同、无本地漂移。本批只升级组件包，原始页面闭包
和资源移植的版本标签保留。npm 下载包提供完整可用的 JS/CSS/类型与指南。

| 变动                                                   | 消费与处理                                                                                                    |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| 消息行 article 及可访问名称、工具条测量                | 现有官方 MessageItem 组合直接继承；检查消息定位、渲染及窄屏。没有把业务已读映射为虚构回执                     |
| 表单1.5px边框、容器宽度响应、手机可输入 ComboboxSelect | 运行时表单直接继承；手机筛选模型、effort/Fast联动及取消草稿确认实测，无保存正式配置                           |
| hover、选中、搜索高亮、内联标识、Toast                 | 官方组件默认实现随包更新；旧 token 官方仍提供到1.0的弃用别名，保留不可变旧源码而非全局替换                    |
| 分栏底层、侧栏披露与 inert                             | 复验既有桌面分栏和手机返回；原页面 useResizablePanel 的宽度策略仍来自 db5e399，不冒称已实现官网所有新拖动策略 |
| 主题选择、动态滑动、下拉刷新、新 ChoiceList            | 包具备能力不等于页面接线。本批保留已授权 light/dark/system 与紧凑手机版，不额外自编新主题/滑动流程            |
| 字体                                                   | 继续通过现有本地字体映射交付，保持官方字体体系，不引入外部字体网络依赖                                        |

0.12取消的 sheet 参数在实际消费链中未造成类型错误；0.23新增容器布局需要有确定
父宽度，通过角色资料与运行时表单检查。没有通过修改生成代码或 source-lock 原始
摘要掩盖差异。源码检查中的3项过期断言指向旧组件位置/较早保护表达式，改为跟随
现有委托组件及更强的 unresolved-intent 条件，产品行为没有为测试而倒退。

这套方法现在可用于正式升级，但“升级官方包”与“官网全站最新交互一比一”是两个
验收范围。公开页面源码落后时，应明确保留差异，不能以猜测补全来冒称原样复用。

## 2026-10-26 页面覆盖补正

新增文件发现现已加入 upstream-diff：candidateDiscovery.untrackedFiles 枚举候选
packages/web/src 中未进入原采用清单的文件，pageParity 独立标为 not-evaluated。
当前公开候选检出83个未分类文件；它们不等于新增功能或必须采用项。

默认分栏必须独立验收，不能以组件导入替代：官网1.21.34普通侧栏240（200–400），
列表380（240–640），正文最少360；动态选中时左栏最多占可用宽度一半。
本批采用发布资源的注册表及宽度函数，原始选取源码保持不可变；
Discovery 和 Memory 使用该计算，普通聊天／角色／计算机／设置保持已对齐的240。
保留各页已有用户宽度；不重置用户设置。第三栏拖动扩展/折叠、旧840px行预览阈值
仍需单独更新，不宣称完整新版分栏协议已经迁移。

主题页仍未接线；已定位官方 SettingsPanel-Cg0my9Pp.js 中完整主题组合，
下一批应移植展示并绑定本地个人偏好，不能直接复制官方账户计费/服务器store。
详细差异见 ../audits/2026-10-26-official-web-page-gap.zh-CN.md。
