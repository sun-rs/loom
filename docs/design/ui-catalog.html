怎么用：ui-component-spec 技能

技能文件：.claude/skills/ui-component-spec/SKILL.md。任何 RAH OS 的尺寸 / 样式改动、任何新组件对齐 Raft，都走这条流程。

A 级：冻结上游源码可判定 → 本地验证即可

参数能从 docs/evidence/raft-web-*/ 的冻结产物里读出「class → 声明」的， 不需要开实时双边。做法：

  • 在冻结 CSS/JS 里定位该 class 的规则，登记 source 为文件 + 具体行/偏移。
  • 用校验器把 RAH 的值解析到同一个上游字面量：node scripts/ui-component-spec.mjs。
  • 用真实 Chrome 门禁证明计算值确实等于它：--expect-spec。
  • 汇报时写 「本地验证」，并写明是哪一行冻结源码。

典型 A 级：长宽 / 内边距 / 边框宽度与颜色 / box-shadow / 字号字重 / transition 时长 / outline / 同值 token 替换。

B 级：依赖运行时状态 → 必须同条件双边实验

值不写在 class 里、而是由运行时决定的，必须先做同条件双边实验再动：

  • hover 的出现时机与延迟、动画中途的插值
  • 焦点走向（Tab 顺序、focus 落到哪个元素、:focus-visible 是否命中）
  • 响应式导航（断点两侧谁显示谁隐藏、侧栏折叠行为）
  • disabled 的判定逻辑（什么条件下才 disabled）
  • 分组与排序（分区怎么分、行怎么排）
  • 时间格式化（相对时间 / 绝对时间 / 何时切换）

同条件的含义：同一视口、同一主题、同一登录态、同一数据形状，上游与 RAH 并排读 computed style，不读截图估读值，不读模型口述。

C 级：措辞纪律

  • 只有真的做过实时并排比较才可以写「双边验收」。
  • 没做过就写 「本地验证」，并说明依据（冻结源码行 / 门禁输出）。
  • 没有证据又想改的，写进 pending，不要写成 override，也不要写成「已验收」。

响应式采样规则

任何触及该组件的断点，两侧都要采：例如 md（768）必须同时采 767 与 768； 另外固定加 1440×900 与 390×844；组件若有 max-height 分支，该分支也要单独采一次 （例如 1440×600）。视口清单写在 spec.gate.viewports 里，门禁按它跑。

步骤

1. 划定组件与改动边界

  • 选定一个共享组件（例如 .sq-btn、聊天侧栏行家族），列出它的类名集合。
  • 只改这个组件的规则。顺手看到的其它偏差写进「挂起」，不在本批次改。

2. 按分级取证

  • 先判定每个参数属于 A / B 级，再决定要不要开实时双边（见上「取证分级」）。
  • 上游发布产物的 CSS/JS 冻结在 docs/evidence/raft-web-*/，其 sha256 由校验器计算，不是声明。
  • 登记上游元素：element / source 文件行 / version（release + commit）/ values / states。

3. 写规格文档

docs/design/component-specs/<name>.zh-CN.md，固定小节： 上游来源 → 上游声明（逐字来自 CSS） → RAH 现状 → 本批次的改动边界 → 挂起（无同条件证据，不改） → 自动检查要求 → 执行记录。

4. 写规格 JSON

packages/ui-tokens/specs/<name>.spec.json。字段清单与归一化规则见 references/spec-schema.md。要点：

  • rules[].declarations 与 browserExpectations 只能写上游字面量，禁止出现 var(。
  • 每条 tokens 都要在 tokenContract 里说明上游是怎么产生这个数的。
  • 每条 rules/overrides/pending 都要有 source + reason（例外还要 since + evidenceNeeded）。
  • probes 是探针清单的唯一来源（门禁与校验器都读它）：{id, selector, disabled?, interactive?, capture?, coverage?}。

夹具里缺任何一个已声明探针，门禁硬失败，不跳过。

  • fixture、gateScript、fixtureMarkupFile 把报告绑定到夹具字节、门禁程序字节与渲染后的 DOM。

5. 基线 → 同值令牌 → 有证据的差异

  1. --write-baseline：先把当前计算值存成基线。
  2. 把硬编码值换成同值令牌（先不改任何数值），再 --compare，diff 必须为空——这才叫证明「什么都没变」。
  3. 只改「本级取证站得住」的项：A 级凭冻结源码行，B 级凭同条件双边实测。不允许 7→8、15→14 这类顺手取整。
  4. --expect-spec：证明计算值等于规格里的上游字面量。

6. 例外与预算

  • 白名单只能缩不能涨：新增 overrides 必须带 source（指向证据）+ reason + since + evidenceNeeded。
  • 预算在 packages/ui-tokens/specs/ratchet.json，与 git show HEAD: 比对，工作区改动无效。
  • ratchet 尚未提交时，--uncommitted-ratchet-preview 只是预览，不是模式：先让人审阅

docs/design/component-specs/baseline-2026-09-12.zh-CN.md 再提交 ratchet。该 flag 永远不进 package.json。

  • 不确定的写 pending，不要写成 override。

校验器的六条机械约束

逐字取自 scripts/ui-component-spec.mjs 的头部注释。

  1. EXPECTATIONS ARE UPSTREAM LITERALS. `rules[].declarations` and `browserExpectations` may not contain `var(`. Comparing a RAH token against itself proves nothing, so the expectation names the upstream value and the checker resolves RAH down to it. See ./ui-component-spec-normalize.mjs for the canonical comparison form.
  2. TOKEN VALUES ARE DERIVED. `tokenContract` states, per geometry token, how upstream produces it (`--spacing * 7`, a lucide `size` attribute, a named upstream custom property). The checker reads those constants out of the frozen evidence CSS and recomputes the literal, so editing `--control-7: 28px` to `99px` fails.
  3. PROVENANCE IS COMPUTED, NOT DECLARED. sha256 of the evidence CSS/JS is computed with node:crypto, and the `upstreamRules` the spec quotes are re-parsed out of the evidence CSS and compared declaration by declaration. Editing `cssSha256` to zeros fails.
  4. THE BUDGET IS A COMMITTED RATCHET. Counts and budget live in packages/ui-tokens/specs/ratchet.json and are compared against `git show HEAD:` of that file. A working-tree bump is inert.
  5. AN EXCEPTION MUST BE FALSIFIABLE. Every override and pending entry carries `since` and `evidenceNeeded`.
  6. COVERAGE IS BY ELEMENT, NOT BY CLASS-NAME TEXT. A committed `*.matched-rules.json`, produced by the real-browser gate, lists every rule that actually matches each fixture probe; any unregistered rule touching a spec'd property fails. The report is invalidated by content hash whenever the CSS inputs change.
