# Herdr 托管 Loom 运行时的实验方案

日期：2026-11-05。状态：实验设计与静态预检完成，尚未运行候选适配器或付费模型。全批排除 Claude Code，包括通过其他 CLI 启动的子进程。配置见[固定实验清单](../evo/evidence/2026-11-05-herdr-runtime-study/plan.json)。

## 要作出的决定

实验只回答三个问题：Herdr 能否减少 Loom 自维护的进程管理代码；原生终端观察与接管是否解决实际问题；为此切换交互式 CLI 是否损害可靠性、资源占用和成本。最终允许三种结论：引入托管层、只引入终端观察入口、维持现状。

关闭网页后继续执行、实例并行、同 session 恢复和 daemon 自动收发消息，Loom 已经具备。这些只能作为等价性要求，不能计作 Herdr 新增收益。GUI 外观漂亮、跑通一个回答或使用更少的本地代码行，也不能单独证明引入有价值。

## 对照组与归因

| 组           | 进程托管                  | CLI 运行方式                                       | 比较目的                                         |
| ------------ | ------------------------- | -------------------------------------------------- | ------------------------------------------------ |
| A 现有 Loom  | 当前 AgentHost 与进程管理 | 当前结构化接口与回复路径                           | 固定产品基线                                     |
| B 仅更换托管 | 独立 Herdr TUI session    | 保持 A 的 CLI 参数、原生驱动和输入输出协议         | A 对 B 识别托管的收益与代价                      |
| C 交互式候选 | 与 B 同一固定 Herdr 版本  | 普通交互式 CLI，借用既有客户端的会话解析与输入转发 | B 对 C 识别运行模式变化；A 对 C 衡量最终产品影响 |

B 如需通用 IPC 转接，转接代码、进程、故障面和内存都计入候选；不能藏到测试脚本中。PTY 会改变 stdio，不能把原结构化驱动直接放进终端便宣布等价。若 B 必须复制各家 CLI 的轮次状态机，停止这条直接替换路线，并记录原因。

C 内对同一运行分别打开和关闭观察视图，核对输入、模型请求和原生 session 不变。人工接管另列场景，不能把接管后用户多发的指令算成纯观察成本。

先沿 Alma 已有的 Herdr TUI 路线，不把新版 herdr-core 混入同批结果。新 core 仅作后继候选，其 API preview、会话恢复和输入语义单独登记。已取得的上游源码快照不等于本机 0.9.1 服务的源码；执行前须匹配二进制版本、协议和对应来源。

## 先复用哪些代码

| 来源                       | 实验使用范围                                                       | 不作为新业务 owner 的部分                              |
| -------------------------- | ------------------------------------------------------------------ | ------------------------------------------------------ |
| Roamgate MIT 固定源码      | Herdr socket／终端桥接、会话定位、原生日志解析、历史窗口与增量读取 | 不接入其工作区助理、任务调度或另一套产品页面           |
| Alma 0.4.403 本机发布实现  | 核对双后端接法、session 关联、文件偏移分页和聊天／屏幕切换         | 作为实现参考；没有取得公开完整仓库，不列为完整源码依赖 |
| Sheprd Apache 2.0 固定源码 | 借鉴已运行 CLI 的只读投影与原生输入区交互                          | 区分原会话观察路径与它另外创建 ACP 会话的路径          |

沿用 Loom Kernel 的 Channel、Inbox、Activation、幂等和执行围栏，AgentHost 仍拥有原生会话与执行租约。外部解析器提供展示数据，不凭 transcript 新建 Room 事件或推进 ACK。C 的最终回复只有通过现有 Host／Worker 提交边界后才算交付。

CLI 与模型候选为 Codex／gpt-6-luna／low、OpenCode／deepseek/deepseek-flash／low、Pi／magpie/kimi-code-cn/k3.1-pro／low。它们来自既有授权表，尚须读取本机实际 catalog 和解析到的模型；缺失则该组合记准备失败，不换模型、不影响其他可用组合。Roamgate 现成解析分支覆盖 Codex／Pi，但未找到 OpenCode 分支，OpenCode须先验证既有原生接口能否与 TUI 共用同一 session。

## 第一阶段 免费验证托管与故障

先用一个 Codex 实例完成纵向路径。实际 CLI 对接 localhost 假模型，保留真实工具读取回执；复用现有 `codex-tool-preflight.mjs` 的审批与工具宿主检查。仅打印版本或返回 exit 0 不算通过。Codex若被本机程序批准提示阻塞，记录准备失败并转进 Pi，不绕过宿主或停止其他组合。

合成程序先验证终端与传输，真实 CLI 加 localhost 假模型再验证原生接口。前者不能冒称后者，也不能用模拟出的业务成功替代原生 session 证据。免费路径通过后再以临时 Core 跑同一个 SDK 业务闭环；正式频道与服务不参与。

| 场景                                   | 必须观测到的不变量                                                     |
| -------------------------------------- | ---------------------------------------------------------------------- |
| 顺序输入、快速回复、慢速流式回复       | 输入与结果逐项对应，完整正文只交付一次；不能漏掉快到未被 UI 采样的回复 |
| 同 Role 两实例并行，分属不同频道       | 会话、工作目录、收件人和结果无串线，彼此不形成全局阻塞                 |
| 重复唤醒、发送成功但 RPC 回应丢失      | 不盲目重发；核实未知结果，不能重复生成或重复发帖                       |
| 等待审批、工具报错、用户中断           | blocked／error／interrupted不记为成功，也不误取上一轮最后一句          |
| 主会话结束但子工作仍活着               | 子工作仍可执行时不释放为完全静止；停止须有对应清理证据                 |
| 观察连接断开、重连、拖动终端尺寸       | CLI继续运行；观察不写入输入、不改 session、不触发新模型请求            |
| 人工接管后有频道消息到达               | 单一输入所有者；自动投递暂停但消息保留，交还后按原顺序继续             |
| CLI 崩溃、Host 重启、Herdr 重启        | 分开测试三种故障；精确恢复原 session，否则明确失败，不创建替代会话     |
| 空闲回收、再次唤醒、终端观察固定占用   | 保留 session 绑定，正在执行或被接管的实例不被空闲回收                  |
| 超长日志、未写完 JSONL、日志截断或替换 | 页面与缓存有界、未知记录可显示或跳过但不变动作；身份变化停止旧绑定     |

每个适用场景使用10个预先固定的事件顺序种子，共用相同输入与真值记录；不靠重复抽取模型回答稳定结果。先做 A，再逐一实现 B／C，单个场景首次失败即保存证据并停止该候选，不不断修改后只留下最后通过的样本。

故障真值包括输入 ID、正文摘要、原生 session／输入／回复身份、工具开始与结束、进程树终态，以及 Room 最终事件。Herdr 的 idle／done／turn 计数只作提示，不能证明该轮已处理。不得要求模型复述一个随机 ID 来充当读取或完成证明。

## 第二阶段 判断维护收益与资源代价

建立同一份职责账本：启动与重连、进程树终止、孤儿回收、空闲策略、会话绑定、输入关联、最终结果、用量、接管和观察。逐项列出 A 当前 owner、候选 owner、能实际停用的代码与测试，以及新增适配与依赖。

进程数、依赖大小、升级接触面与排错步骤一并统计。移到第三方仓库的同类解析仍是依赖维护成本，不能按本地文件少了就算消失。保留两套长期运行的状态机不算收敛；此阶段不删除生产实现，只以隔离候选的契约测试证明替代范围。

资源测量用合成程序固定负载，各组同机、串行、固定顺序交错重复5次，记录0／1／10个实例、空闲与活动、观察窗口关闭与打开的状态。报告整个候选进程树和服务的 RSS、CPU、启动／接收／结束／恢复耗时及请求数。RSS总和仅作同口径比较，不称为去除共享页后的物理内存。

记录P50、P95及原始样本；小样本P95仅描述本批。分别测冷启动与热会话，不把 A 的空闲回收和 C 的一直常驻混成同等资源政策。每轮不应因 GUI 解析、重画或订阅而新增模型请求。

候选至少能让一项完整生命周期职责停用现有独立实现，并以同一组契约验证接替它，才有资格作“替换托管层”结论。单纯转移文件、删注释或保留两套并行状态机不算。若只解决现有方式无法可靠完成的接管需求，则只评估“增加终端入口”；仅增加窗口且没有可验证的任务收益时，直接保留现有后端。符合其中一个实际收益条件后，才进入真实模型阶段。

## 第三阶段 真实模型与成本对照

本阶段尚未启动。候选通过前两阶段、三家计量均可闭合后，再形成一次明确预算的付费批次；不因某一家登录或 catalog 失败中断其他家的准备，也不把计量失败留到模型工作完成后才发现。

仅比较 A 与保留下来的候选；B 若已证明与 A 的原生协议逐字一致，不为它再复制一整批模型消耗。需要宣布“接近原生 CLI”时，必须增加同 CLI 的独立原生组 N，而不能拿 A 代替原生。

每个 CLI 固定6个区组，每区组 N／A／候选各一条全新主 session，连续6轮Human输入；三组顺序使用六种排列各一次。每家18条主session；其中3个协作区组的每组另建一个审查实例，共9条审查session，因此每家合计27条session、108次Human输入，派生的实例执行与模型请求另计。原生组的6次结果用于估计自身波动，不以某一次原生消耗为唯一分母。

两类任务各3个固定快照：一类修复带隐藏验收的跨模块缺陷；一类先设计、实施、接受新约束并由第二实例审查。审查实例与主实例使用同一CLI／模型，以免混入另一运行时因素；N组由代码转交相同范围的同伴最终正文，不加入工具轨迹或人工总结。实现／审查安排是测试prompt，不能写成产品工作流。跨实例参与者的所有费用计入组内总账。

| 条件         | 固定规则                                                                                                                |
| ------------ | ----------------------------------------------------------------------------------------------------------------------- |
| 任务与质量   | 同样源码、测试真值、输入事实与交付要求；隐藏验收由脚本运行。严重错误、漏要求、人工救援单列，不让模型互相打分决定通过    |
| 模型与配置   | 同 CLI／精确模型／effort，固定快照／工具政策；不同厂商结果分别报告，不混成单一倍率                                      |
| 记忆与子代理 | 所有组关闭官方自动记忆，保留连续会话；内部子代理能力政策一致，实际后代用量去重并保留未知                                |
| 成本         | 所有请求、失败、重试、子工作和自动标题等辅助调用计入；缓存输入按原生口径单列，不重复加总                                |
| 统计         | 报告总量比、每区组比、原生范围／均值／中位数及质量通过率；比率区间按区组重采样，仅作探索性区间，不把6组称为稳定总体分布 |
| 停止         | 不因单个高倍率改prompt或补抽样。模型／计量／预算失败按原批记录，不用成功子集代表完整门禁，不偷偷换组合补跑              |

候选交付质量相当后才解释成本差异；若与原生波动重叠，不据此追求单次1.0或继续修改。若各区组持续更高，再从请求数、输入上下文、辅助调用和恢复路径找原因。本研究不修改既有[效率合同](cli-efficiency-gate.zh-CN.md)的阈值或补判历史失败。

## 隔离与结束条件

所有程序运行在新建的临时目录、显式命名的Herdr session／socket及独立Core数据目录，不接入当前会话或用户已有窗格。工具进程缺少`HERDR_ENV`不说明本对话不在Herdr；历史上已经发生过这一误判。沿用Herdr自带说明，测试进程外显指定隔离目标，不借用当前焦点。

不更新或重启用户Herdr、不改全局CLI配置、不安装用户插件、不连接正式Loom服务。外部桥接只启用所需只读投影与受控输入；CLI无法提供精确身份时记不支持，不按cwd最新文件猜会话。免费原生探针的网络出口固定localhost；真实批次另用明确provider允许表。

每个候选保存源码／二进制／配置哈希、完整请求和生命周期证据、失败样本、资源采样与清理回执。只清理自己创建的进程和目录；不可确认的终止不写成清理通过。任一关键身份、隔离、幂等或错误完成问题未解决时，该候选不得接管生产。

第一轮实施只限一个CLI的纵向原型和上面的免费实验，最多4小时工程预算；到时报告净收益和阻塞，不扩展到完整GUI迁移。全量替换与任何付费批次另作明确执行决定。
