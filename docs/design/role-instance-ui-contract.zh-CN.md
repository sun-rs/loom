# Role 重构的 UI 范围合同

日期：2026-09-23。用户补充要求已确认；作为 [重构施工设计](role-instance-refactor-execution-plan.zh-CN.md) P6 的范围约束。本文记录目标，不表示 UI 已修改。

## 1. 保留大页结构

搜索、动态、聊天、任务和其他已有大页保持原结构及用途，不为 Role 重构另建一套工作台。保留共享导航、分栏、宽度记忆、滚动/草稿和 Web/PWA 语义。响应式折叠使用现有共同 owner，不能在 Role 页面另写断点逻辑。

集中变化是原 Agent 成员管理页改为 Role 管理页；频道里的具体工作成员仍是 Role 的实例。模板与实例的配置、状态和操作明确区分。

## 2. Role 管理页

| 区域         | 目标行为                                                                                     |
| ------------ | -------------------------------------------------------------------------------------------- |
| 左侧目录     | Role 配置列表；不能把每个实例重复显示成模板，也不为模板伪造在线状态                          |
| 资料/配置    | 编辑 Role 新版本；保留已有实例冻结快照语义，不向所有实例热更新                               |
| 聊天 tab     | 展示该 Role 的有效实例参与的频道；按 channelId 汇总，同频道多个实例可展开区分                |
| 记忆 tab     | 不存在；平台记忆能力及频道/成员读写权限配置不是恢复旧 Agent 记忆 tab 的理由                  |
| MCP tab      | 不存在；保持既有第三方 MCP 平台管理退役范围                                                  |
| 实时执行操作 | 停止、重启、model/effort 切换、fork、私聊等必须选择具体 instanceId；不默认套到模板的所有实例 |

聊天 tab 的后端投影是 roleId → instanceId → channelId，不再用旧 Agent principal 的全部 Room membership 直接替代。结果去重频道但不丢实例身份；当前无实例显示空态，加载/失败不能伪装没有频道。

实例动态属于具体实例，并从右侧第三栏展示。Role 本身没有一条独占 session，不能在模板资料上展示某个实例的 context/token 指标充当整个 Role 的状态。原提醒、工作区等实例相关入口必须绑定实例；不在本次补充中擅自指定新的模板聚合功能。

## 3. 聊天大页与第三栏

聊天左侧删除私聊分区。频道列表继续保留。以下详情统一使用现有右侧详情位置：

- 私聊：指向明确实例的私有 box，共用其主 session，显示排队状态。
- Side：独立临时上下文，标明与原实例关系、可读记忆/禁写记忆和实际能力状态。
- 消息列：保持既有线程目标与关注者逻辑，身份改为实例。
- Role 实例动态：展示该 instance 的活动、运行和 session 状态。

“第三栏”是详情容器角色，不要求所有宽度都实际显示三列。宽屏最多三列；变窄时依次隐藏中间内容、左侧列表，最右详情保留。分栏显示 X 关闭当前层，独占主内容区显示返回。深层详情继续保存导航来源，不创建第四个并排 pane；关闭/返回恢复实际上一层，而不是按 Role/Room 类型猜路径。

例如频道 → 消息列 → 实例动态 → 私聊可以有多层历史，但最多三列展示。具体点击是替换右侧当前详情并入导航栈，还是切换同层 tab，按已有导航 intent 定义；不能用 React 临时 state 抹掉来源。

私聊/Side 的入口必须指向实例，公开 @ 继续是公共分工。旧私聊记录保留，通过授权的历史/搜索/通知入口可查看；不能因为左栏不显示而删除数据。未确定承接实例的旧私聊只读，不能悄悄新建模板级全局 session。

## 4. 通知、身份和状态

删除左栏私聊分区后，未读/回复定位应沿现有动态/通知机制指向 private box，并打开对应第三栏；不得广播其正文给其他实例。P6 要补“详情关闭时收到私聊回复仍可找到”的验收，不以移除分区为由丢通知。

同 Role 多实例按实例 ID 选择；头像/名称可以相同，必须显示可区分标识。Role 配置已更新、实例配置有 override、会话故障、能力不可用分别展示，不能混成“离线”。Side 不可用应有准确原因，不创建空白成功页。

## 6. P6 必须通过的场景

1. 大页导航和原有分栏尺寸不变；Role 目录/资料改动不带动搜索、任务页面重排。
2. Role 模板无实时在线状态；同 Role 两频道实例独立，修改模板不改正在运行实例。
3. 聊天 tab 展示实例参与频道，同频道多个实例可区分；无 Agent 私信分组。
4. 聊天左栏无私聊分区；授权历史仍可打开，不自动创建新 session。
5. 私聊、Side、消息列、实例动态均进入同一个右侧详情体系，重复点击不堆出第四列。
6. 宽屏、两列、390×844、PWA 下返回来源正确；刷新、迟到响应和窗口缩放不串 target 或丢草稿。
7. 私聊排队可见且不打断频道；关闭第三栏后，回复能从已有通知机制定位。
8. Side 显示独立上下文和记忆禁写；能力未验证时不能提供可点击的假成功动作。

后端语义和 target 权限通过后再接正式 UI；隔离 fixture 必须显式标记，不能作为正式用户页面交付。
