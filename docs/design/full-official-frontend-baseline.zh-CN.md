# 完整官方前端稳定基线

Owner2026-10-30最终选择：以GitHub Web **1.21.23** (`db5e399f017d584e49597e3a28757645d6807893`，tag `v1.21.23-source.1`) 的完整源码和原始锁文件为下一产品基线。其Web清单锁定`@botiverse/raft-ui@0.7.0`。本决定取代先前Web1.21.40＋UI0.52.2目标；不继续把官网新片段补入旧页面。

## 依赖和所有权

官方本体保留完整Web及其所需官方workspace包，逐文件hash校验，不手改页面、样式或生成产物。配套CSS、字体、图标和交互来自同一版本；保留原始LICENSE和pnpm锁。Loom薄适配只拥有SDK数据投影、身份映射、路由／能力绑定及明确的产品扩展。官方UI缓存不是业务真相，Loom Kernel／AgentHost／client-core仍是原合同中的单一所有者。

Role是配置，频道成员是独立Instance；官方Agent字段不能让二者重新合并。实例冻结执行配置／连续session／单lane、频道私密消息、Fork／Side、平台记忆、本地通知与已批准移动触控策略均须在迁移清单中有真实接线或明确限制。不能通过新建假对象、替换运行后端、关闭权限或丢弃现有数据来使页面看起来能用。

## 实施顺序及验收

1. 独立取得并校验完整源码，按原始依赖锁构建原版；保存各个大页／菜单／表单的官方模拟对照。
2. 在同一个官方版本之外建立Loom适配。先闭合启动→频道列表→消息→角色／实例管理的真实业务链，再覆盖其余现有能力；不重写官方容器与菜单。
3. 原版和适配版使用相同夹具、固定时钟、中文、主题、字体、viewport和DPR进行截图／几何／交互对照。官方UI区域默认要求一致；Loom专属差异按来源、原因、边界和回归单独登记，不用大面积遮罩消除差异。
4. 类型／构建、完整来源校验和必要业务／桌面／手机检查通过后，备份并预检正式状态，平滑替换精确服务；真实页面复查。未通过时保留正式旧构建服务，报告具体缺口。
5. 原混搭运行时仅在完整替代验证后退出产品图。历史证据保留；不把旧页面重新引入新版本来补缺口。

这不是只把npm包降级，也不是在原混搭UI上继续自编。源码取得、原版构建、模拟像素一致、真实API业务接线和正式部署是五个不同结论，分别记录。

## 后续更新

只在取得完整下一版本及其配套锁文件后建立候选。比较官方新旧接口及注册场景，整版替换后修适配层，运行来源／业务／视觉回归。接受与官网最新版的版本差；不承诺升级零改动，不持续追赶网页像素。

此前取得的Web1.21.40编译发布图、UI0.52.2源码及可行性记录保留为历史／候选证据，不能混入1.21.23运行时或冒充原始TSX。
