# 完整官方前端基线与 Loom 接线

2026-10-30 owner裁定：下一基线固定为 Web **1.21.40** 与 UI **0.52.2**，停止“旧页面加新版选段”的升级方式。随后 owner明确授权直接提取部署版本。本方案据此采用完整发布代码依赖，不再等待公开仓库提供原始TSX。

## 取得的是什么

| 层         | 本次取得                                                                                        | 不能由此推出                  |
| ---------- | ----------------------------------------------------------------------------------------------- | ----------------------------- |
| Web        | 官方1.21.40完整第一方可执行模块及静态资源图；release `a7bb80017084e766d68b8a1d7c6377496a16fbaa` | 已取得原始TSX、类型与构建工程 |

| Loom运行版 | 现有db5e399选定源码与后继资源移植仍在服务                                                       | 已整体切换1.21.40             |

完整归档与机器可读来源记录位于`frontends/raft/upstream/releases/`。Web归档保留HTML、JS、CSS、字体、图标、locale与Service Worker的原字节；每个文件记录URL、MIME、字节数、SHA-256和静态依赖边。316个资源、219个第一方JS模块、19538241字节，均可从固定HTML根沿依赖图到达。查询参数资源保留独立身份。约5.75MB压缩归档是开发依赖，不是把19.5MB一次送给浏览器的加载方案。

第三方Cloudflare遥测脚本不作为UI依赖引入；业务API、WebSocket、用户上传内容不属于静态代码图。非字面量`import(e.module)`位于React Router通用运行时，单独记录；静态图完整不等于所有运行时资源与业务流程均已验收。原始TSX公开镜像停留在db5e399；不以压缩代码冒充TSX工程，也不以这个事实阻断已授权的发布代码提取。

## 不可变依赖和适配边界

- **官方代码**：整版归档不可手改、裁成新选段或混入旧页面。HTML和所有模块原件保持哈希可验。
- **资源投递**：Loom外层负责同源路径、CSP、缓存及字体映射；投递变换有独立清单和验证，不修改归档。官方硬编码API origin必须经显式传输接线进入Loom，禁止把本地用户凭据送到Raft远端。
- **数据与权限**：复用Loom SDK和原有认证上下文。原生store只承接UI投影，Room、投递、任务、记忆、session与执行状态仍由已有后端owner掌管。未接的写操作明确拒绝，不伪造成功收据。
- **对象差异**：官方Agent不是Loom Role与Instance二者的总和。成员页配置绑定Role，频道成员绑定Instance；稳定ID与显示名分开，不把Role保存变成已有实例改配。应显式适配资料路由与操作能力，不能复活官方一Agent一固定session的调度。
- **Loom专属部分**：实例列表／冻结修订、Fork／Side、平台记忆、539张owner头像、本地通知、已批准的移动端导航／触屏紧凑策略均列入对接清单，不能因整版替换静默丢失。
- **原生功能取舍**：组织账单、公开分享、多Human和受管理第三方MCP不因原版页面存在而启用。通过明确的能力入口省略；不改原版尺寸、字体和控件协议来掩盖未接线。

## UI0.52.2必须单独核验

1.21.40实际vendor含0.52.1的PanelAction／PanelSplitActionMenu触控边缘修复，但没有0.52.2新增的Badge `anchor-scope`触控规则。现有证据只能识别这些实现指纹，不能凭此断言其完整包版本。

因此整版Web接线不能假设它已满足目标UI版本。需要通过完整0.52.2库与原生模块的出口／React上下文接线实现单一UI运行时；所有用到的出口必须有明确映射并失败关闭。不得向vendor补几段字符串、同时加载两套UI上下文，或更改版本字段来宣称完成。取得归档与验证旧服务的npm0.52.2都不关闭此项。

## 分阶段验收和施工次序

| 阶段               | 通过条件                                                                                         | 当前边界                              |
| ------------------ | ------------------------------------------------------------------------------------------------ | ------------------------------------- |
| 整版取得           | 固定release身份、原件校验、重算静态图、无缺边／未知文件／混入旧文件                              | 已取得；原始TSX未取得且不再是前置阻塞 |
| 原版独立运行       | 在关闭外网、Service Worker及WebSocket的隔离浏览器中，用明确fixture接口运行整版；记录实际缺失接口 | 是依赖取得检查，不是产品验收          |
| 单运行时与传输入口 | 完整UI0.52.2、同一个React／UI上下文；所有远端接口转为本地显式接线                                | 未完成                                |
| 纵向业务对接       | 真实临时Core完成Role→频道→实例→消息→启停／私聊；保留因果、幂等和未知结果核实                     | 未完成                                |
| 保留能力与页面     | 任务／文件／记忆／Fork／Side／通知及桌面／手机／触屏分栏回归，按差异清单验收                     | 未完成                                |
| 正式切换           | 验证构建、备份、空闲检查、原服务平滑重启、真实页面与保护数据核验                                 | 未执行；旧服务继续运行                |

先贯通真实纵向业务，再补保留能力；不按几十个页面分别续接旧实现。整个迁移是一次依赖替换，不能用原版隔离截图冒充正式Loom完成。

## 可复现命令

```sh
# 对本地完整归档验原字节、版本与依赖图，无需网络
node scripts/official-web/pinned-release.mjs

# 定向回归：缺失／改写／漏lazy模块／混版本／未知候选均应拒绝
node --test scripts/official-web/capture-release.test.mjs scripts/official-web/release-integrity.test.mjs scripts/official-web/pinned-release.test.mjs

# 完整原版隔离启动。只用虚构身份、临时浏览器；不访问Loom生产数据
node scripts/official-web/native-release-browser.mjs
```

重新取得发布版时，先保存带release identity的HTML，再运行`capture-release.mjs <html路径> <新目录>`。工具拒绝在同一目录混release；只追踪第一方及显式字体来源，排除API和bundler调试模块名。下载完成后重算图与原件，再产生完整归档，不能覆盖旧归档／旧证据或边下载边移动产品pin。

未来更新比较的是“整版官方旧依赖→整版官方新依赖”和明确的适配端口，随后重跑真实纵向流程及受影响页面。完整静态图与原生页面大幅减少手工重画，但不能自动证明API、Role／实例语义、移动端例外和UI版本接线仍兼容。
