# UI 一致性收口计划与边界

2026-09-04；改造前里程碑 `22086e2b9767343984bb0b5f4d4725240ac09d20`。

资源采用与维护政策现由 [ADR 0028](../adr/0028-owned-neo-brutalist-ui-library.md)
收紧：既有资源转为内部可维护源码，不再从外部参考工作树生成覆盖；共享基础组件
进入 `ui-web/src/neo-brutalist`。英文入口为 [RAH Neo-Brutalist UI](../design/neo-brutalist-ui.md)。
本计划的分批验收仍有效；目录迁移本身不等于剩余页面和双边对比完成。

目标是减少实现来源和重复规则，不重写 Kernel、SDK、调度或业务状态。每批
先增加失败测试，再迁移生产消费者、删除旧 owner 的重复实现，最后跑真实浏览器。
共享组件只能接收展示属性与回调；不得引入参考项目的模拟 store/API/状态机。

## 1. 来源和当前状态

`raft-ui` 是本地参考重建项目，不是官方 React 源仓库。来源必须区分：

| 采用方式                 | 可接受证据                                              | 不可宣称                |
| ------------------------ | ------------------------------------------------------- | ----------------------- |
| official-original        | 官方发布资源、固定 URL/文件及 SHA-256；原样产物摘要相等 | 重建 CSS 也属于官方源码 |
| extracted-port           | 固定官方包、可定位片段、移植 owner 和差异说明           | 整页/整套状态机原样复制 |
| reference-reconstruction | 带 manifest 的参考项目快照及生成链                      | 官方源代码              |
| rah-local                | 明确的本地 owner、必要性和协议测试                      | 官网也具有此本地语义    |

单一当前登记为 `docs/product/ui-behavior-registry.json`；Markdown 行为索引由它生成。
74 个旧 intent 保留原 ID 与历史接线声明，但历史声明不自动转成当前验收。
源文件哈希、ID、owner、采用方式和测试场景通过机器检查；哈希只证明材料固定，
不证明实现正确。运行回执写临时目录，附登记摘要和场景结果，不把静态 JSON 的
“有测试”当成“测试已通过”。旧审计留在历史链接/Git，不作为当前通过率分母。

## 2. 有序迁移批次

| 批次 | 单一 owner / 工作范围                     | 出口条件                                                                              |
| ---- | ----------------------------------------- | ------------------------------------------------------------------------------------- |
| A    | 来源登记、机器检查、历史索引              | 伪官方来源、摘要漂移、漏 ID/owner/场景、生成文档漂移均失败                            |
| B1   | Shell 分隔线/拖拽公共实现；标题栏图标按钮 | 三种 splitter 共用事件 owner，保留各自宽度策略/持久键；迁移标题按钮并删除重复尺寸规则 |
| B2   | Shell/标题/Tabs 的剩余几何协议            | 完整主页面及侧栏布局；断点两侧和矮屏无缝隙、裁切、点击遮挡                            |
| B3   | 浮层、表单、空态、工具栏、通用按钮        | 复用既有浮层与 interaction-state owner，逐族迁移、删除冗余覆盖                        |
| C    | 页面与功能补齐                            | 页面仅组合共享组件，typed SDK → canonical owner 不变；每条功能独立验证                |

B1 不等于全部 Shell 完成，组件测试不等于全站双边一致。后续批次必须继续
登记真实缺口；不能通过给尚未迁移的组件套一个相同类名来宣称完成。

### B2 首段：会话标题与 Tabs

先迁移 Room / Agent / Thread 标题几何、Room / Agent Tabs。官方冻结 bundle 的
Panel header slots 使用共享 shell-header-height、shrink-0、border-b-2，TabList
支持 Home/End、循环焦点和禁用项跳过。采用这些展示合同，不引入官方 store。
Room/Agent 的标题、能力闸门和选中回调仍由原页面提供；Thread 弹层状态不迁移。
共享 Tabs 只拥有焦点/键盘协议，自动激活保留现有 Agent 行为并补足 Room；
能力失效不擅自改 canonical 页面选择，焦点回退到首个可用项。

TDD 先覆盖 Room 禁用项跳过、单一 Tab 停靠点、两组独立、无可用项、窄侧栏末项
可见、标题不受长内容挤压及矮屏边框对齐。然后复跑完整应用的隔离 daemon
Chrome/Firefox 场景。Settings、Computer、全局发现的标题迁移仍是后续 B2，
本段不将其算作完成；同样不宣称所有页面已与官网双边验收。

## 3. 状态、组合与 TDD

分三层：纯策略/来源负例测试 → 实际生产组件矩阵 → 完整应用浏览器验收。
矩阵覆盖 rest、hover、press、focus、disabled、loading，长名称/空数据/权限不足、
侧栏打开、390×844、700/701、767/768、1023/1024、1279/1280 及矮屏。
每个控件可注明不适用的状态及原因，例如 splitter 没有异步 loading；不以省略代替。

宽度、图标尺寸、边界命中和焦点/键盘/回调次数应有独立预期，不从组件读取值后
再断言自己。浏览器使用真实 Chrome 和 Firefox；截图仍需查看。组件 fixture
不得进入生产入口，不访问正式 daemon、不启动真实模型、不伪造官方在线验收。

## 4. 回退、验收与交付

每批运行 `npm run check`、`npm run format:check`、`git diff --check`、Web build、
新增矩阵和既有端到端门禁。不改数据库模型、不迁移用户状态。修复批次按既有
安全规程检查活动工作后备份并重启正式实例，再做只读浏览器核验；不靠热更新交付。
回退采用 Git 的定向 revert，不覆盖用户后续改动。报告必须区分：登记/代码迁移/
本地测试/官网双边测试/正式部署，不使用没有分母定义的“100% 一致”。
