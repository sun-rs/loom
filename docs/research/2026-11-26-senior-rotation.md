# 长期角色（Leader / Auditor）何时换班：前辈经验与长会话数据（2026-11-26）

**前辈回答**（briefing/ANSWER-*-senior-rotation.md）
- t17w（Claude，8 天、273 轮、4 次压缩）：最相关的是①换话题或权限/角色口径改变（两类最严重的错都在此时：自己套用旧项目心智模型；t17g 在用户说"你先继续带领"后两次未批准合入）②长等待后被唤醒（拿过期事实判断）③压缩次数（前 1–2 次基本无害）；轮数、时间、大小经压缩间接起作用。建议：在卡/波次边界，压缩 3 次、换项目或阶段、权限口径变更、同会话 2 次已核实事实错误或越权，任一即换；单纯时间长、轮数多、被唤醒不换（先读"当前事实卡"）。交接补不回：用户语气与优先级、对 worker/模型的可信度判断、未成文直觉。
- t17g（agy，7 天、369 轮、21 次压缩）：压缩次数 × 换大课题最核心；有效决策轮数与纠偏信号次之；历史体积间接；挂钟时间最弱。最易丢"负知识"（被否方案及原因）、在途环境坑、热区代码心智地图；补不回隐性尺度与展开一半的跨文件因果链——绝不在波次未收口时硬换。建议：只在波次收口边界换；Auditor 对失忆零容忍（压缩 ≥1 或有效审卡 15–20 轮）；Leader 压缩 ≥2、换里程碑、有效工作轮 35–40 或 2 次事实错误。
- t13n（Claude，8 天、约 2,700 往返、约 15 次压缩）：压缩次数 × 话题切换次数最相关；同一主线连续推进多次压缩仍稳。常见错误是"信二手结论不抽原件"。建议：第一个可核实事实错误进入加严模式（每个结论现查原件），同类再犯在阶段边界换；压缩 8–10 次且一天内处理 >10 张卡或 >3 个子系统时换；不按剩余上下文换；Leader 与 Auditor 错开换并由老方核对新方首轮；交接三件套：状态单、判例账本（用户原话、裁决、被否方案及原因）、未决裁决清单。
- t4c（Solars Supervisor）：忙，尚未回答。

**长会话数据**（t13n 1,033 轮/195h/7 次压缩，t17w 274 轮/193h/4 次，t17g 369 轮/180h/22 次，t4c 1,696 轮/260h/90 次；详见 Super 草稿区 senior-degradation.md）：轮数、运行时间、历史大小、压缩次数、压缩后占比都**看不出与错误率的稳定关系**（如 t13n 自认错误率按天 0–1%，无趋势）；唯一弱信号是 Claude 实时上下文 >~700k 时严重事件偏多（样本极小），以及压缩/交接后第一阶段的"过期事实当现状"。pilot-2 的 12 次换班中 4 次失败，成功的也出现首报核对缺漏。

**结论**：换班不该由单一计量驱动；最可靠的触发是"语境变化 + 已核实错误 + 压缩次数"，且只在干净边界执行；而交接质量（判例账本、被否方案、当前事实卡、首轮只核对）比换班时机更决定成败。

## 评审后的定稿（v2，2026-11-26；评审：t17g、t17w、t13n，t4c 待交）
评审一致认可：干净边界、不按轮数/时间/剩余换、错开换、判例账本与首轮只核对。修改如下。

**A. 立即处置（不等边界）**：P0 越权（未批准合入、绕过沙箱）或造假 → 冻结该角色的写操作并换班（t17g、t4c）。

**B. 在下一个干净边界换（机器可判定，loomd 自动提示）**
1. 换项目（cwd/git 根变化）或进入新阶段/新目标（以 `notifications --complete`、目标编号、门禁编号等结构化事件为准）。
2. 角色变更、权限口径变更——只认 Super 用命令登记的裁决（会漏判、不误判）。
3. 切换密度：24 小时内经手 >10 张卡或 >4 个子系统（按文件路径前缀），且期间压缩 ≥5 次（Claude 计 compact；agy/Codex 按"距上次换班累计输入 token"折算，逐 CLI 校准）；同一主线、单一子系统放宽。
4. 同一卡/主线连续 ≥3 轮审计退回打转 → 换班或重设计评估（提示 Super）。

**C. 错误驱动（人工标记，带证据）**：第 1 个已核实事实错误（含"把测试当产品、把报告当原件"这类错读）→ 加严模式（每个结论现查原件）；加严期间再出任何一次已核实错误 → 边界换。标记只能由 Super 或另一方高级角色附原件证据；Auditor 每次签收记录抽查结果（含"抽查无误"），给错误率一个分母。

**D. 软信号（只提示，不强制）**：实时上下文超绝对高水位（Claude 约 650–700k）→ 进入只读核对、不做新决策，到边界换；压缩次数按 CLI 校准的观察值；24 小时内被用户纠正 ≥3 次（由 Super 登记）。

**E. 不作为理由**：轮数、运行时间、长等待后被唤醒、剩余上下文百分比。

**F. 换班安全（直击 pilot-2 12 次失败 4 次）**
- 前任在继任首报被另一方核实前保持只读在线，继任失败即回退前任；同一阶段换班失败 1 次即停下报 Super，禁止连环重换。
- 防抖：同一角色两次换班至少隔一个阶段，否则报 Super；Leader 与 Auditor 错开至少一个阶段，由不换的一方核对新任首报。
- 在途消息：发给旧地址的待回复/排队消息改投继任或作废，并在交接单列明。
- "当前事实卡"（HEAD、在途波次与续作、最新裁决）由 loomd 机械生成，在每次压缩后首轮、换班后首轮、长等待后唤醒时自动附带。
- 交接必填：状态单、判例账本、**已否方案及原因**、未决事项、"用户偏好与可信度判断"；新任首轮只核对；换班当天新任不得改既定规则（合入时机、并发上限、预算），改需老方或用户确认。

**G. 被动换班单独记录**（不计入出错）：前任被弹窗/额度卡住超过 30 分钟、模型或 CLI 版本变更。

**H. Super 豁免**：用户直接对话的 Super 不自动提示，由用户决定。

**依据与指标的诚实评估**：B1、B2（登记后）、B3、B4、D 的高水位可由 loomd 机械判定；C 依赖人工标记，会漏判，因此靠 B3 机械兜底和抽查分母弥补。不存在单一可靠的"寿命计量"，这是数据给出的结论，不是规则的缺陷。

**补充（t4c，Solars 主督导，约 7 天、1,100+ 轮、多次压缩）**：与 v2 一致——相关性排序为"压缩次数 + 跨阶段话题切换 > 活跃决策密度 > 运行时长/总轮数"，过勤换班（如每 50 轮硬换）会频繁引入交接误解。新增两点并入 v2：
- C 节硬触发再加一条："连续两次派活漏带硬约束"。
- 新增"加严复核"软触发（不换班）：第 3 次压缩、连续运行约 48 小时、或跨入新大阶段时，切到零信任现查模式（每个 SHA/路径/数值先跑命令核实再出口，约每 150 轮自查一次账本漂移）。由 loomd 在这些时刻附送提醒（随已有投递）。
- 错峰铁律再次强调：Leader 与 Auditor 绝不同时换，较老一方核对新任首轮报到与首批决策，直到平稳度过一个完整阶段。
