# AML 记忆排行榜与 MemoraX（2026-11-25）

> 调研日期 2026-11-25。只读阅读源码，未注册任何服务、未发送任何数据。榜单和产品变化快，引用前请先核对。

## AML（Agent Memory Leaderboard）
- **评测方式**：参赛方只提供 Add/Search 两个接口，答题模型、coding agent、打分都由平台执行（`README.md:84-88`）。文本赛道每次检索 top_k=100；编码赛道共 150 个任务，各在 relevant 和 noisy 两种历史下跑一次。数据来自 HF Space 的 `data/cycle2-public.js`（2026-11-19 发布）。
- **可复现性差**：原始数据、held-out 题、gold 答案和评分细则都不公开；答题模型和裁判模型的名字也未公开。开源组限定用 `gpt-4o-mini` 加 `text-embedding-v4`，商业组不受此限制，两组成绩不可比。商业组提交的是黑盒 API。
- **利益关联**：
  - AML 的发起方以天津大学居首，MemoraX 创始人是天津大学教授；
  - 文本套件中的 ScriptMem 直接引用了 `github.com/memorax-ai/ScriptMem`；
  - 规则中没有利益冲突条款。

  **可信度判断：中低。**
- **AML 测的是什么**：从海量原始对话里找回证据。这对应 loom 的 `loom hist`（历史检索），不对应 loom 的记忆层（角色自己写入、带修订版本的少量事实）。

## 开源冠军
| 项目 | 做法 | 结论 |
|---|---|---|
| Resurface（文本 61.22，MIT） | 原文存 SQLite；FTS5/BM25 加向量，用 RRF 融合；带出相邻轮次；写入不调用 LLM | 可作为 `loom hist` 检索的参考实现。没有角色范围、修订版本、取代关系，不能当记忆后端 |
| InsightMem（代码 63.33） | 三路 BM25/向量；区分 patch、observation、transition 等内容类型 | 上游 InvMem 未声明许可证，只借思路。它也没有记录"哪个修复通过了测试" |
| Khipu（多模态 43.26，MIT） | 五通道检索加云端精排，依赖 Postgres+pgvector；写入图片时调用 gpt-4o-mini | 依赖云端，拒绝 |
| atlas-harness、Mem-Pro（商业编码榜） | — | 无公开代码 |

**共同规律**：排名靠前的系统都是"原文存储 + 混合检索 + RRF + 相邻上下文"，写入时都不调用 LLM。没有一个对接编码 CLI，没有一个支持角色权限或修订版本。

## MemoraX（memorax-ai/memorax-code，MIT）
- **开源的只是胶水层**：仓库里只有本地 backend 和各 CLI 的 hook/插件/skill。记忆的抽取、存储、检索全在云端（`platform.memoraxai.com`），必须联网。私有部署只在 Enterprise 档提供，需询价。
- **每轮自动上传对话**：每轮结束后把用户指令和最终回复上传，由对方的模型抽取记忆。脱敏只有正则，官方自己声明"不是完整的 DLP"。手动 add/search 不做脱敏。
- **不支持 agy**；只有用户、仓库、项目三级范围，没有角色分层。
- API key 以明文写在 `~/.memorax-code/config.toml`；卸载后云端数据不会自动删除。产品尚未到 1.0，公司成立于 2026 年。
- **对照 loom 的 7 项硬约束，全部不满足**：本地私有、四家 CLI、角色可见范围、多 cell 以 home 为权威、确定性可审计、不额外付费调用模型、供应商宕机时仍可用。另外，它注入的 hook 会与我们关闭原生记忆的做法冲突。
- **结论：不作依赖，也不作可选后端，只借鉴思路。** 可借鉴的设计：
  - 记忆四分类：编码经验、仓库知识、个人偏好、操作流程；
  - 写入前与已有条目比对，决定合并、替换还是删除；
  - 上下文压缩后重新注入；
  - 按类型做占位式脱敏。

## 其他
- Basic Memory：形态最接近 loom（Markdown + SQLite + MCP），但许可证是 AGPL-3.0，不引入。
- Cognee、Mnemon：靠 LLM 构图或提炼，违反"不做后台提炼"的原则，拒绝。

## 对 loom 的取舍
1. 记忆层继续用自己的设计（docs/MEMORY.md）。
2. `loom hist` 的检索借鉴 Resurface：默认只用 FTS5/BM25；向量作为可选的本地派生物，可以从原始记录重建；数据库记住自己的写入设置，设置不一致就拒绝启动；每段证据自带时间、说话人、角色、卡片 ID。
3. "哪个修复通过了测试"这类代码经验，由 loomd 用证据卡、diff 和 DONE 状态确定性地生成"补丁 → 测试结果"关联。这是 AML 上没有任何系统做到的。
4. 评测方法借鉴 AML 的编码赛道思路：衡量的标准是"上次的经验这次有没有帮上忙"，即任务是否解决、测试是否通过。具体落到 MEMORY-TESTS 的 L05/L06。
