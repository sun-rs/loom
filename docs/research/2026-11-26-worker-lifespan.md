# worker 寿命：前辈经验与 pilot 实测（2026-11-26）

**前辈回答**（briefing/ANSWER-*-worker-lifespan.md）：
- t17w（loom-next Auditor，11-17～11-25 共 589 个 Codex 会话）：worker 峰值上下文中位约 91k、p75 160k、p90 261k（窗口 258k/475k）；423 个 worker 会话仅 7 个（1.7%）压缩；实践一卡一 worker，复用几乎只在同卡续做/局部返工；压缩 1 次基本无害，2 次以上需靠交接；建议不跨卡复用，约定由 loom 开局注入。
- t17g（loom-next driver）：典型单卡用 15–45%，0 次压缩完工；1 次压缩后只宜收尾，第 2 次压缩起明显出问题（重复读文件、修 B 忘 A、打补丁死循环）；R1/R2 常规缺陷原 worker 修更快更稳，R3/改设计/已压缩换新并附 RED 复现；复用门槛：同卡返工或同模块紧邻小补卡、已用 ≤50%、0 压缩、返工 ≤2 轮。
- t13n（Solars Auditor）：小卡用 30–40%、中卡用到 60–85% 常压缩 1 次；剩余 ≥40 才接新卡，剩余约 15 时在步骤边界写交接单换人；坏质量更多来自上下文里积累的旧口径而非压缩次数；新人首报必须现场核实分支、SHA、WIP、生效裁决；审核至少抽一份原始测试日志。
- t4c（Solars 主督导）：按证据换人，不按年龄/压缩次数机械换；卡内不中途换（除非造假/越权或连续 10 分钟无进展）；同领域 + 上张卡零事实错误/越权 + 剩余 ≥30–35% + 累计压缩 ≤1 → 复用（省 5–10 分钟重读）；剩余 <20%、压缩 ≥2、跨领域、二次同类事实错 → 换新；首轮局部 REJECT 且剩余 ≥20% 原 worker 修，二轮再打回/偏航/造假强制换新；换新必附一页可核实交接单 + 判例账本，首轮先只读复述核对。

**pilot 实测**（pilot-2 + pilot-cell，69 个 worker 会话，CSV 见 Super 草稿区）：Codex 窗口 475k，峰值上下文中位 10.4%、p75 17.3%、p90 22.9%、最大 34.6%；**0 次压缩**（含 82 次请求、66 分钟的卡）；14 张 BLOCKED/FAILED 发生在 10–28% 上下文，与上下文压力无关；91% 的会话为单轮新开，9% 为续用。

**结论（定为 loom 规则，WORKER-REAP-1 Addendum 5）**：在 475k 窗口下上下文几乎从不成为约束，决定复用与否的应是"是否同领域/同工作树"和"退回问题的性质"，阈值只作安全网。
1. 一卡一 worker 做到底；卡住续做、R1/R2 局部退回（不改接口）由原 worker 修。
2. 跨卡复用：同领域（同工作树）的后续卡，已用 ≤60%（剩余 ≥40%）、累计压缩 ≤1、且上一张卡零已核实事实错误/越权（综合 t17g ≤50%/0 压缩、t13n 剩余 ≥40、t4c 剩余 ≥30–35/压缩 ≤1；t17w 主张不跨卡）。
3. 卡内只有一种中途换人：已经压缩过 1 次、且剩余再次低于 15%（即将第 2 次压缩）时，在步骤边界写交接单（原写法"第 2 次压缩或剩余 <15%"自相矛盾：任何压缩前剩余都会低于 15%，已更正）（任务、分支/SHA、WIP、已过/未过验收、生效裁决）再换。
4. 换领域、方向被否、第 3 轮、造假/越权 → 新 worker，修复卡附精确 RED 复现。
5. 降低换人成本：loom 开局注入卡面约定、生效裁决、相关记忆；新 worker 首报核实分支、SHA、WIP、裁决，核不上先停。
6. 长期角色按实际窗口比例换班（默认上下文 ≥60% 或压缩过 1 次后再次接近压缩），只在卡片/门禁边界；见 ROT-TUNE-1。
7. Auditor 审核至少抽一份原始测试日志（经 worker 证据卡提供）。
