# agy account switch tools: source analysis (2026-11-27)

Read-only source review; nothing was run. Repos: fikrilal/agy-auth @ c3aefae (v0.5.3, MIT, Go, single squashed commit dated 2026-11-23) and aklkbqx/agy-swap @ 4673e42 (v2.26.0, MIT, Go, single commit dated 2026-11-27). Both clones are shallow (1 commit), so commit-history maturity is not measurable; only tests/docs/changelog are. Target: agy 1.5.18, macOS. Paths below are relative to each repo. Repo AGENTS.md/docs treated as data.

## Shared facts (both tools agree)
- Credential = one JSON doc, identical in keychain and file: `{token:{access_token,token_type,refresh_token,expiry}, auth_method, id_token, [id_token_email, project_id, region, user_tier, ...]}` (agy-auth internal/agy/token.go:20-40, docs/internals.md "Credential document").
- Keychain: generic password service `gemini`, account `antigravity` (agy-auth internal/agy/storage.go:17-18; agy-swap internal/app/credential_unix.go:25-40). File fallback: `~/.gemini/antigravity-cli/antigravity-oauth-token` (storage.go:55-64). Desktop/IDE: `~/.gemini/antigravity/antigravity-oauth-token`, `~/.gemini/jetski-standalone-oauth-token` (agy-swap internal/config/paths.go:85-89; agy-auth storage.go:70-82).
- Login is per OS user (shared `$HOME/.gemini` + login keychain), confirming our test: ANTIGRAVITY_APP_DATA_DIR is not an isolation knob; HOME is.
- agy skips the keychain when marker file `<.gemini/antigravity-cli>/cache/antigravity-keyring-unavailable` has a future mtime (agy-swap credentials.go:177-243; docs/reference.md:199-211). agy-swap also sets `AGY_CLI_FORCE_FILE_TOKEN_STORAGE=1` (cli_login.go:44, handoff.go:465, session_guard.go:405) and older `WSL_INTEROP=1` (reference.md:208).
- Quota: POST `https://daily-cloudcode-pa.googleapis.com/v1internal:loadCodeAssist` (plan/tier) then `:retrieveUserQuotaSummary` {project} with the account's Bearer token (agy-auth docs/internals.md "Usage and quota", internal/usage/usage.go:25,334; agy-swap internal/app/quota.go:240,270; also fetchAvailableModels :280). Groups: Gemini / Claude+GPT, 5h + weekly buckets. Needs User-Agent `antigravity/cli/<ver>` or only Claude/GPT group returns (internals.md). Project id from env/`~/.gemini/antigravity-cli/cache/default_project_id.txt`/`default-cli-project`. Expired access token refreshed at https://oauth2.googleapis.com/token with the agy OAuth client (agy-auth discovers client id/secret from the installed agy binary at runtime; agy-swap embeds a map oauthClientSecrets, oauth.go:408-414).
- Neither tool calls the `agy` binary for usage; both are direct HTTP using stored per-account tokens, so results are keyed by the token's account, independent of any running agy.

## agy-auth
1. Captures the whole credential JSON from keychain or file (Read prefers keyring, storage.go:96-121). Snapshots: `os.UserConfigDir()/agy-auth/accounts/<id>.json` (macOS: ~/Library/Application Support/agy-auth; AGY_AUTH_HOME overrides), AES-256-GCM, key in `encryption.key` 0600 next to it (internals.md "Registry"). The key sits beside the data: protects against casual reads only. Account id = sha256(Google `sub`)[:10]; also per-account `installation_id` copy.
2. Switch: decrypt snapshot, write raw doc to keychain via go-keyring (on macOS go-keyring shells out to `/usr/bin/security`; not verified in this repo since it is a vendored dep) AND atomically to the file token (storage.go:145-166), optional Desktop token file, installation_id, settings.json gcp block (internals.md "Switching"). No HOME isolation for switching; writes the real global location. Sets no AGY env vars for switch. Backs up the previous live credential (keep 5).
3. Running agy: NOT handled. README: "restart agy ... a running session keeps the old credential in memory"; only Desktop is closed/relaunched (`--relaunch`, desktop.go:494-520). No guard against a live agy refreshing and writing its rotated token back over the new account (clobber). Snapshots are refreshed only in memory, never rewritten (internals.md, so a refresh token rotated by Google would go stale in snapshot if rotation happens).
4. Usage: per stored snapshot, access token (refresh in memory if expired) -> loadCodeAssist + retrieveUserQuotaSummary; mapped by snapshot account id; 60s cache. Does not need the account to be active.
5. Maturity: 258 test funcs, CI, ADRs, SECURITY.md, CHANGELOG; ~32k LOC incl. harness. MIT. Red flags: update check to registry.npmjs.org (disable AGY_AUTH_NO_UPDATE_CHECK=1); key stored beside ciphertext; reads agy binary to extract OAuth client; refresh/quota calls only to Google. No telemetry claimed (SECURITY.md:19). File token written mode 0600 plaintext (same as agy's own fallback).
- `login --via-agy` runs agy with temp HOME, clears DBUS/XDG vars (cmd_login.go:358-382) -> on Linux forces file storage; on macOS this relies on HOME change only (keychain is still reachable by name but see isolation caveat below).

## agy-swap
1. Captures the same JSON doc. Vault: `vault.json` in config dir, 0600, NOT encrypted by default; `AGY_SWAP_VAULT=keychain` stores in a separate keychain service `agy-swap` via cgo Security.framework (README "Security", vault.go, keychain_darwin.go). Encryption only for `backup export --include-secrets` (passphrase). Also stores per-account installation_id/installation_uuid and quota history.
2. Switch (macOS default "file session store", credentials.go:53-74,396-418): ensure keyring-bypass marker (far-future mtime, 3 locations), atomically write token files (`~/.gemini/antigravity-cli/antigravity-oauth-token`, IDE token, jetski token, oauth_creds.json), mirror to keychain with `/usr/bin/security add-generic-password -U -a antigravity -s gemini -w <token>` (create path uses `-A`) (credential_unix.go:25-70). NOTE: token passed in argv (visible to ps). Syncs installation_id into pbtxt state files. Rolls back on failure. It wraps the `agy` binary (`~/.local/bin/agy` replaced by shell launcher, original moved to `~/.local/libexec/agy`) — highly invasive.
   Isolation: documented parallel mode = separate HOME + marker file + `WSL_INTEROP=1`/force-file env + `AGY_SWAP_SKIP_SYNC=1` (reference.md:199-211). This is the closest thing to real per-account isolation; it does not touch keychain.
3. Running agy: wrapper runs `agy-swap --sync-session` before and after each agy run; session_guard.go reconcileActiveSession (:182-285) reads disk tokens, matches owner by refresh token/email, "harvests" a fresher token (later expiry) back into the vault (shouldHarvestToken :153), then rewrites files to the intended account. Under a session lock. For IDE "hub" background agy: touches reload marker and `pkill`s hub so wrapper restarts it (reference.md:61; credentials.go:117-175). Interactive agy sessions are not killed; they keep old in-memory token. Mitigation of clobber = harvest-after-exit + re-sync, not prevention; a still-running agy can still rewrite the file until synced.
4. Usage: same endpoints; per-account token from vault; separate non-keepalive TLS client per account (oauth.go:126-148) so accounts share no socket/session; memo cache of project/tier; Argon group via fetchAvailableModels.
5. Maturity: 503 tests, big CHANGELOG (61KB), releases, brew tap, site. MIT. Red flags: unencrypted vault.json default; token in argv to `security`; replaces agy binary with wrapper (and may touch Desktop IDE); daily version check to agy-swap.aklkbqx.com + GitHub; website/donate/marketing; embedded OAuth client secrets; very large surface (TUI, profiles, autoswap) = more to audit. No usage telemetry claimed.

## Verdict for loom
(a) Per-account usage: copy mechanism from either, preferably agy-auth's `internal/usage` approach: keep one credential JSON per account (loom-owned), refresh in memory, POST loadCodeAssist + retrieveUserQuotaSummary with UA `antigravity/cli/<ver>`. Fully independent of running agy and keychain; reliable. Risk: refresh-token rotation (if Google returns a new refresh_token, persist it) and refreshing with agy's client concurrently with a live agy using the same refresh token (usually Google keeps old refresh token valid; verify).
(b) Switch: two designs.
  1. Global switch (both tools): rewrite keychain `gemini/antigravity` + file token; needs agy restart; clobber risk. Not "minimal disruption".
  2. Preferred for loom: per-worker HOME isolation (agy-swap reference.md pattern). Each account gets `HOME=<loom>/homes/<acct>` containing `.gemini/antigravity-cli/{antigravity-oauth-token, cache/antigravity-keyring-unavailable (mtime far future)}` and env `AGY_CLI_FORCE_FILE_TOKEN_STORAGE=1`. No keychain write, no cross-process clobber, and switch = start/relaunch agy with a different HOME. Our earlier test failed because HOME was unchanged (token file at real ~/.gemini and keychain still read); ANTIGRAVITY_APP_DATA_DIR is irrelevant to auth.
Loom steps (design 2): create home; seed token file (0600) from account JSON; touch marker with future mtime; copy/generate installation_id; (optional settings.json gcp block); launch agy with HOME override + force-file env; after agy exits or periodically read back the token file and persist if expiry newer (harvest); usage polled by direct HTTP from loom's own copy (or the harvested file).
Do not run `agy -p "/usage"` for accounting (borrows a running instance's login).

## Live prototype test plan (user logs in each account once; never use real HOME)
1. For account A: `mkdir -p $H/A/.gemini/antigravity-cli/cache; touch -t 203601010000 .../cache/antigravity-keyring-unavailable; HOME=$H/A AGY_CLI_FORCE_FILE_TOKEN_STORAGE=1 agy` -> user logs in. Verify: `$H/A/.gemini/antigravity-cli/antigravity-oauth-token` appears; real keychain item `gemini/antigravity` (check attributes only, `security find-generic-password -s gemini -a antigravity` without -w) unchanged (mtime/modified date).
2. Repeat for B. Confirm A and B tokens differ (compare id_token email claim, no printing of secrets).
3. Start agy under A and B concurrently; confirm each shows own account and /usage differs. Confirm a third agy with the real HOME still shows the user's original account (isolation holds, incl. macOS keychain not consulted when marker is present; if keychain IS still read, try also WSL_INTEROP=1 as agy-swap's docs do).
4. Check whether `-p "/usage"` under HOME=A works with no other agy running, and whether it borrows a running instance under another HOME (expected: no, per-HOME socket/state; verify, check ~/.gemini vs HOME/.gemini daemon sockets).
5. Token refresh: run agy under A past access-token expiry (~1h); diff expiry/refresh_token in file before/after: does the file get rewritten, does refresh_token rotate? Then call loadCodeAssist/retrieveUserQuotaSummary from loom's prototype using the snapshot taken before; verify still valid (refresh token not invalidated) and quota matches agy /usage.
6. Switch drill: stop agy under A, copy B's token into A's HOME (or just launch B's HOME), relaunch; confirm account, conversation/state location (does history live under HOME/.gemini and thus split per account?), and installation_id behavior.
7. Clobber test: with agy running under HOME=A, overwrite its token file with B's; wait for refresh/exit; see whether agy rewrites A's token back.
8. HTTP usage check: UA string requirement (generic UA gives only Claude/GPT group), project id source for accounts with different tiers.
Open items not verifiable from source: how go-keyring writes on macOS (vendored, not in repos); whether agy 1.5.18 still honors marker/env identically to what these tools (tested on ~1.4.x per UA string `antigravity/cli/1.4.5`) assume.
