# a11y、get-selected-text、wterm 与 loom（2026-11-26，只读调研，未构建、未运行、未启动任何应用）

- **a11y（accessibility）**：操作系统给读屏软件的接口。macOS AXUIElement（`kAXFocusedUIElementAttribute`、`kAXSelectedTextAttribute`、`kAXValueAttribute`、`kAXChildrenAttribute`，`AXUIElementPerformAction(kAXPressAction)`，需 TCC"辅助功能"授权）；Windows UI Automation；Linux AT-SPI2。对 agent 友好在于读到带角色的结构化文本、按引用操作，不靠截图/OCR/坐标。TUI 更好：PTY 纯文本进出，无需权限、无实现质量问题。佐证：microsoft/Hybrid-Computer-Use（AX 引用 + 差量回读，截图兜底）、mac-computer-use-mcp、A11y-Compressor（arXiv 2605.00551，a11y 树线性化费 token，压缩到约 22%）；反方纯像素：UGround、UI-TARS。原句"TUI > GUI with a11y > GUI"未找到出处，但与实践一致。
- **yetone/get-selected-text**（HEAD 0ddeb5d，crate 0.1.6，Rust，MIT/Apache-2.0）：macOS 先读系统焦点元素的 `AXSelectedText`；失败则 osascript 保存剪贴板、静音提示音、模拟 Cmd+C、等 100ms、比对 changeCount、恢复剪贴板；按应用名 LRU 记住哪种方法有效。Windows/Linux 只有模拟复制。"a11y 最快、最不侵入、最正确，但很多应用不规范"：AX 一次同步读取、无副作用；自绘界面、未开 a11y 的 Electron、多数终端不给 `AXSelectedText`，只能走慢且侵入（动剪贴板、向前台注入按键）且有竞态的回退。
- **Alma**（com.yetone.alma 0.4.1177）：自带 Swift 辅助进程用 AX 取前台应用、窗口标题、焦点 `AXValue`、`AXSelectedText` 及窗口文本树，用于 QuickChat"注入实时屏幕上下文"；另带 computer-use skill（AX 动作优先、`CGEventPostToPid` 回退、不抢焦点）。**Herdr 窗格内容不经 AX**：alma-server 调 Herdr 的 `pane.read` RPC 取原生文本/ANSI。
- **Herdr**（dev.herdr.app 0.1.18，GPUI）：是 a11y 树的**提供方**（`NSAccessibilityElement`），不是读取方；自己持有 PTY 文本，不需要 AX。
- **vercel-labs/wterm**（HEAD 4b6307e，v0.6.0，Apache-2.0，实验项目）：Web 终端模拟器，Zig 写的 VT 解析编译成约 49KB WASM（可选 libghostty 内核），行渲染为 DOM 真文本（原生选择、查找、读屏天然可用），可选 WebGL；通过 WebSocket 接 PTY；`webmcp` 给页面内 agent 提供列终端、读屏/回滚、等输出、输入按键等工具，`term.readText()` 取文本快照。是渲染器与浏览器桥，不是 PTY 宿主。
- **对 loom**：核心路径无收益——loom 已从 holder/PTY 屏幕、原生记录和 hook 拿到第一手文本，经 AX 只会是有损副本外加权限。可选的边缘用途：全局"选中文字发给 agent"热键（AX 优先、剪贴板回退）；让 worker 操作原生 GUI 应用时借用 Alma 的 computer-use 工具，不自建。风险：辅助功能授权等于对所有应用的界面读写权（隐私与外泄面）、授权绑定具体二进制签名（重建/换终端需重授）、覆盖不均、回退会动剪贴板和注入按键（违背不抢焦点、不静默失败），以及每次读树的 token 成本。结论：不纳入 loom 核心。
