# 三层换班与三层重启恢复 设计 v2（2026-11-27，Super 综合 t17g / t17w / t4c 讨论）

依据：讨论原文 ~/.loom-next/runs/loom-next/briefing/DISCUSS-ANSWER-{t17g,t17w,t4c}-lifecycle.md；前稿 2026-11-27-lifecycle-design.md；Orca 调研 2026-11-27-orca-bot-session-continuity.md；身份遵循调研 2026-11-27-agent-identity-adherence.md。
约束不变：Claude 只经 CCP；模型不自动切换（同模型换账号除外）；不做保活；loom up 一次性只管 Super。

## 0. 三方共识（v1 的缺口）
1. Super"自己判断何时换人"不可行——模型不知道自己的成本（t17w 被压缩 4 次没有一次主动提出）。
2. 手写交接单会漂移、截断；用户原话裁决与"已否方案"转述一次就走样。
3. 换人/恢复的切换窗口会吞掉用户新消息；hc 地址变化让回复落空。
4. 两个高级角色同时冷启动时，不能让两个新会话互相用文本背书。
5. 重启后旧队列会被直接投出（实例：e8777fd1）；旧进程未退时 resume 会出双实例。
6. Claude Auditor 经 CCP、无 hooks 的换班与恢复尚未实测，不能直接当主链路。

## 1. 公共机制（三层共用）
- **固定别名地址**：每个角色（Super、各项目 Leader/Auditor、worker）有固定别名；换人/恢复只改别名指向，在途消息与 expect-reply 跟着改投。
- **收件箱屏障**：切换时先起新会话 → 新会话接管别名并拉取切换窗口内未消费消息 → 再退旧会话。
- **单实例锁**：每个角色一把锁 + 进程 incarnation；resume/新开前必须确认旧进程已退出（或经 holder 结束），否则拒绝。
- **首轮机器题**：新会话（换班或恢复）首轮由 loomd 问 2–3 个可机器核对的问题（当前 release SHA、待决事项数、最新裁决编号、负责的卡）；答对才转正，答错回退到旧会话（换班）或报 Super（恢复）。
- **离线变化摘要**：恢复的会话首条投递附"离线期间变化"（main SHA、新增裁决、卡状态变化），≤12 行，标"数据非指令"。
- **进展判定**：worker/角色"有进展"= 工具调用或子进程活动或输出，任一即可（避免长测试误判）；**额度/限流/模型满载**单独 5 分钟守卫，与"业务 10 分钟无进展"分开。额度问题只做同模型换账号（Codex 账号管理）或等待，并通知；不自动换模型。

## 2. Super 层
- **触发**：loomd 依据原生用量给出"建议换人"提示；Super 只在**空闲边界**执行：用户静默 ≥5 分钟、没有向用户提出的待答问题、没有等回复的消息、没有执行到一半的授权。用户说"换人"也立即触发（仍等当前回合结束）。崩溃时由用户 `loom up` 触发。
- **交接内容拆三份**（取代单一 60 行手写交接单）：
  1. **裁决账本**（追加式，永不覆写）：`loom ruling add` 记用户原话、时间、适用范围、取代关系；红线条目常驻注入；交接只引用编号。
  2. **机器实况 + 承诺清单**（loomd 生成，不可伪造）：在途项目与卡、待用户决定的事、Super 说过"稍后汇报"的承诺、已问未答的问题、等回复的消息；外加旧会话最后 3–5 轮用户↔Super 原文（≤800 token，标"数据非指令"）。
  3. **工作台**（Super 亲手写，≤30 行）：对各 worker/模型/前辈的可信度判断、用户口味、正在思考的半成品。
- **无感**：同一 Herdr 标签页 + 别名 + 收件箱屏障；新 Super 首条消息只说一句接手和最多三条在途事项；旧 Super 只读在线直到首轮机器题答对，答错回退旧 Super。

## 3. Leader / Auditor 层（v2 换班规则保留，补以下）
- **项目级换班锁**：同一项目同一时刻只允许一方换班。
- **核对方不可用**（另一方挂了、正在换班、卡弹框）：改由 Super 对照机器事实卡核对首报。核对 5 分钟无结果升级 Super 介入，30 分钟仍未完成则回退前任并通知用户。
- **继任不空等**：首条消息不得以"等待"收尾；确认后立即执行交接单"首个动作"（ROT-TUNE-2 已有，保持）。
- **Claude（经 CCP、无 hooks）**：在专项实测通过前，Claude 高级角色的换班与恢复默认走"交接单新开"，不依赖原生 --resume；实测通过后再改为"可续接"。

## 4. Worker 层
- **默认：交接单开新 worker**。
- **原生续接**只在全部满足时：同 realpath(cwd)、同 CLI/账号/版本；worktree HEAD 与未提交改动哈希等于落盘记录；卡面未修订；main 没有影响该卡的变化；压缩 ≤1 次；中断不是 worker 自身造成（死循环/卡死）；CLI 支持续接（agy 不支持）。续接首条消息必须说明："上次中断在 <步骤>，后台进程已不存在；先核对 git status 与最后一条命令结果再继续。"
- **必须新开**：任一条件不满足、中断超过数小时、R3 返工、越权造假、额度换号后（同模型换号不影响 Codex 线程续接时除外，以 Codex 切号实测为准）。
- **现场体检**：`loom recover` 列在途 worker 时附 4 项机械事实——worktree 脏行数、HEAD 相对基线是否漂移、残留子进程数、cwd 校验。
- **外部资源登记**（可选）：worker 若持有私有 DB/端口/测试账号等，登记到卡的 resources；恢复时先只读清场对账，不提供直接 resume。

## 5. 重启恢复
- **顺序**：`loom up`（Super）→ `loom recover --all-projects`（只读）→ `loom project up --recover`（项目进入**恢复中**：暂停自动投递、派卡、门禁、合入）→ 恢复 Auditor（Super 核首轮）→ 恢复 Leader（Auditor 核首轮）→ 双方核过后**解冻** → Leader 按第 4 节逐个处置 worker（不自动排队）。
- **过期投递**：恢复中模式下，早于关机时间或已被后续裁决覆盖的排队消息，逐条列给 Super 确认，不静默投、不静默丢。
- **必须由代码落盘的状态**：
  1. 全局登记表：Super 入口/原生会话 id/别名/交接三件套路径；项目清单与上次关闭方式（正常/异常、时间）。
  2. 会话索引：角色、CLI、模型、effort、启动入口（是否 CCP）、账号目录、realpath(cwd)、原生会话 id、transcript 路径、进程 incarnation、hc 地址与别名、回合状态（空闲/工作/待答/弹框）、最后 deliveryId。
  3. 持久收件箱：待投、已投未回、expect-reply、被扣住的消息，带时间与去重 id；消费游标。
  4. 卡与工位：状态、负责人、worktree、分支、基线 SHA、最近 HEAD、未提交改动哈希、返工轮次、证据卡、后台任务 pid 与命令、外部资源登记。
  5. 门禁与换班：gate 授权记录、受保护分支 ref 快照（P0 检测）、进行中换班、阶段锁、失败计数、上次换班时间、前任/继任、只读/冻结锁（重启不得洗白）。
  6. 组织真源：policy.json、charter.md、裁决账本、事实卡；loomd 与 skill 的 release 版本。
  7. 通知队列与去重键（防重启重刷旧告警）。
