# 随机模型下的业务交付与长期成本验收设计

状态：最小业务冒烟执行器已实现，免费真实 CLI 链路和独立审计通过；owner 已要求开始测试，本批一次冒烟配对 P121 已完成，业务样本通过、效率未验收；见[P121 报告](evidence/2026-10-06-business-smoke-p121.md)。目标合同和历史裁决不变。本文取代 P118–P120 的路径限定方案作为后续设计依据，旧入口和证据作为历史保留，不再作为下一批默认入口。

## 1. 要回答的问题

在相同任务、材料、模型绑定、effort 和原生记忆策略下，Loom 能否正确、安全地完成任务；相对原生 CLI，实际累计消耗与完成时间是多少，跨独立运行有多大波动？

不再要求模型产生相同思考、文字、工具顺序或生成次数。答案内容、执行行为与程序计量分别核验。一次成功不代表稳定；一次恢复也不自动导致整个长期实验结束。模型多想、少想、犯错和修正造成的实际费用都属于使用成本，不因“随机性”扣除。

owner 提出的“查时间/日期通常一次用对工具”作为低歧义接口的设计参照，不作为已测得的成功率：目标唯一、参数少、结果明确，值得用于审查回复接口是否让模型承担了本可由代码确定的身份、目标或状态。工具选择可靠性仍只是诊断项；一次工具调用不等于一次模型生成或一次 HTTP 请求，工具结果之后可能还有回答生成，网络重试也须单独记录。不能把“首次用对工具”提升为产品验收目标，更不能用它代替答案质量与完整长期成本。

归因分两步：固定假模型行为、贯穿真实产品链，验证平台是否强制增加步骤、丢失结果或漏记用量；再以预先冻结的真实模型配对观察接口选择、恢复与成本波动。前一步不能证明真实模型会选对工具，后一步的一条轨迹也不能证明某句提示导致失败。已有 [P122](evidence/2026-10-06-business-long-p122.md) 两臂各记录 36 次生成，产品总输入仍为原生约 1.37 倍且有三题错误，说明相同生成次数也不等于质量或效率通过；完整请求中的固定声明和累积历史须继续独立检查。

P118/P119/P120 各只有一个产品阶段，且实验条件不同，不能作为同一研究的三份重复样本，也不能借用已完成的原生长链作为新实验分母。P120 已证明“最终正确送达”和“限定 MCP 路径”可以有不同裁决；后续业务门禁不得再把二者混成一个布尔值。

## 2. 三层验证，各自独立

| 层           | 方法                                                                                                         | 能证明什么                                        | 不能证明什么                             |
| ------------ | ------------------------------------------------------------------------------------------------------------ | ------------------------------------------------- | ---------------------------------------- |
| 程序与计量   | 固定事件、故障注入、临时 DB、轨迹重放；真实 CLI 连接本地假模型                                               | 权限/唯一性/ACK/用量归属/停止机制在所测输入下正确 | 真实模型的选择概率、成本或任务能力       |
| 真实模型观察 | 预先冻结任务、独立配对与停止规则；保留所有路径和费用                                                         | 本研究范围内的质量、恢复、成本及波动              | 从一批推断稳定、因果开销或所有模型均适用 |
| 合同裁决     | 对真实观测逐条应用[目标合同 §6](target-contract.zh-CN.md#6-验收数字对照原生-cli-同一-session同模型同-effort) | 哪些指标达标、失败或证据不足                      | 用累计均值抵消某项合同失败               |

合同数字不在本文重述，也不改为概率阈值。改变合同必须另获 owner 批准。实验是否继续收集数据，与是否已经出现合同失败，是两个状态。

## 3. 实验单位与公平条件

一个独立配对包含原生和 Loom 两臂；每臂三个独立实例/原生会话，各连续十二阶段，阶段次序固定。会话在臂内保持连续，不按任务或 token 重建；另一臂和另一配对使用新的独立会话，不共享原生自动记忆或历史。配对内模型、effort、CLI 版本、源码、任务哈希一致；服务端具体模型版本不可验证时明确记录为未知。

每次 initial 和 resume 在调用前验证 provider-owned 自动记忆关闭，并记录实际参数及可获得的运行证据；不能核实则不准入。正常同 session 历史保持开启。产品平台记忆的开关也在 manifest 中固定，当前传输研究关闭长期记忆干预；既有 session 中已注入的索引不能通过开关当作撤回，故研究使用独立临时数据和新会话。

完整材料各 session 首次实际投递一次，后续不重发；两臂收到相同业务指令，平台必须存在的工具/交付指令属于被测成本。原生通过固定中继得到本臂实际同伴消息，Loom 通过 Room 实际投递，不把一臂答案复制给另一臂，不填标准答案。模型答案改变后续历史是实际运行差异，保留并报告，不能声称全部输入差都是纯协议开销。

当前三人同题、可见同伴答案的事实核验只作为**传输成本工作负载**，不证明三份独立审查或协作价值。下一类真实协作任务需要独立冻结任务、质量标准和重复计划，不能混入此分母。

缓存只观察、不伪造冷缓存，不在失败后为某一臂单独预热。分别报告缓存与未缓存输入；执行顺序预先交替，降低顺序混杂但不声称消除它。不给生产 session 改 seed/temperature 来强求轨迹一致。

## 4. 以业务结果为准，不限定传输路径

正式业务判据由同一套可信事实组成：当前主体和目标正确；规范 Room 事件与唯一消息对应；Run/Activation/session 归属明确；真实消费者 ACK；状态、用量、终止证据完整。Kernel 是业务事实 owner，原始 provider 轨迹用于诊断和用量交叉，不能独自证明业务成功。

MCP、Worker CLI，或合法的 MCP→CLI 恢复，均可满足业务交付。需要识别“是否发生未授权行为”，但不应把某种 JavaScript wrapper 写法列为业务正确的必要条件。优先在现有 Worker 应用服务调用/回执边界观测，独立记录传输类型，不靠执行模型脚本来理解它，也不创建第二套业务状态或 ACK。

具体规则：

- 唯一正确发表：交付成功；即使前面多次被拒，重试费用全部计入，一次成功指标为失败。
- 发表了错误答案：质量失败，实际费用保留；若系统安全且能按现有业务机制继续，则执行后续预定问题，保留错误历史，不人工纠正。
- 明确拒绝且无业务写入后恢复：记录错误类别、恢复及全部费用；不规定恢复必须走原工具。
- 幂等重放：一个业务事件算一次发表；每次请求与生成照计成本，重放不等于首次成功。
- Run 安全结束但没有规范回复：交付失败；只有在平台现有机制允许继续且未留下不明/活跃工作时，才准入下一阶段。不得伪造 ACK、替模型补发或手工完成 Activation。
- 非任务所需但无害的工具调用：记录遵循指令问题和费用，不仅因调用次数多而中断。未授权修改、越权、危险副作用仍触发安全停止。实验目录授权范围和禁止行为预先固定，不用临时语义判断追加授权。

路径识别不完整但业务与完整计费均可核实：传输诊断标为 unknown，不冒称 MCP 成功，也不因此取消业务观察。若不能核实行为是否超出授权、存在未知写入结果或用量缺口，则按证据不足停止。不得把“看起来最终成功”当作放行所有工具的理由。

## 5. 停止规则与不停止规则

| 条件                                                                     | 决策                                                             | 保留与裁决                                   |
| ------------------------------------------------------------------------ | ---------------------------------------------------------------- | -------------------------------------------- |
| 越权、泄露、错目标写入、非幂等重复发表、执行围栏失效                     | 立即停止相关运行和后续准入，安全清理                             | 安全失败，所有已知成本保留                   |
| 源码/模型/记忆/会话/材料条件漂移，未知写入结果，不能核实的行为，用量缺失 | 暂停新阶段；只做不产生新付费调用的证据核对；仍不能恢复证据则结束 | 证据不足；不填零、不补跑、不拼历史分母       |
| 时间/token/执行数上限，Run 无法安全终止                                  | 停止下一阶段或按既有取消机制结束在途工作                         | 截断；记录实际超限，未运行阶段留空           |
| 答错、拒绝后恢复、多次思考、额外生成、已知合法路径变化、单轮超预算或慢   | 在安全及资源边界内继续预定序列                                   | 相应质量/可靠性/合同项失败，全部费用进入总账 |
| 原生先出现质量失败                                                       | 不自动取消产品臂                                                 | 两臂按预定条件各自观察；等质量比较可能不成立 |

不发送“请换成某工具再试一次”等实验员干预提示。不允许通过换会话、换模型、重跑某轮或标准答案回填修复样本。CLI 自身的请求重试、平台原有的调度重试必须记录实际执行和费用；实验器不得另加重试。现有产品无法合法继续的失败不能为研究强行绕过，标明触发条件与受限范围。

## 6. 质量判定与不美化成本

事实任务采用冻结的答案结构和确定性语义解析。可以容忍不改变含义的格式差异，如已列明的空白/代码围栏；关键字段、值、否定、unknown 与 absent 不可互换。冲突答案或解析歧义保留为不可判定，不挑一个有利值。答案表只在评价器侧，不进入模型上下文。

开放式任务另设固定评分表，覆盖事实依据、产物正确性和用户要求。评分者对实验臂匿名；保存原文、评分与分歧，人工裁定不能改写模型输出。额外付费 LLM 评审需另行授权，不是默认必需环节。

同时提供两张账：

1. **所有尝试账**：包含答错、失败、重试、思考、工具返回、收尾、恢复及截断前的全部已知费用。
2. **质量与完成账**：每个预定阶段的正确/错误/不可判定/未完成和最终送达情况。

当前事实工作负载的等质量准入固定为：两臂各 36 个预定阶段均完成且语义答案正确，并具有完整送达和用量证据。双方恰好同样答错不算等质量合格；错误不会阻止安全条件下继续观察，但会使该配对的等质量效率结论不成立。

只有工作范围完整、证据充分且满足预定等质量条件，才报告“同等质量下的效率比较”。质量不相等时，仍可展示两臂实际总费用和质量差，但不得宣传便宜的一臂效率更高。不得仅筛选正确轮次重新计算一个好看的主倍率；任何成功子集统计必须标为附加描述并同时展示全量账。

## 7. 报告格式与随机性

每次配对保留逐阶段原始量，以及每实例首次、第 4/8/12 阶段累计值：总输入、缓存输入、未缓存输入、输出、CLI 实际提供的思考量、回复前/后生成、延迟、上下文/压缩可见性。没有的数据为 unknown。原生与产品 DB/轨迹中的同一费用只能算一次；语义或归属不确定的费用单列，不能无声丢弃。

主要累计量采用**同范围总量之比**；不以逐轮比值的简单平均替代。各独立配对分别展示，再提供等长完整配对的合并总量比和配对比值的中位数、范围。截断样本单独展示范围和成本，不能塞入完整样本分母或按未运行阶段补零。分母为零的比值为未定义。

总输入不是货币价格。仅当实际适用费率及缓存/输出等类别有可靠依据时才另列估算金额，注明估算而非账单；否则只报告 token 向量。平台纯固定开销、模型思考、缓存、业务工具及历史差异可以按可核实证据分解，无法分解部分明确保留，不把全部差异归为平台因果效应。

可靠性分开报告实际尝试数、一次正确送达、恢复后正确送达、最终失败、未运行、未知、重试类别和费用。已观察失败不从分母消失，未运行阶段不冒充观察。连续 session 内轮次相关，独立重复单位是完整配对而不是某一轮或某个同频道实例。

小样本不提供虚假的总体尾延迟、p95 或“稳定成功率”；先列原始配对值、中位数和观测范围。四个配对只构成探索性重复，不足以证明罕见错误率或一般性稳定。若后续确需统计稳定性结论，必须先确定关注效应、可接受误差与样本量方案，再独立授权；不能边看结果边加样本到显著或通过。

## 8. 从免费验证到付费研究的固定顺序

### A. 免费程序验收

先实现业务结果与路径诊断分离、观测继续规则、两张账、独立裁决状态。测试固定种子/固定轨迹，不能让测试本身随机失败。覆盖 MCP/CLI/混合恢复、不同合法 wrapper、额外生成、答案错误后继续、无回复终态、末轮恢复、幂等重放、费用缺失、unknown write、错目标/重复写入，以及截断不填零。至少把 P118–P120 实际轨迹作为只读回归材料；历史裁决不变。

真实 CLI 加本地假模型穿过正式护栏和执行链，既测多种合法路径，也测必须停止的反例。先修完已知目标参数歧义再冻结付费源码，避免用付费发现已知问题。目标绑定必须尊重顶层/Thread/private box/多目标合并/held draft；不存在唯一目标时不能猜测。

### B. 单独授权的真实冒烟

方案默认 Codex `gpt-6-luna/low`。一次配对，两臂各三 session×两阶段；Loom 先、原生后，优先尽早发现产品入口与观测缺口。冒烟验证路径是否可观察和费用是否完整，不用质量好坏或暂时倍率决定是否挑选该样本。发现安全或观测阻断后停止；不自动换工具提示或重跑。冒烟费用单列，不并入长期分母。

冒烟的输入/token/时间/最大执行数上限应从免费护栏演练和保守的既有实测冻结到 manifest，授权前展示准确数值。尚未实现的 manifest 不允许付费启动；本设计不授权模型调用，也不默许沿用旧 runner 的停止逻辑。

### C. 单独授权的探索性长期研究

固定 **四个独立配对**，每臂三 session×十二阶段，共 288 个预定阶段；每配对臂顺序为原生→Loom、Loom→原生、原生→Loom、Loom→原生。保持唯一模型/effort/workload，不同时扩展四家 CLI。四对不是“稳定达标”的样本量承诺，只用于避免依据一个偶然样本作判断。

每一配对是独立付费批次，启动前需要明确授权；owner 可以一次明确授权列出的四批及其总上限，否则不得从一批授权推导其余三批。全研究及每批资源上限、截止时间、执行顺序与代码哈希在第一批前冻结。不得因前几批好看而提前宣布稳定，或因不好看临时增加批次。owner 可随时停止，结果按部分研究报告。

若任何配对暴露安全/观测系统性阻断，剩余配对暂停；修复后产生新研究身份，已发生费用不消失，不能接着凑成原研究的四个成功样本。普通质量失败、成本高或模型换合法路径不触发这种系统性暂停。

## 9. 最小实现责任与交付

这是验收工程，不建立生产场景流程。`packages/kernel` 继续唯一拥有 Room、ACK、权限与执行事实；应用服务/AgentHost 保留真实工具回执、运行与用量观测；`scripts/cli-efficiency` 仅负责实验清单、调度准入、证据核对、质量评分和汇总。不把 provider transcript 升级为业务真相，不新增平行队列或伪状态。

执行器最少拆分 `executionIntegrity`、`deliveryVerdict`、`qualityVerdict`、`costEvidence`、`contractVerdict`、`observationStatus`、`transportDiagnostics`；这些都是实验结果字段，不能改变生产业务状态。继续/停止由显式原因决定，不再 catch 任意 assertion 后终止整个研究。

实施顺序：固定报告与停止规则的失败测试 → 业务交付证据适配 → 计量和质量解耦 → 全路径免费链路 → 已知接口问题修复与验证 → 冻结可运行 manifest → 请求明确的冒烟授权。产品修复遵循 TDD、完整检查及服务重启验收要求；仅文档设计不触发部署。

## 10. 设计结论

评价对象是“实际完成任务的产品”，而不是“模型是否复现一条预定工具轨迹”。可重复的是任务、约束、测量与裁决规则；随机的是模型轨迹。设计允许后者变化，同时保留失败、质量差、超额成本和未知证据。

当前入口为 `node scripts/test-cli-business-smoke.mjs --plan` / `--paid`；产品先、原生后，各三连续 session×两阶段，每臂输入上限 600000、时间上限 600000 ms，产品最多 12 个 RunAttempt。资源上限是止损条件，不是效率预算；单个在途请求不能被精确截断到 token 上限。付费只运行一次，不自动补跑。免费证据见[业务冒烟链路](evidence/2026-10-06-business-observation-free.md)。
