# 手机布局根因与消息状态接线（2026-10-20）

本批目标是已采用Web页面的手机可用性，不是原生iOS应用移植。官方Web锚点保持v1.21.22；本轮另外取得官方移动端 `https://github.com/botiverse/mobile` 的 `655975433b8492a8f4eef7bbce1b913140bc7485`，阅读iOS/Android共用的Compose源码与iOS UITabBar宿主，保留FSL-1.1-ALv2授权边界；没有复制原生执行代码。

## 根因与处理

| 问题                           | 证据                                                                                                                                                             | 本批处理                                                                                                                                |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| 底栏图标视觉不对称             | 五个横向中心等分，但原生MobileNavItem仍是带文字版本的`flex-col justify-start gap7`，隐藏文字后图标在44px按钮顶部；`::before`保留黄色选中贴片，与胶囊选中底色叠加 | 既有纯图标胶囊布局明确居中、gap0，去掉带文字版本的伪元素；保持22px图标、44px点击区域和50px底栏；不是复制UIKit材质                       |
| 消息文字偏大                   | 原生`SlockDesignTokens.kt`的`SlockTextSize.Content=14sp/20sp`，源码注明16sp真机试用后回退；Web无设置时默认16px                                                   | 手机首次加载且无显式字号时采用现成14px档；不写入偏好，已有14/16/18px选择优先，桌面默认仍16px。未改字号档位、官方名称/说明随字号变化规则 |
| 任务标题数量叠行               | 本地TasksPage把标题与数量放在新版默认纵向PanelHeaderContent，既有手机同排断言失败                                                                                | 手机限定该页标题内容为横向居中；不缩小原生触摸按钮                                                                                      |
| 头像、输入与大标题是否都应缩小 | 原生ThreadPage.kt消息头像36dp，与当前Web36px一致；IconButton44dp、MinTouchTarget48dp；当前原生普通标题56dp/紧凑48dp                                              | 保留头像尺寸和既有48px紧凑标题，不做全局缩放。输入保持已有Safari避免聚焦缩放的处理；本批未改字体家族                                    |

原生尺寸是dp/sp，Web是CSS px，二者不是物理像素等价。浏览器已有显式16/18px偏好不会被本批覆盖；iOS系统文字放大、浏览器页面缩放也不能由桌面模拟排除。

## 消息状态

唯一运行事实仍来自Kernel。AppearanceRuntime已有的当前对话读取循环，同时读取`room.agent.activity.list`与`room.member.list`，投影给消息；没有新调度器或持久状态。频道/私聊及其消息列只消费同roomId事实。其他来源未绑定时不展示猜测状态。

- 运行中、排队/启动、空闲、执行错误采用`raft-ui Status`与原生AvatarBadge方形角标；空闲不等于在线。
- 权威成员列表中不存在的实例作者显示“已离开”，头像沿用官方停用灰化；不显示“已删除”。Role配置删除不参与判断。
- 加载中、失败、换频道或无观察时撤掉角标/离开推断，不把缺失记为离线；保留旧响应隔离。
- 聊天状态不受“显示底部实时动态条”外观开关影响；模型/工具不参与状态推断。

## 验证范围

新增状态投影与手机默认字号单测先失败后通过；底栏中心断言先失败。临时Core浏览器用明确的作者/运行状态响应夹具覆盖四种状态、离开、失败清除与恢复，不伪装真实模型执行。消息默认字号分别验证390px为14、桌面为16，不持久化隐式默认。

现有手机导航门禁含已被后续官方版本替换的旧规格：记忆筛选已改用32px/13px原生任务筛选配方；页头按钮现为44px原生PanelAction而非旧32px加扩展区；桌面多页已移除多余标题。测试按当前原生来源更新，保留真实点击、边缘命中、键盘视口、返回与聚焦断言。任务标题叠行是真实产品回归，已修复。

Chromium/WebKit短屏与阅读/编辑布局检查、正式页面检查结果见同日证据文件。390×844阅读态composer54px、标题48px、正文693px（约82%）；360×640正文489px。不能称这些数据为真机iPhone/Android验收；真实系统键盘、安全区、浏览器缩放、PWA后台和推送仍待真机验证。本批无付费模型调用、无全量后端套件。
