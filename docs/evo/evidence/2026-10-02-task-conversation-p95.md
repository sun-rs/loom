# P95：Task 与频道差额读取的四轮真实验收

**本批功能路径通过，回答质量有偏差；不能据此宣称完整效率门禁或 P94 真实过期重试验收通过。**

负责人授权两个 Codex `gpt-6-luna / low`，最多四次运行，异常即停、不自动补跑。产品 `7456a81`（部署记录 HEAD `526b712`），正式 4176，新频道 `p95-task-continuation-20261002`。两实例各两轮，实际四次，无补跑；placement 与每轮原生 turn_context 的模型、effort 均匹配。

## 实际通过的路径

1. Human 创建并指派 A 的 Task；A 读取指定代码、认领、启动、记录进度、提交，状态到 submitted。
2. B 在频道独立审查；Human 在测试脚本中验收 Task 到 completed，用于验证完成后的讨论路径，不等于独立认可回答的每个判断。
3. Human 在同一 Task 消息列继续追问，没有重新打开 Task。只有 A 运行，回复仍在该消息列，Task 保持 completed。
4. Human 在频道追问 B，只有 B 运行。A/B 分别延续原生 session，互不共用；代数未改变。

四个 Activation 均 completed；无调度重试、额外 Run、自写自收 Inbox 或用量缺口。测试频道已急停，结束时无活动运行。

## 差额不是全频道历史重发

A 第三轮自动正文序号为 `[18,23,28]`：新的频道 Human 消息、B 的频道回复、当前 Task 追问。原生 user 输入同时包含 CHANNEL_P95_CEDAR 与 TASK_ONLY_P95_MAPLE。

B 第四轮自动正文只有 `[37]`，没有重发旧频道正文，也没有 Task 的 #28/#33。B 未关注该 Task，既无此 Task 追问的 Activation，也无该消息列的正文呈现凭据；原生本轮输入没有 TASK_ONLY_P95_MAPLE。其 Room 扫描 ACK 可越过这些不适用事件，不代表读过其正文。

这证明了自动投递选择和传输，不证明模型理解正确，也不是频道内部的隐私隔离。Task 创建元数据仍是频道事实；成员显式历史读取权限未改变。
