本次 owner 同意先核实官方，再对比例进行有限优化，并以同一真实频道截图验收。

原生 dp、Web CSS px 均为逻辑单位，不是设备物理分辨率，也不保证视觉绝对等价。

## 本轮唯一新增例外

高度 <=600 CSS px 时复用已有的紧凑 composer；600 同当前官方 PanelHeader
短窗口断点，但将它用于 composer 是 Loom 自己的设计，不宣称上游已有。
只移动已有 CSS 区块到独立组合媒体查询；窄窗口、coarse 触控原行为保持。

- 空内容且没有附件、任务勾选、textarea焦点：单行。
- 聚焦、草稿、附件、任务状态：保留编辑工具栏。
- 不调整消息字号、头像、边框粗细、导航、列宽或第三栏；不用 transform/zoom。
- 精细指针的矮桌面窗口也享有该行为；普通高度桌面不变。
- 预期低高度正文增加约57px，必须以后截图实测为准，不能用预期冒充结果。

## 验收结果

676f1517 已安全部署，2个数据库/325个文件完成备份，20个业务表哈希和推送配置保持。
回归先失败后通过；6项尺寸/字体测试、6项短窗口/UI契约检查、产品构建通过。
正式服务使用同一频道在390×844、820×1180、1180×820、960×540及600/601边界截图。

| 视口     | 正文高度前→后 | 输入区前→后 | 正文占高前→后 |
| -------- | ------------- | ----------- | ------------- |
| 390×844  | 692→692       | 55→55       | 82%→82%       |
| 820×1180 | 915→915       | 112→112     | 78%→78%       |
| 1180×820 | 555→555       | 112→112     | 68%→68%       |
| 960×540  | 283→340       | 112→55      | 52%→63%       |

短横屏正文增加57px（20.1%），同段末尾完整可见p/li从9到12；不是通用阅读速度指标。
字体14/22保持；手机16/24也未更改。600高时采用收起，601高保持常规展开；
这个边界存在离散变化，是本轮明确的Loom例外，不是连续缩放。

聚焦输入框展开89px；非空草稿失焦保持展开、跨尺寸保留；任务勾选状态保持时
不收起。文件按钮可打开正式文件选择器、关闭回到输入区。草稿和任务勾选最终清空，
没有发送消息/创建任务/调用模型。控制台无error。

截图 after-*.png 和 after-measurements.json 是部署后证据，原文件为修改前证据。
测量为Chrome精细指针CSS视口，不能证明真实触控软键盘/华为折叠设备行为。
本轮仅收口短窗口输入区优化，不宣称所有平板比例已解决；更大栏位调整需要
同条件原生截图与来源进一步核对后单独决策。
