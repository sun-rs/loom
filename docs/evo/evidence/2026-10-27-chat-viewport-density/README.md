宽度改变会改变换行，不能将这些数量当成固定文本容量基准。

可复现问题：短横屏下固定栏位占比偏高。960×540 中顶栏48、频道头48、
tab行49、输入区112，共257px，正文仅283px。1180×820 中频道头为56，
固定区域合计265px。此环境的横屏正文实际字号比手机小，不能将损失解释成
字号放大，也不能把此结果直接等同于用户设备的浏览器布局行为。

当前 compactDensity 依赖 width<768 或 pointer:coarse，未将短横屏高度
独立纳入输入区密度政策。后续应优先核对短横屏输入区折叠与原生顶栏组合；
保留搜索/通知和显式字体偏好，不应全局缩放 UI 或仅强制隐藏桌面导航。
本次只收集证据，没有修改产品或重新部署。
