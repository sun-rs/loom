# 原生自适应布局接入（2026-10-27）

部署产品 `598df5cf`。这是 Loom 外层兼容适配，不是修改或执行 Kotlin 原件。
原生固定源 eff04722 的布局规则在 `native-adaptive-bindings.json` 对应到实际消费者。

## 规则及边界

- 单一 `adaptive-layout.ts` 定义媒体条件：主指针coarse使用840px双栏门槛，
  fine/none保留Web768px；使用CSS逻辑像素，不按物理分辨率/设备名称猜测。
- CSS在现有PostCSS构建边界映射md媒体条件；页面JS订阅使用同一规则。
  原件/生成源码不改。仅映射md，其他断点以及额外pointer/hover条件保留。
  官方useMobileNav hook在已有Vite兼容层映射同一条件。
- 触屏密度与分栏分开：行、字体、间距、表单和composer紧凑规则不因展开失效；
  导航底栏和底部留空仍只属于单栏。主指针切换会更新布局订阅。
- 触屏任务无显式选择时保持列表，显式taskView仍优先；字号用户偏好不覆盖，
  无偏好时触屏首次读取默认小号，折叠展开不改变默认。
- 触屏动态/搜索列表保证右侧至少360px；触屏消息列需窗口1200px且实际容器841px，
  主正文至少440px、消息列400px。不足时只隐藏主栏，保留挂载与草稿，返回仍走原入口。
- 不新增桌面模式开关，采用原生默认开启；不宣称复制全部原生导航/姿态能力。

## 未覆盖

自动化仅能改viewport，无法切换pointer能力；原生桌面UI工具也未能取得浏览器窗口。
因此未声称触屏平板截图、真机折叠、iPad外接键鼠或第三栏触屏实测通过。
下一次真机重点：820左右展开保留底栏；>=840可双栏但仍紧凑；横竖切换不丢草稿；
任务不自动切看板；窄正文消息列使用替换/返回而非挤压。大屏鼠标仍按Web布局。
