## 模型及 effort

2026-10-27，本机 `agy 1.4.8` 的 `agy models` 与正式 Loom `host.runtime.list` 逐 ID、effort 比较一致，共 13 项（原始 stdout 见 models.tsv）。

| 模型系列          | 原生 ID 前缀       | 目录明确发布的 effort |
| ----------------- | ------------------ | --------------------- |
| Gemini 4 Argon    | gemini-4-argon-    | low / medium / high   |
| Gemini 3.8 Flash  | gemini-3.8-flash-  | low / medium / high   |

| Claude Sonnet 5.5 | claude-sonnet-5-5- | low / medium / high   |

每个 ID 含 effort 后缀，是一个独立精确绑定，不把显示标签当 ID。`--help` 的通用 effort 参数虽有 xhigh/max，但不能作为每个模型支持这些档位的证据，因此产品不额外发布。目录可选不等于所有条目都已成功生成、配额可用或账单已确认；本批只实跑 Gemini 3.8 Flash Low，以及 Codex gpt-6-luna / low。

## 协作任务与结果

以 78e8b10d 的真实 AGY parser 和测试建立独立 Channel home 快照；目标是修复负 reasoning token 与安全整数求和溢出。AGY 提方案，Codex 审方案，AGY 加测试和修复，之后原计划 Codex 最终审查、AGY 收尾。流程只在 Human prompt 中表达，没有新增系统工作流或硬编码调度。双方禁用子代理、额外 CLI、Task/记忆写入和目录外修改。

**结果是未完成，不是完整协作通过。**

1. 第一组开场中，负责人把审查员的完整 @ 也写进了步骤说明，导致两位同时被唤醒。属于实验设置错误，不是 Loom 派送缺陷。停止该组，保留所有运行/用量，另建明确只点名 AGY 的第二组。
2. 第二组正确完成 AGY→Codex 方案请求、Codex→AGY 回复、AGY 续接并写出代码和测试。Codex 回复里仍主动 @ AGY，因此本次不证明“B 不 @ 也自动交回 A”。
3. 监控将两组总输入（包括缓存读取）合计计算；达到预设 300,000 输入停止线时，AGY 正在实现轮中。停止请求时已记 301,881，清理期间的已完成生成继续入账，最终已记录合计 320,589 输入、84,113 缓存输入、3,546 输出。全部执行已停止，无静默重跑。取消时未返回的生成/账单消耗未知，不能把缺失部分当作零或宣称与供应商账单完全一致。第二组本身为 188,795 输入、31,249 缓存、2,416 输出。
4. 第一组无效设置消耗也计入停止线，因此这次无法将“没有完成”归因为运行时、模型质量或产品成本。没有原生/Herdr 对照，也不是长任务效率 gate，不给消耗倍数结论。

## 工程产物独立复核

负责人已经直接复现原 parser 会输出 `reasoningOutputTokens=-1` 与超过安全整数范围的 inputTokens。AGY 快照修复包含 thinking 非负安全整数和求和安全整数校验，测试 3 项通过；最终 Codex 代码复审没有发生，不能冒称经过双人验收。

负责人独立接收最小修复，并补上 reasoning 大于 output 的非法情况及缺省/null 边界。主仓库新增 8 项测试中 7 项先复现失败，实施后 AGY 定向 18 项测试和类型检查通过。异常 usage 返回 gap，但保留独立有效的 final、重复步骤去重与 session 校验。没有因一个随机模型行为修改调度或提示词体系。

本次产品变更仅是上述已复现的计量边界缺陷；模型目录映射无需修改。后续协作验收应先把无效设置与有效场景的预算分别预登记，并保留完整失败账；不通过事后扩大预算、重复抽样或把负责人复核算成模型复审来宣称通过。
