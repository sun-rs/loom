# 固定操作轨迹的免费传输诊断

2026-10-10，基于 `ed38108`。实际安装的 Pi、Kimi CLI，经原生入口与隔离的正式 Loom daemon 执行；所有模型响应来自本地假服务，付费请求为零。Loom 显式开启 native-final 试验，未改变部署中默认关闭的开关。

本次固定的是每轮一次真实文件读取和一次最终回答，连续 12 轮；不是让真实模型重做业务题。五个会话共 60 轮、120 次 HTTP 请求、60 次成功读取，均独立核过原流完整性、session 连续性与 provider 进程封账。每臂恰好 24 次请求，没有协议额外请求。它证明此路径无需额外生成，不证明真实模型一定遵循该路径。

## 实测请求体

单位为实际 UTF-8 请求体字节，包含 JSON、工具定义与设置；不含 HTTP headers。**不是 token、未缓存输入或账单。**

| CLI / 路径       | 首次请求 | 最后请求 | 全部 24 次累计 |
| ---------------- | -------: | -------: | -------------: |
| Pi 原生          |    6,067 |   11,684 |        212,958 |
| Pi Loom          |   13,280 |   20,758 |        408,382 |
| Kimi 普通 print  |   89,102 |  100,832 |      2,232,965 |
| Kimi 共享 ACP 桥 |   88,869 |   94,615 |      2,201,754 |
| Kimi Loom ACP    |   96,109 |  103,804 |      2,398,882 |

Pi 的额外 195,424 字节可精确分解为：每请求多 7,046 字节的常驻提示组件，累计 169,104；当前消息包装累计 4,056；历史中旧包装累计重传 22,264。工具定义、设置和当前轮工具结果尾部的字节差为零。常驻提示在各次请求中只有一份，没有每轮新增一份；但它随每次请求重传。新 wake 正文包装每轮约 163–167 字节，也保留在正常会话历史中。

Kimi Loom 比 print 累计多 165,917 字节，比共享 ACP 桥多 197,128 字节。Loom 首次额外常驻正文相对 print 为 6,806 字节。print 自带自动提醒，工具定义在 26/27 项之间变化，ACP 则走手动授权模式；因此不能把 Loom 与 print 的总差全部称为纯协议成本。工具定义本身约 75–79 KB/请求，也使跨 CLI 的请求体比例不可直接比较。共享桥复用产品代码，是模式诊断，不是独立官方基准。

## 结论与下一步

“只注入一次”不能等同于“只传输一次”：这些规则仍随原生历史传输。当前可定位的机械增量主要是常驻提示和每轮消息包装；没有看到读取消息盒强制带来额外请求。此前付费长任务的业务修错、思考和工具结果增长仍须保留，不能被本次合成轨迹替代，也不能全部归咎于随机性。

下一步优先设计按交付模式生成的精简常驻指令，避免同时携带通用 Worker 收尾规则和 native-final 例外。先写保留目标绑定、stale/未知写处理、工具回退等边界的测试，再做免费同轨迹前后对照；只有之后的多 CLI、多模型付费质量与总用量对照，才能证明优化收益。本次未实现该候选，也未修改产品或重启服务。

限制：Kimi 工具结果的耗时前缀不同，固定的是文件正文和操作；Pi 使用合成模型，没有 DeepSeek 思考流；本次无压缩、无多人协作，也不构成五家成本验收。旧付费失败、语义缺陷和所有费用保持原样。
