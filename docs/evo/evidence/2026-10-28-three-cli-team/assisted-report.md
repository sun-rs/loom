# OpenCode／Claude CLI／AGY 三方完整协作测试

Owner 明确要求三家共同完成协作测试。结果：**同一频道、同一批实例及原生 session 完成设计讨论、实现、两份独立评审、真实缺陷修正、复审和最终交付；过程中有一次 Human 通信规则澄清，因此不判全程无人干预通过。** 原先停顿和费用完整保留，没有更换模型或重建成功样本。[本次流程结果](assisted-summary.json)、[本次流程质量](assisted-quality.json)、[计划](plan.json)。

## 完整执行和实际价值

1. OpenCode 阅读共享任务及团队信息，并向两位成员请求设计意见。两家实际回应了精度、舍入、校验、分组和 CLI 设计。
2. 起初同一条请求同时 @ 两位成员，普通 final 按当前有界返回规则没有派生回协调者的投递，讨论停顿。完整账本保留该阶段，不记成功。
3. Human 一次性澄清“多人请求的回复要显式 @ 请求者”后，沿原实例、原生 session、工作区和任务继续；没有提供代码解法或评审发现，也没有清零费用。实际共两条 Human 消息：开场一条、澄清一条。
4. OpenCode 实现 API/CLI 和 35 项测试，明确向两位提出独立评审请求。
5. AGY 实际读取源文件，创建 `review_checks/agy/test_agy_checks.py`，执行 12 项独立 API/CLI 检查和 35 项原测试；原始工具 DONE 记录与输出均保留。
6. Claude CLI 实际读代码与运行测试，发现全局拒绝 JSON float 的实现过严：取消行中的浮点、无关行字段里的浮点，本应不读取却在 JSON 解析时被拒绝。它提供了实际 stdin 失败用例，构成有具体价值的独立评审。
7. OpenCode 改为先用 Decimal 承接 JSON 数字，再在真正读取业务字段时拒绝非法类型；新增回归，37 项测试通过。Claude CLI 独立重放失败用例、确认活跃业务字段的浮点仍拒绝、完整运行 37 项测试后明确接受。
8. OpenCode 最终交付；外部固定检查 **40/40**、自测 **37/37** 通过。负责人随后在最终文件上重跑 AGY 检查 **12/12** 通过。AGY 的接受意见针对修复前代码，最终修复由 Claude CLI 复审，不伪造 AGY 的第二次接受。

这是单任务功能观察，不是成功概率、CLI 排名、全部后端边界或极长历史验收。AGY 最初 `Decimal(str(Fraction))` 建议并不普遍正确；实现采用整数舍入避免了该问题。审查者本身也可能遗漏或判断错误，不能把“模型说通过”当验收。

## 本次发现的两项修正

**AGY 目录等待时间。** 免费准备阶段保留两次失败：第一次私有包装器路径错误、第二次 AGY 明确模型目录为空；均在发送任何付费提示前被拦住，没有创建半组成员再 SOS 恢复。原生 `agy models` 联网刷新，5 秒默认探测期限处在实际约 5–6 秒的边缘；5.2 秒假 CLI 在旧代码上被终止，可稳定复现。默认 AGY 限时改为 15 秒，与 OpenCode 一致；显式更短限时仍生效。15 项相关检查和 root typecheck 通过，第三次免费三成员准备成功、0 生成。[实际时长对照](agy-timeout-control.json)。这解决目录被过早截断的具体原因，不承诺所有离线/网络异常都有模型目录。

**通信说明。** `peerReplyReturn` 仍保持原合同的单跳边界；其只接受一个已实际送达且只点名当前实例的顶层来源。多人点名请求、多个来源和自动返回的下一跳均不猜测接收人。native-final 通信说明补充这些边界，同时要求状态/确认类信息用普通名字，避免无意的 @ 唤醒。新增两项红转绿测试，native-final 六项检查通过。当前同一 session 以一条 Human 澄清恢复；没有声称新增说明已经通过全新 session 的无人干预实测。

## 清理与部署

所有免费及付费隔离 daemon 均已正常退出，无遗留测试进程；测试房间、Role、实例和原流仅保留在私有证据目录。正式服务按要求备份、核对账本后重启，沿用原 Web 构建，真实 Firefox 页面确认正常并保持空频道；部署收据单列。没有删除原失败样本、未知边界或其他会话。

后续最有价值的验收是：使用已补充通信说明的新 session，再观察一次无需 Human 恢复的完整三方工作。只有获得同质量重复样本后，才讨论原生／Herdr 成本倍率；本次不因发现一个路由说明遗漏而重写调度架构。
