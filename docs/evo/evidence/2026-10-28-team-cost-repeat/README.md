## 固定条件与结果

两个真实外部成员：Codex CLI 0.164.0 / `gpt-6-luna` / low，以及私有固定 Kimi CLI 2.1.1 / `kimi-code/k3-256k` / low。没有用全局已更新的 Kimi 冒充审计过的版本，也没有将本批外推为 K2.8、OpenCode、Claude、Pi 或 AGY 的结果。AGY 自动记忆禁用尚未证明；OpenCode 的 `run` 准入不能直接证明 Herdr 交互 TUI 隔离。

原有 invoice 12 项累积需求、相同起始文件与外部 40 项检查。完整路径是双方讨论设计、A 实现、B 读取实际文件并执行独立检查、修复并复审阻塞项、A 交付；没有把该流程写入产品调度。顺序固定为 Loom/Herdr、Herdr/Loom、Loom/Herdr，各组新团队、各成员保持一条连续原生 session。Codex 自动记忆显式关闭，Kimi 按固定版本源码审计；两臂均禁止原生子代理。质量规则在首个团队完成前冻结，负责人非盲审实际交接和原生工具记录；不宣称盲审。

## 三类不同问题

1. **运行时退出兼容缺陷**：第二组 Loom 的 Kimi 已正常 `end_turn`，但未在 EOF 后 15 秒内真正退出；Host 正确拒绝发布。Codex 无 Run、无 Activation、无 usage、无原生文件，预热关闭且频道尚无开场，证明未执行为零；原统计把“两个成员均执行”与“计费完整”混淆。仅据此修正离线会计分类，业务仍失败。
2. **模型漏寻址**：第三组 Loom 的新请求是“请 B 独立审查”，没有 `@Team Reviewer-1`。最初设计请求的定向投递和普通 final 自动返回均已成功；新请求无 @ 不会唤醒 B。这不是要求 B 额外 @ 回 A，也不是自动返回故障。保留现有寻址/单跳返回合同，不加入语义猜测、硬编码工作流或额外工具循环来拯救本组。
3. **原生轮询和预算截断**：第三组 Herdr 的 Codex 发起 30 次 `herdr agent read`、5 次 prompt（含重复催促），反复读尚未完成的终端。达到单组输入观察上限时 Kimi 仍在审查；A 已提前声称“未发现问题”，但 B 没有明确接受。原生模型本身也可能产生大量额外调用。预算按观察点执行，本次已计输入超出单组阈值 8,271；取消在途还可能有未返回账单。后续测试必须把预算截断视为删失样本，不能把缺失计费当业务缺陷或完整成本。

## 免费定位与最小修复

付费六臂全部结束后，才修改产品。9 次免费探针均只 initialize / session/new，部分加 session/close；**无 session/prompt、无模型调用**。原始固定包 EOF 正常退出观测 6.115–14.004 秒；显式 session/close 约 87–89 毫秒后，应用退出仍需 10.246–13.204 秒，不能解决应用级清理。

另外两次仅通过 Node load hook 在同一固定 bundle 的 ACP 清理闭包插入计时；原文件哈希不变。其中一次无 MCP、无模型，19 秒左右才干净退出：EOF 至 exit/close 均 18,936 毫秒，`appendLogStore.drainRetirements()` 占 18,900 毫秒，其他已记录步骤只占数十毫秒。官方本机源码中该操作等待被释放日志的持久写入；并非 stdout 被后代占住（exit/close 同时），也非模型仍在思考。原付费失败未插桩，不能断言所有 EOF 超时都只有此原因。

`kimi-eof-drain.mjs` 将有界等待 **15 秒改为 30 秒**。没有添加 session/close、修改原生包或扩大工具协议；仍要求真实干净退出、完整工具终态和投递/取消围栏。超过 30 秒即使 TERM 后退出 0 也不得发布成功。这是经过复现的兼容窗口修正，不保证所有磁盘/原生关闭都必在 30 秒完成，也不是新的付费协作通过。探针、源码位置和哈希见 [eof-probes.json](eof-probes.json)，阶段计时见 [native-cleanup-timing.txt](native-cleanup-timing.txt)。
