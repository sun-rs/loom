# 免费工具前置与四运行时协作续验

Owner 在剩余事项「免费预检 → 协作闭环 → 同质量成本对照」后要求开始。本批沿用四个指定模型、low 档、三组固定组合、隔离工作区和原 invoice 评估器；不替换上一批失败记录。详见 [计划](plan.json)、[结果](summary.json)。

## 已落地的测试入口

`scripts/cli-efficiency/codex-tool-preflight.mjs` 在本机启动无凭据的假 Responses 服务，用确切安装的 Codex 和原生工具读取随机文件。随机内容只在文件中，必须出现在对应 call_id 的实际工具返回；进程退出 0、模型 final、版本号和模型目录都不能替代它。支持新版数组形式 tool output。

- `gate-daemon.mjs` 在准备 Codex 付费 daemon 前执行检查：warm 走既有模型守卫和 Unix WebSocket；exec adapter 选择 exec 检查。
- `native.mjs` 在原生付费轮开始前执行 exec 检查。进程内成功收据按 CLI/host 字节哈希、模型、effort 和 transport 缓存；失败不缓存。没有跨批次静默复用旧证明。
- 假模型只绑定 localhost；独立 HOME/CODEX_HOME、无账号凭据、不向真实 provider 发送请求。自动记忆关闭。检查的是原生工具健康，不是生产全量账号/配置或付费模型质量。
- 关闭时先关 WebSocket、再停止拥有的进程；清理超时阻止通过，限定进程组兜底终止，不杀其他会话。
- 两个入口的阻断测试证明预检失败后没有启动付费路径。相关 15 项检查通过；真实 warm 和 exec 免费工具检查都成功，见 [收据](free-preflight.json)。

上次诊断更正：重新检查最后一次守卫探针原流，thread/start、真实读文件、turn/completed **已经成功**；最终关闭等待超时遮蔽了成功状态。不是新的守卫启动故障。此前首个探针的 modelProvider 参数拒绝、错误的 JSONL/Unix 握手及数组输出判定仍是测试器错误，保留历史记录。本轮 exec 探针最初未关闭 stdin 导致超时，已改为立即送 EOF 后免费验证成功，没有付费消耗。

`successfulBriefing` 将常驻成功 Run 的 null exitCode 与无 error、Activation 已完成一起判断；失败和在途仍拒绝。协作私有执行器复用该函数，避免再因“常驻进程没有退出码”挂起。

## 真实业务结果

| 组合                                      | 结果                                                                                                                                           | 观察输入 / 输出 / 生成  |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------- |
| Codex GPT-6-Luna ＋ Kimi K2.8             | 实现、独立读取代码与测试、额外 API/CLI 检查、最终交付完成；外部 40/40。Kimi 使用固定 /tmp 临时文件，违反严格仅工作区指示，不能称全指令遵循通过 | 462,046 / 9,470 / 21    |
| Codex ＋ OpenCode DeepSeek 4.1 Flash 1017 | 预算触发停止；代码外部 40/40，但未完成交付闭环                                                                                                 | 2,085,971 / 32,713 / 66 |
| Codex ＋ AGY Gemini 3.8 Flash             | 准备恢复后停在设计讨论，无实现、无评审闭环；外部 0/40                                                                                          | 266,392 / 2,660 / 16    |

三组有运行时间重叠，只作功能观察，不作无负载时延对比。全部观察输入 2,814,409、输出 44,843、103 生成，包含失败。每组预算在观察点检查，停止时在途工作使第二组超过 180 万输入观察阈值；不冒称硬限额无超支。中止请求最终计费覆盖未证明；OpenCode/AGY 当前为产品逐响应账，没有独立原流对账。AGY 自动记忆隔离仍未知；没有原生对照，不发布倍率。

第二组 Codex 原生记录有 47 个工具调用，其中 17 个涉及 patch、16 个涉及测试、6 个涉及 Worker（分类重叠）。整数定标方案下金额公式反复修改，过程中测试多次失败再修复，是可见的主要工作量来源。它不证明模型稳定更差，也不证明 Loom 相比原生增加某个倍数；需同质量多次对照才能下结论。

AGY 第一次目录报告 available=true 但 modelBindings=[]，在任何生成前停止。随后原生目录恢复，保留原频道及 Codex 实例续做准备。旧准备停止已置频道 SOS，明确调用恢复并记录指导消息，导致额外唤醒；因此它是**准备阶段有干预的样本**。其后 Codex 同回合 Worker 发请求和 final 重复 @，AGY 又反向提出请求，形成交叉请求；最后两条 AGY 反馈没有 recipients/replyReturn。不得将此样本伪装成正常单请求返回的失败复现，也不得据此放宽因果/循环围栏。静默不等于任务完成。后继归档因旧目录存在被拒绝，已用新目录独立执行最终评估，旧结果不覆盖。

## 收口判断与下一步

免费工具前置已落地。Kimi 组合证明当前代码可以完成该功能闭环，但本批**不是四家全面通过、统计稳定性通过或成本门禁通过**。所有隔离服务已停止，待处理工作只留在已关闭的测试库中；正式产品数据和运行服务未修改。

下一批必须先完成全部模型目录验证再创建频道/实例，目录不全仅停在准备阶段，不能在创建一半后用 SOS 恢复干扰对话；取消无必要的准备恢复广播。保持语义质量标准，保留自然工具调用与修改次数。先取得 OpenCode/AGY 无准备干预的完整交付，再设计重复原生/Herdr 对照；不基于单个高消耗样本重写后端，也不自动付费补跑。

后续准备入口已修正：`collaboration-preflight.mjs` 先一次性验证所有精确模型/effort，再允许私有协作执行器创建频道与实例。缺失 AGY 目录、错误模型和错误 effort 的拒绝测试通过。已执行版本保存为 `run-executed.mjs`，后续修改不覆盖原实验脚本。
