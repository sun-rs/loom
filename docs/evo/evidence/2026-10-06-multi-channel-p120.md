## 模型波动与验证设计的限制

本次和 P119 都发生相同目标参数误用，但恢复路径不同：上次省略 threadId 后继续 MCP，本次选择 CLI。两批不是同一冻结 profile 的预注册重复研究，样本也极少，不能估计稳定性或错误概率。可确认的是当前工具接口确实允许产生这种误用，随机性不能成为忽略其费用的理由。

这次还暴露验证器的剩余限制：它测的是“仅 MCP 的恢复轨迹”，而用户最终关心业务正确送达后的真实长期成本。免费合成模型能证明预设路径被正确观察，却不能保证真实模型不选择另一条可用路径。因此先前免费验收不能替代真实路径覆盖。

后续应暂停同型付费长测，先免费处理两项边界：当前目标回复接口由可信执行上下文绑定，避免频道名和 Thread ID 混淆；业务正确性/权限/唯一发表/ACK/完整计费作为验收依据，MCP 与 CLI 路径选择作为单独诊断。在 CLI 回退有明确证据支持前不直接扩大白名单，也不通过注入标准调用消除模型波动。若还需限定某个传输路径，应明确那是传输实验，而非整个产品的长期业务效率实验。

需要新付费时应先以单独授权的小规模冒烟确认真实入口，再启动完整长期配对；不再反复先花费 36 阶段原生费用，随后因未覆盖的工具选择而首轮终止。任何新方案均先冻结，旧结果保留。
