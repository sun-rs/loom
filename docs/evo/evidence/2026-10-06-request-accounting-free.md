| CLI 自动加入的 Shared MCP Types |                1573 |                1671 |
| CLI 自动加入的三个资源工具说明  |                1681 |                1720 |
| `loom_reply` 定义               |                 697 |                 711 |

因此，把 `loom_reply` 本身写得更短，不能假定另外 3391 字节也会消失。此结论仅适用于本次安装与配置，不能推断其他 CLI 或其他版本的行为。

此外，产品 runtime policy 那个 developer input 项比原生多 6479 JSON 字节；工作目录/环境上下文多 27 字节。两臂基础说明、团队说明、委派规则逐项等长且工具目录比较已排除其他差异。

这些 input 项在每条 session 内保持相同：模型请求仍携带它们，不表示每轮在 session 中新插入了一份。固定额外 input 为 10608 字节/请求。缓存命中、tokenizer 和费用未测，不能把重复传输解释成全部未缓存计费。

## 工程裁决

1. **不是材料每轮重新投递，也不是说明在 session 内无限复制。** 本探针中材料只在每人首次新 wake 出现；正常历史随后被原样带入请求。重复传输历史是原生 CLI 也有的行为，差别在 Loom 每轮多留下了协议内容。
2. **继续缩短 `loom_reply` 描述不足以解决固定成本。** 大部分 MCP 增量由 CLI 通用说明产生；直接改原生历史、屏蔽回执或删除可信投递信息不在本轮修复范围。
3. **最有价值的 Loom 自有候选是常驻协议说明的路径化审查。** 6479 字节的固定增量需要逐段区分身份/安全、业务用法和与 MCP 重复的 CLI 操作引导；只有后者可考虑按实际运输路径减少。这需要同一 owner 的协议版本与恢复路径测试，不能再叠加一套提示、按场景特化或删除 CLI fallback。当前尚未证明有多少可安全去掉，也未实施。
4. **历史增长另有约束，不能用固定说明缩短来宣称解决。** 回执身份、引用、去重与错误恢复信息继续保留；原生 final 控制引出的中断提示不能靠删 transcript 消除。若后续要改变 final 边界，必须同时证明完整工具结果、真实 ACK、无额外续生成与取消安全；此前的成功发送不能替代这些证据。

免费捕获回答了“多出来的请求内容在哪里”，没有回答“删减后模型是否同样可靠、账单能省多少”。[P122](2026-10-06-business-long-p122.md) 的质量失败及效率未验收保持；不增加付费样本、不更新其分母。下一次实现应先限定可删除语义、TDD 和免费实际 CLI 验证，再单独授权真实同质量长链验收。正式服务没有重启或变更。
