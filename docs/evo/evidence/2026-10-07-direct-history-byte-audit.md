# Direct MCP 的重复历史封装字节审计

结论：不只是首轮工具目录更小。实际 code-mode 与 direct 输出已经证明，普通 compact published 回执的历史表示减少一层 MCP JSON 字符串嵌套；这会随旧回执进入以后请求而重复节省字节。仅此项可做同内容精确反事实，不需要假设模型答案更短或生成更少。

## 同内容核算

使用此前 compact-receipt-free 实际 3 个续轮请求中的输出，固定内层回执所有值、call/item 标识和 wall-time 数字，仅替换为已观察的 direct 输出表示：每条输出从 417 B 变为 308 B，减少 **109 B**。其中去掉 `{content:[{type:text,text:...}],isError:false}` 的二次字符串编码减少 **87 B**；输出类型和展示头替换减少 **22 B**。

对本次 production-free 实际 direct 的 3 个输出反向重建也得到相同差额：实际 310 B，按相同数字计时及相同标识恢复 code-mode 外壳为 419 B，仍相差 109 B。两个探针实际长度不同来自计时字符串及不等长 opaque ID，不能直接把 417−310 当成严格同内容效果；109 是保留这些量的规范化结构差。

## 长任务历史中的重复份数

复用此前 72 请求中的 36 个产品请求，固定已有请求/历史调度。共有 **198 次历史工具输出重放**（3 个 session × (0+1+…+11)）。旧完整回执 code-mode 输出总计 137,620 B；此前已分析的 compact receipt 改造后投影为 82,774 B（减少 54,846 B）。在这个 compact 基础上，direct 封装继续投影至 **61,192 B**，新增减少 **21,582 B = 198 × 109**，其中 17,226 B 来自去掉嵌套、4,356 B 来自类型/展示头。

这是两个先后独立变化，不能把 54,846 B 也记成 direct exposure 的收益。按同样每 session 每轮一份历史结果的假设，第 12 轮单次请求已有 11 份旧回执，因此仅这部分少 1,199 B；不是每次请求恒定只少 109 B。旧 752,048 B 产品−原生 input 差账上的 21,582 B 约为 2.87%，这只是固定旧轨迹的表示投影，不是重跑后的总差。

## 不可扩大解释的边界

- 字节均为 compact JSON 的 UTF-8 字节，不是 token、价格或缓存收益。
- 输出投影保持业务回执不变，不删除 ledger、ACK、seq、消息内容或原生历史。真实 future ID、计时、模型行为及请求份数可能不同。
- 工具调用本身的模型生成代码还可能变短，但不同样本参数/正文不同；本报告不据此算输出 token 效果，也未将调用代码计入 21,582 B。
- 工具目录另为每次请求固定上下文。本次实测每请求目录 20,257 B 且无 Shared MCP Types；未将工具目录差与上述历史结果差混算。
- standing instructions、wake、原生中断通知和业务历史仍在。实际冷恢复仍 2 HTTP，不能声称 direct 后无需任何后续生成。
- 这是纯离线分析，无新增 CLI/provider 请求；源捕获、源码和旧审计均未修改。可用 analyze.py 重算，manifest.private.json 记录输入 SHA。
