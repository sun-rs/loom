# P121 输入开销：固定上下文与续轮历史

本报告只读复核 P121 已归档的六份原生 rollout 和结果，未调用模型、未修改提示或历史裁决。[逐项文本计量 JSON](2026-10-06-p121-input-analysis.json)包含原始文件哈希、报告 token 和精确文本长度。长度单位为 Unicode codepoint 与 UTF-8 字节，不做字符到 token 的估算。

## 关键结论

**“首次固定开销”是测量位置，不表示平台上下文整个 session 只计一次。** 同 session 的后续生成仍以已有上下文为输入；常驻说明和历史可能命中缓存，但缓存输入仍包含在总输入中，不能等同于新增文字或未缓存费用。

P121 两臂每阶段均仅有一条已报告生成，没有额外生成次数。A 原生续轮的新消息文本只有 1,270 字节，报告输入仍为 13,395 token；产品新 wake 为 1,809 字节，报告输入为 16,930 token。这与继续使用已有上下文相符，不能把输入量理解成此次新增消息的 token 数。归档没有完整出站 provider 请求，因此不声称已精确还原每一项常驻说明、工具 schema 或历史序列的 token 占用。

| 实例 | 首次输入差，token | 续轮输入差，token | 两臂上下文增长之差，token |
| ---- | ----------------: | ----------------: | ------------------------: |
| A    |             3,030 |             3,535 |                       505 |
| B    |             2,836 |             3,338 |                       502 |
| C    |             2,642 |             3,140 |                       498 |

例如 A 两轮输入差累计为 6,565，而非仅 3,030 或 505。增长差是报告用量的差分，不能直接命名为某一段协议文本的成本。合同原裁决不变：A 首次固定开销失败；累计较低倍率不能抵消它。

## 首次可见组成

三组配对均观察到：

- 原生基础指令逐字相同：18,037 字符 / 18,043 字节。共同多代理 developer 两段也相同，不能归为产品独有开销。
- 产品比原生多一个常驻平台前缀：6,448 字符 / 6,462 字节。包括身份、运行上下文、优先级、Worker 操作、沟通、Role、通知及空记忆索引说明。其中 Worker CLI 区域 2,728 字节、Message Notifications 区域 1,428 字节；这些分区没有被换算成 token。
- AGENTS 与环境块产品多 27 字节，来自工作目录路径长度；业务指令不是再注入一整份。
- A/B/C 首次 wake 分别含四、二、零行成员/实例创建事实，合计 1,310 / 655 / 0 字节。这是实际投递的平台元数据；不是三人的同一输入条件。
- B/C 首次已收到此前真实同伴答案。两臂都按本臂历史投递，不能据此宣称三份独立理解，或把所有首次差异当作纯平台因果开销。

完整源码材料每 session 首次呈现一次，续轮不重发；材料保留在正常会话历史，与“每轮重新插入材料”是不同现象。

## 续轮可见组成

三个实例的新 wake 相对原生中继均多 653 字符 / 539 字节。可见差异包括真实频道名、Room sequence、短消息引用、真实实例 handle、mentions 行、catch-up/当前消息分区，以及当前 Reply context 与 MCP 提示。续轮每人的 Reply context/MCP 两行共 216 字节，mentions 三行共 138 字节。两臂包装方式和文字语言不同，因此总字符差与字节差不同。

在第一轮结束后、第二轮开始前，归档还保留以下不同历史：

| 文本项                                     |  原生 A/B/C |       产品 A |     产品 B/C |
| ------------------------------------------ | ----------: | -----------: | -----------: |
| 模型正文或工具代码，字节                   | 答案正文 38 | MCP 代码 137 | MCP 代码 140 |
| 实际工具输出文本，字节                     |           0 |          446 |          446 |
| CLI 的 `turn_aborted` developer 提示，字节 |           0 |          221 |          221 |

产品上述历史相对原生多 766 / 769 / 769 字节。工具输出计的是归档解码后的文本块之和，包含回执及执行完成标题，不是原始 HTTP JSON 序列化大小。中断提示由原生 CLI 留存，不能直接当作 Loom 重复发出的消息。

这些是增长差 505/502/498 附近**可观察到的组成变化**，不是其精确 token 分账。未留存完整 provider 工具定义、序列化边界及缓存决策，不能把字节相加后宣称已经解释全部 token。

## 重复项与最小建议

存在少量明确重复，但没有证据支持删除整个安全协议：

1. `Tool access: full_access` 在同一常驻 prompt 出现两次，分别由 [runtime context](../../../packages/daemon/src/standing-prompt-compiler.ts#L106) 与 [workspace policy](../../../packages/daemon/src/standing-prompt-compiler.ts#L153) 生成。可研究保留一个权威位置；不能删去实际权限或身份围栏。
2. memory help 指针出现两次；当前索引为空。可合并导航文案，不能因此删除记忆开关、隔离、显式写入规则或伪称记忆不可见。
3. CLI 发帖模板与通知区的 `message-post` 要求来自[同一 standing protocol](../../../packages/agent-host/src/standing-protocol.ts#L60)，本轮 wake 又指定 [MCP 回复](../../../packages/agent-host/src/worker-mcp-guidance.js#L6)。可考虑在单一位置描述当前回复入口及 CLI 恢复路径；本批没有据此证明提示冲突或量化节省。必须保留当前目标、seq/turn、final、held 与 unknown-write 边界。
4. [Role 区域](../../../packages/daemon/src/standing-prompt-compiler.ts#L174) 的 `This may evolve.` 对冻结 Role Revision 含义含糊，宜单独核对并精简，而不是暗示实例会随 Role 编辑自动变化。

成员/实例元数据与 ACK/presented-window 有关，不能直接从文本删除后仍声称完整呈现。MCP 回执、当前因果参数、错误恢复信息也不是无效内容。原生中断提示属于 CLI 行为，本报告不建议修改 CLI 或为了省历史而牺牲完整工具输出。

## 缓存与结论边界

两臂总输入为原生 79,932、产品 98,453；未缓存输入为 41,020、60,309。续轮产品 C 缓存为零，原生 C 缓存为 13,056，这是已观察事实，不足以推断缓存机制或提示压缩效果。输入倍率不是账单倍率。

本样本说明：即便没有额外生成，常驻平台说明及交付历史仍能增加每次生成的上下文输入。它不证明这些差异全部不可消除，也不证明删提示就必然减少一轮生成。只有两轮、单一配对，不能判断长期摊销或稳定收益。后续若精简，应固定业务材料与安全边界，先比较相同输入的编译文本及免费链路，再由独立批次验证实际用量；本报告没有执行该优化或新付费验收。

后续免费小修仅移除了 workspace-policy 中重复的 Tool access 行，保留 Current Runtime Context 中的实际值；完整 prompt 的单次出现和值保留已通过回归测试。上文所有长度仍描述 P121 原始归档，不随修复重算。此修复尚无新的付费用量效果验证，不能从删除字节推导 token 或账单节省。
