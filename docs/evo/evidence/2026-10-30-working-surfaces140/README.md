# 工作状态、计算机概览与页面底色接线（Web1.21.40）

本批为 owner 明确指定的五项兼容修复，仍不宣称整版 Web 迁移完成。无后端调度改动、数据库迁移、付费模型调用或正式测试对象。

## 原因与处理

- 成员角标：原 MembersStrip 调用未提供 badge，成员行生成器还将 badge 固定为 undefined。现通过已有 `agent.presence.list` 的 definition ID 和 catalog 的成员 principal ID 关联，交给原生 AvatarBadge。思考／工作为黄，在线为绿，离线为灰，异常保留原生 error 色；读取失败清除诊断状态，不把启用成员视为工作中。成员行文字同时采用该观测，避免绿色／黄色角标旁仍写旧的“空闲”。
- 工作动态：旧接线只读取选中频道，并进入旧底部横幅。现从工作区既有观测投影全部实例，使用完整归档的原生顶栏弹窗、最多三个叠放头像及频道标题摘要；跨页不丢失，点击使用 catalog 已验证的 `instanceChannelId` 返回所属频道并打开实例。无需额外轮询 Role 修订或完整历史。工作结束／观测失败移除计数；成员过滤不串频道，空摘要不留空行。旧底部横幅停用。
- 计算机：新增官方“概览”入口，桌面首次进入选中概览；明确计算机选择仍保留。原生列表／卡片、统计、实例头像条、详情跳转及设备端视图偏好接入本机已验证 inventory。没有磁盘、内存或账户额度观测，保留未知，不伪造数值；云注册、迁移和远程控制未引入。
- 记忆：卡片容器误用 `bg-layer-canvas-muted`，已改为 `bg-layer-canvas`。浅色主题实际计算值为 `oklch(1 0 0)`；真正的窄侧栏继续使用奶油底色，不全局改主题。
- 蓝色提示：官方 `_nt` 使用 freshness 的“已确认但 stale/unavailable”条件，文案为未读数可能不是最新，并非每次刷新都出现的加载横幅。现复用原生 info PanelNotice，绑定实际列表／未读读取失败；成功恢复即移除。正常首次加载仍使用既有全页加载层。
