# 手机 Tailnet 首次切页优化

2026-10-28，源码基线 `55fd64e5`。用户确认慢发生在手机浏览器经 Tailnet 访问；此前本机 Firefox／HTTP 的快速结果不能代表这个场景。

## 已确认的等待与处理

此前页面模块在点击后才开始下载，模块就绪后才挂载并读取数据，首次进入要串行承担代码和 API 的网络往返。本批用相同持久数据、同一个 PID 41326 Core、390×844 浏览器与每次资源/API 响应人为增加 200ms 的代理确认该等待。真实手机 Tailnet 的五次节点探测为 30/218/33/39ms 与一次超时；这是单次节点连通性样本，不证明浏览器吞吐、持续丢包或唯一根因，未修改网络配置。

优化只在 Loom 的模块加载生命周期：

- 手机／宽屏触控设备的页面就绪后，在空闲时预热动态、任务两个模块；搜索与动态复用一个模块。
- 打开“更多”时逐个预热其四个入口；关闭菜单取消剩余队列，已开始的原生 import 不强行取消。指针／焦点只预热目标模块，宽屏触控导航保留官方拖动事件。
- 共享同一个成功模块／在途 Promise；不预挂载页面、不提前查询或缓存业务数据。失败 Promise 释放，后续明确导航可再次尝试；实际导航仍由既有错误／更新提示负责，不自动循环重试或刷新。
- 后台、省流量、2g 与宽屏鼠标桌面不做推测加载。使用既有 `compactDensity`，避免漏掉展开的折叠屏。官方组件、字体、尺寸、布局和路由／草稿围栏不变。

## 最终三对受控测量

[完整口径与区间](comparison.json)、[全部迭代的测量摘要](measurement-digest.jsonl)。每臂三次完整七页旅程，最终版本交替运行；每次首页可见后统一等待探针的 400ms 采样点。以下是点击到页面容器可见、再过两帧的中位数，**不是全部数据就绪或 INP**。

| 页面       | 修改前 ms | 修改后 ms |
| ---------- | --------: | --------: |
| 动态       |     247.4 |      22.0 |
| 任务       |     244.0 |      21.2 |
| Role／成员 |     269.2 |     102.3 |
| 计算机     |     237.5 |      93.2 |
| 设置列表   |     253.1 |      45.1 |
| 记忆       |     236.5 |      40.9 |

任务空态数据就绪中位数为 **472.3→250.4ms**，Role 列表为 **522.1→342.2ms**；网络读取仍存在。记忆为空频道场景，保留原有 200ms 查询延迟，不能外推大历史。搜索因同一旅程已加载动态模块，原本就快，不宣称所有目的地等幅改善。

不是手机硬件或真实 Tailnet 浏览器测量：没有限带宽、CPU 降速或模拟丢包；数据是当前空频道、无活动 Role、保留删除修订的真实 Core。预热只移动少量页面代码的获取时机，不保证启动更快、不保证网络停顿消失，也不声称大历史性能已通过。

## 过程问题保留

- 初始就绪探针误命中隐藏桌面导航；修正为检查可见匹配项。初始不完整旅程与日志保留。
- “更多”四模块并发曾争用请求连接，改为可取消串行预热，原结果仍保留。
- 动态的额外数据就绪探针未可靠识别标题；计算机探针误命中工作区名称。这两个 `usable` 字段双方均不用于结论，页面呈现及真实 DOM 检查另行保留。
- 最终第三对发现旧 pilot origin 的 HTTP 缓存仍生效（脚本传输 0 字节、约 1ms），作为混合缓存观察单列；另用独立冷缓存来源补足第三个冷缓存单元。不是从耗时大小选择样本；摘要保留两组记录及原因。

## 验证和部署

模块预热、取消、保存流量、宽屏触控、失败恢复、原生导航／生成闭包及 UI 契约共 **44 项定向检查通过**，新增不变量先失败复现；[测试](focused-tests.txt)、[类型检查](typecheck.txt)、[构建尾部](build-tail.txt)、[检查范围](checks.json)。无后端全套或付费 CLI 测试。

额外运行的全站 action 审计在未改动的 `AddInstanceDialog.tsx` 失败，断言只接受 `Button` 而当前使用 `DialogCommit`。独立提取原 HEAD 后重现[同一失败](ui-action-baseline.txt)；本批未修改该文件或把此项记为通过。

原始预热版部署后补齐宽屏触控及失败恢复，再备份并部署最终版；[首版部署](deployment-initial.json)与[最终部署](deployment.json)均保留。两次均检查空闲、在线备份及验证，精确优雅重启 `com.loom.evo`，仅更换冻结 Web 目录，业务账本未变。原 Tailnet/LAN HTTPS 和三个 HTTP 入口均保留，两个 TLS 首页经原 CA 校验且匹配新 index。旧快照保留供回退。

部署后实际 Chrome 产品页确认新构建、390×844 首页／任务／更多／Role／返回，以及 1440×900 计算机详情，无控制台错误。Firefox 新页复查遇到 native `cgWindowNotFound`，不冒称已验收；HTTPS 有独立证书校验。本机尺寸模拟不是实体手机。请在手机刷新后确认实际体验。
