# 修复后原生对照：有限重复短任务

本批由 owner「新代码下的 token 消耗相比原生、每个 CLI 都测」授权。
Claude/Pi 当前 Kimi K3.1 Pro/low 路由另经 owner 明确批准。不是旧结论续写，
也不是长任务、多人协作或六家统一验收通过。

## 设计与统计

每个可进入计量的 CLI 计划三个独立样本，每臂三轮同 session，使用相同固定
两文件快照、问题与只读要求。顺序 native/Loom、Loom/native、native/Loom。
按全样本输入总和计算比值，保留单组范围；不以单次最优值或首轮结果替代全程。
每 CLI 观察上限 200 万输入、3 万输出、40 分钟，边界检查不能阻止在途超额。
发生执行/计量失败停止该批，不补齐假比率；测试入口修正后的批次另立记录，
先前失败及发生的费用不删除。

原生自动记忆按现有显式开关/精确版本审计限制；正常历史保留。新建隔离工作区
与频道不证明 OS 级全局文件隔离，平台记忆未被证明完全关闭，任务禁止写记忆。
Pi 两臂统一禁用外部扩展/技能/上下文文件/MCP/模板及缓存保温，保留连续历史，
明确测试现有 native-final 试验路径，不等于正式服务默认 Pi 设置。

输入包含缓存读取；输出包含 provider 报告的 thinking，不能把 reasoning 再加
一次。报告是 token 用量而非实际账单。不把流式修订片段重复计数。三组不是
统计等效证明，简单代码审查也不是复杂长任务的充分样本。自动回答有效性检查
不代替独立质量审计。

  因而不能宣称账单3.611倍。错误指引修复没有根除模型漏传final。

## 测试工具缺陷及留账

- Codex第一次原生3轮52,639输入/822输出，Loom入口被旧保护器拒绝
  `thread/start.serviceTier=default`；保护器现只接受省略或default，仍拒绝priority。
- Kimi第一次print入口在显式-m之前要求全局默认模型；使用复制的私有测试home设定
  同一个批准模型，未改用户配置，doctor通过。没有将启动失败当作模型质量问题。
- Claude首批拒绝产品`--settings {fastMode:false}`；修正只放行该对象。
  随后一批中模型路由批准信息被产品子进程环境清理丢失，错误拒绝Kimi响应；
  现将批准路由冻结在生成的guard配置中，免费真实子进程验证通过。该批真实响应费用
  从原生transcript恢复，不能记为未调用或零费用。
- OpenCode精确版本自动记忆审计更新见本目录opencode-memory-audit.md。

上述均是测试工具维护，不是为改善样本倍率修改产品。正式服务未重启或改变配置。
