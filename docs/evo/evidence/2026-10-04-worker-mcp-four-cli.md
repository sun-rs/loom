# 内部 Worker MCP：四家 CLI 免费协议验证

日期：2026-10-04。被测产品基线：`96e562b0af73bd9e4c8393d11b080b00f8872608`。
范围：owner 要求“试试构造 mcp，然后四家验证”。构造一个可丢弃的内部回复工具，安装版 CLI 连接本机确定性假模型。真实模型调用为零，未接真实 Worker／Kernel，未改产品、全局配置、账号、安装或正式服务。

## 结论

**同一个 stdio MCP 回复工具已被四家安装版 CLI 实际调用并收到结果。** 这支持采用统一的内部 Worker 工具契约，不需要让模型学习四套 shell 命令。尚不能宣布真实模型一次调用成功、产品接线完成或成本下降；P97 的效率失败结论保持。

## 最小接口与验证方式

所有 CLI 共用 `worker-mcp.mjs`，只暴露 `loom_reply(body, final)`。参数严格拒绝 actor、token、turn 等额外身份字段。实验绑定从 MCP 子进程启动环境读取后固定，不查询“最新 Run”；返回明确标识的 `FAKE_MCP_RECEIPT`，不产生业务写入。JSON-RPC ID 重放缓存仅限本 stdio 进程，**不是 Worker 的持久业务幂等**。

先写失败测试，再实现最小服务；6项测试通过，覆盖参数拒绝、重复／冲突请求、ID 类型区分、两个独立进程不串绑定和可选身份日志白名单。身份日志默认不记录值，实验 opt-in 只记录自身的关联 ID。

验证按本轮 tool-call ID、正文和绑定核对结果，不把恢复后的旧历史回执当成本轮成功。Codex／Claude 还逐项核对唯一 receipt ID；Kimi 的 CLI 工具输出与服务日志核对同一个 receipt ID。OpenCode 按本轮 call ID、正文、固定连接绑定验证下一请求的工具结果；其请求摘要未保存 receipt ID，不声称同等程度的 UUID 核对。

Codex 使用前次研究已验证、与 Homebrew 同版本同哈希的现有安装副本独立运行，没有连接用户现有 daemon 或 session。Codex／Claude 使用已验证的官方自动记忆关闭开关；Kimi／OpenCode 仅在子进程使用临时 HOME／XDG／KIMI_CODE_HOME 隔离配置，**不等于已证明官方自动记忆关闭**。因此本次不是四家原生成本对照。假模型的 token 字段是夹具数据，不进入用量比较。

## 失败及关键限制

- Codex 前3次夹具设置尝试未调用工具：MCP 已就绪，但工具属于延迟暴露，静态模型请求里没有具体回复工具定义。最终夹具根据 MCP 清单注入已知工具名后，代码模式调用通过。这证明执行链可用，**没有证明真实模型能够无需查找就发现并使用工具**。产品必须验证精简工具说明／暴露方式，不能把夹具知道名字当作真实模型能力。
- Kimi 最初命令使用不兼容的 `--prompt`／`--yolo` 组合，启动即失败，没有模型请求；纠正探针启动参数后通过。不能隐去这次设置错误，但它也不是模型工具调用失败。
- OpenCode 前3次隔离 `run` 启动停在 bootstrap/init，各35秒有界超时，零模型请求、零 MCP 调用。禁用默认插件、复用实验目录已存在依赖均未解决。第4次改用产品实际 `serve --pure` 路径后通过。尚未证明 `run` 卡住的根因，不能归因于 MCP 不兼容。
- MCP 初始化、列工具是客户端协议操作，不要求模型生成；工具说明仍可能进入后续模型请求。没有测得其 token 成本，tools/list 次数也未记录。
- Codex 暖进程的两轮仍使用同一假环境绑定。原生 turn 元数据提供了构建 Host 映射的依据，但本次没有实现或验证真实凭据签发／撤销、旧轮迟到拒绝、generation 围栏、未知结果或持久幂等。
- OpenCode 的 MCP 请求未观察到可关联到原 Run 的原生身份。不能用“当前 active Run”、请求到达时间或参数正文匹配替代身份。尚需验证可信调用关联或 CLI 的薄适配；不能为迁就接口擅自把 Codex／OpenCode 改为每轮冷启动，目标合同 §6a 仍有效。
- 四家都没有覆盖真实业务的 held 上下文交付、ACK、final 中断完整性和任务完成；没有自动发布 provider stdout，也没有部署任何新产品能力。

## 实施判断

统一 MCP 工具契约值得继续；Skill／长 prompt 不应再承担命令拼装、凭据复制或完成手续。业务与权限仍由现有 Worker 应用服务／Kernel 单独拥有，Host 只负责可信执行身份和工具生命周期，不恢复第三方 MCP 管理。

下一产品切片必须同时完成：直接可发现的短工具定义、原 Run 固定授权及迟到拒绝、复用真实 Worker 的一次显式发布、完整返回后的可靠 final 结束。不同 CLI 允许很薄的身份适配，共用业务语义；OpenCode 的关联缺口必须先解决，不能用宽权限连接掩盖。通过免费业务链测试后，再准备独立授权的同题付费对照；本次不构成新付费批次授权。

MCP 协议存在版本差异；本次只按已安装客户端实际初始化协商验证，不宣称最新规范全兼容。[2026-07-28 官方变更说明](https://blog.modelcontextprotocol.io/posts/2026-07-28/)已移除新版本 initialize 交换，不能混用新规范结论与本次旧版客户端行为。
