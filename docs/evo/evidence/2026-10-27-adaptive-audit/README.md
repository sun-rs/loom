# 平板／折叠屏布局根因核查（2026-10-27）

本批是研究和正式页面只读尺寸对照，未修改产品或宣称修复完成。

## 已证实根因

Loom `mobile.css` 的紧凑规则整体限制在 max-width:767px；Navigation 使用 md
切换侧栏／底栏，多个页面的 matchMedia 同样使用768px。
`mobile-message-default.ts` 仅在首次读取、没有用户显式偏好且宽度小于768时选择sm，
不是持续适配窗口变化。`TasksPage.tsx` 在无显式taskView时根据同一断点切换列表／看板。
因此展开设备会同时改变导航、布局及控件密度，而不是只增加正文空间。

正式Chrome窗口对照（非真机）：390×844时任务为列表，首卡宽343、高174.5、
标题14/20；820×1180时为看板，首卡宽232、高202.5、标题14/22。
顶层额外出现桌面搜索栏和左导航。不能将结果简化为“所有文字放大”：
本样本标题字号未变，窄列、行高和外围布局共同造成信息密度下降。
见 [measurements.json](measurements.json)、[手机](phone-before.png)、[平板](tablet-before.png)。

## 官方原生策略

参考 botiverse/mobile `eff04722`，已比对候选 `720cd7fc` 的有关变更。

- RaftAdaptivePane.kt：宽度先按density换算dp，840dp开始DualPane；折叠姿态不单独强制手机布局。
- RaftAppShell.kt：大屏桌面模式默认开启时，DualPane切到左导航；因此官方平板也不保证始终底栏。
- core/.../AdaptiveListPaneWidth.kt：频道/成员侧栏默认240、范围200–400；动态/搜索列表默认380、范围240–640；详情至少360。
- data/AdaptiveSideThread.kt：第三栏需窗口>=1200dp，并且实际详情区域至少440+1+400=841dp；不足则在当前详情替换、可返回。
- 原生排版不是随窗口加宽整体缩放；文字偏好、导航形态、分栏资格分别管理。

## 建议实施合同（尚未实施）

1. 将交互形态、内容密度、单/双/三栏资格分开；浏览器使用CSS逻辑像素，不能照抄物理像素。
2. 触屏小于840逻辑像素保留手机导航及单栏；840以上允许原生式双栏，仍保留紧凑控件。
3. 桌面鼠标环境保留官方Web规则；不能把所有md断点全局替换成更大的数字。
4. 列表宽度使用官方范围并先保障正文最小宽度；第三栏取决于实际剩余空间。
5. 窄中屏任务默认列表，用户显式选择看板优先；字号不因展开/收起跳档，尊重显式偏好。
6. 同时覆盖390、767/768、839/840、820、1024、1199/1200、1440及展开/收起连续变化；
   检查草稿、选中对话、返回栈、滚动锚点和输入焦点。触屏带键盘/鼠标设备不能只靠pointer猜型号。

当前仅确认任务页布局密度回退，未量化同一聊天正文的可见字符数，也没有物理折叠屏验收。
具体设备识别/导航偏好须在实施时统一到一个前端布局策略，不新增后台业务状态。

## 依赖边界补齐（2026-10-27）

引入同一固定 revision 的六份官方原件：RaftAdaptivePane、RaftAdaptiveListDetailSplit、
RaftAppShell、AdaptiveSideThread、LocalPreferences、AdaptiveListPaneWidth。
均由 git show 提取、原始 SHA256 锁定，未改官方文件。
`audit-mobile-source.mjs` 现在除字节差异外，还提取并比较九组布局规则；
无法识别源码格式或缺文件时退出2，不沿用旧值。未变的数值不代表其他函数行为未变，
完整源码diff仍要看。Loom消费者及待完成状态单独记录在 native-adaptive-bindings.json。

4项定向测试通过：固定合同、修改官方源码数值的差异检测、不识别格式失败、
20份原件摘要及绑定路径。实际独立checkout对比：20文件无本地漂移、候选干净、
语义无变化，见 [source-intake.json](source-intake.json)。AGENTS.md加入中间宽度和
连续缩放的验收边界。本批未修改运行时布局；平板适配尚未实施，不重启服务或跑产品构建。
