# Agent 资料页吸收建议与剩余边界（2026-10-20）

本次在 `milestone-evo-message-identity-2026-10-20` 推送后整理。它是下一批设计建议，不表示下述模块已经施工。源码锚点仍为锁定的官方 v1.21.22（`af3d6ef4a22f0f05f5f9db9424285755d67e9726`），不是本轮重新访问官网登录态后的最新版本声明。

## 官方实际结构

[AgentDetailPanel](../../frontends/raft/packages/web/src/components/agent/AgentDetailPanel.tsx) 的组合链为 ProfilePanelBody → 顶部控制 → SortableTabsList → Profile 内容。资料区有头像/名称/状态、AgentProfileInfo、Skills 和动作区。InfoRow（约594行）统一标签/内容列及字体；AgentHeaderName（约633行）使用 PanelTitle 与编辑入口；资料正文从约3100行开始。名称显示 `displayName || name`，身份和导航继续使用 ID。

官方另有动态、聊天、提醒、工作区、应用与 MCP 标签。它们不是七个可以直接接入 Loom 的空壳：各自依赖官方 store、权限、API和固定 Agent 生命周期。`AgentProfileEditDialog`、`AgentSkills`、`AgentWorkspace`、`AgentActivityLog` 可作为局部复用来源；不能整体挂上官方 store 再把 ID 换成 Role ID。

## 建议吸收顺序

| 顺序 | 官方部分                                     | Loom 对接                                                                                                        | 边界                                                                                                           |
| ---- | -------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 1    | Profile 的头像/名称、InfoRow、编辑交互       | Role 详情默认展示名称、角色 Prompt、CLI、模型、强度；编辑仍交给现有 RoleEditor/ManagementClient，保存新 Revision | 复用官方布局与控件，别再新设计一套表单；不复制官方运行时写操作；Role 无真实在线状态                            |
| 2    | Profile 的状态、Computer、运行配置与创建信息 | 实例资料展示当前冻结配置、原生覆盖、所属频道、执行主机、修订是否落后；沿用现有实例控制                           | 所属主机与在线状态来自真实观察，未知显示未知；采用新 Role 配置仍通过显式重启；不因为编辑 Role 改正在运行的实例 |
| 3    | 动态/工作区/聊天入口                         | 复用当前 RunAttempt/用量/工具轨迹、已授权文件树、独立单聊和频道私密入口                                          | 整合入口，不另建日志或文件授权所有者；Role 级聚合必须带实例与频道来源；跨频道不能共用一个 session              |
| 后续 | Skills 展示行与来源分组                      | 仅接已有可验证的发现/配置能力                                                                                    | 官方磁盘发现列表不等同 Loom 的生效能力，未证明生效不得展示为已启用；不顺势增加安装器                           |

名称仍遵守现有合同：Role 改名不更改已创建实例的冻结名称；实例在授权重启采用新配置后再显示其实际名称。删除再建同名 Role 不复用旧 ID。正文引用的是实例 Principal，不能用 Role 名或 Role ID 替代。后台身份仍然稳定，UI只显示可读名称。

不吸收：第三方MCP管理、云组织/账单、公开分享、官方Agent私有记忆目录、自动定时执行器和跨主机迁移。它们分别属于明确排除、不同记忆合同或冻结的远端范围，而非“顺手把标签显示出来”。

## 当前真正未收口的部分

1. **消息身份/样式**：本批已修复快照丢失profile、消息丢失提及绑定、当前用户黄色标识及消息列成员目录。缺少绑定的旧消息保留普通文本，不猜测历史身份。头像在线角标、已离开/删除标签尚未完整绑定；应以实例成员/生命周期事实接入，不能把Role配置删除当成实例删除。截图中的大块最后回复预览不是锁定新版的 ThreadRepliesBadge，本次不倒退到旧版布局。
2. **Agent资料整合**：当前 Role 详情主要仍是编辑表单（RoleEditor），实例侧栏主要是动态（InstanceInspector）；上表1—3尚未完成，这是明确的前端整合工作。
3. **既有前端兼容边界**：PDF评论未启用，转发消息包完整预览未接（channel-client明确提示）；不等于常规附件评论与消息列不可用。当前未重新扩大附件验收。
4. **验证边界**：通知已完成服务链路测试，但真实iOS/Android系统展示/点击、PWA后台和键盘未完整验收；LAN HTTP不提供Service Worker；官方登录态双站逐像素比较尚无证据。WebKit既有并行搜索超时的根因仍未证明，串行通过不擦除原失败。
5. **后端冻结保留项**：本地单Human MVP维持冻结；本批只修复快照读取缺陷，没有新调度或成本实验。Fork/Side现有五家CLI加合成模型证据不等于付费模型质量全覆盖；Claude/Pi SEA helper及远端Role session绑定缺口仍按当前状态表保留。极长历史找回约束质量和五家长期统计成本也不是本批UI里程碑证明的内容。

建议下一刀只做表中1＋2的纵向资料展示与现有编辑/重启闭环，随后补实例状态到消息行。保留现有测试，仅新增资料展示与写入边界的定向回归；不重新启动整站视觉微调或全后端成本验收。
