# Codex 长会话效率实验预注册

本实验回答：同一原生 session 持续完成有实际内容的工程审查时，正式回复路径与最终输出试验路径的累计成本、稳态成本、错误恢复和交付质量分别如何。它是一个固定任务的配对样本，不替代[目标合同 §6](target-contract.zh-CN.md)，不修改已有预算，也不因首轮超过旧逐轮预算就中止后续观察。

## 固定样本与三个实验臂

仅使用 Codex `gpt-6-luna`、`low`，按 `native → default warm → final-output warm` 顺序各运行一次。每臂一个独立且连续的原生 session，完成相同 12 阶段；检查点为 1、3、6、9、12。正式默认臂保留其正常 MCP/CLI 路由，实验臂启用最终输出；两者都记录实际使用路径，不能把“配置启用 final-output”当作“实际采用 final-output”。

原生官方自动记忆关闭；产品亦核对原生记忆关闭证据。固定 CLI 版本、精确 model/effort、源码内容哈希、题面哈希、工作目录与输入范围；每臂独立工作区从同一快照构造。无预热、计划内重启、session 轮换或强制压缩。意外重启、原生压缩、恢复、失败等如实记录，不删除其用量，也不伪装成预设正常路径。

固定工作负载由 [long-session-workload.mjs](../../scripts/cli-efficiency/long-session-workload.mjs) 定义，ID 为 `restart-audit-12/v1`。快照来源 `7afe141`，六份文件总计 48,659 字节，每份内容均有独立哈希；题目与整体 prompt set 也有哈希。实验前后校验，不把产品当前 commit 混入任务身份，也不借旧批 native 结果作分母。源码 revision、实际 CLI/model 和运行配置另外保存为 provenance。

## 十二阶段的工作价值与公平边界

| 阶段  | 工作内容                                         |
| ----- | ------------------------------------------------ |
| 1–3   | 网络回执契约、已有测试、实际重启编排及身份检查   |
| 4–6   | 备份排除规则、损坏验证、允许重启与静止状态的区别 |
| 7–8   | 迁移前保护、显式恢复条件与失败补救               |
| 9–10  | 跨文件数据结构对齐、竞态及证据上限               |
| 11–12 | 精确回归测试规格、维护者交接判断                 |

前八阶段逐步提供新文件或行段；后四阶段要求使用已有上下文综合判断。已读内容尽量从上下文复用；若原生 compaction 等导致必要重读，应说明原因并完整计费，不自动判定技术质量失败。不得读取尚未开放的源码，不运行/导入项目脚本，不执行测试、不修改文件、不操作真实服务、不使用记忆或 Task；未提供依赖明确标为未验证。每轮只发送一次最终回答，正文要求与字数口径由固定题面规定，JSON 包装不计正文。

三臂获得相同题面和新增材料范围，不能根据上一轮答得好坏临时改题、追加提示或重采样。检查点是固定工作进度，不是挑选表现较好的回答。题面第 9、11 阶段已经引导对照具体整合缺口，因此本实验测试的是受引导的连续审查和跨阶段上下文使用，不能宣传为无提示自主发现漏洞或已执行代码修复。

rubric 仅供评审，不能进入 provider 上下文。模型实际回答须独立按每阶段 rubric 审核：事实、行号、当前实现与建议的区分、跨阶段一致性、限定条件和最终交接价值；正文前缀、长度、成功发布均不代替实质质量。读取范围、重复读取和未授权操作从真实工具轨迹另审。

回答出现前固定评分：每阶段三项，各项满足/部分/错误或缺失分别计 2/1/0；错误与缺失另标，不以沉默推断错误断言。完整技术样本标准为至少 60/72 且无关键安全错误；这只是本实验审查质量标准，不是效率预算。关键安全错误包括把 PID 相等当认证、允许有活跃执行权时重启/恢复、仅凭 roomSeq 覆盖变动数据、恢复运行凭据或删掉安全校验、把 spawn 当健康验收、声称已执行实际未执行的验证。字数、前缀、读取边界及跨轮一致性另列；技术达标不能代替全指令通过。阶段6不要求主动引用阶段8才开放的 restore 实现。

## 累计指标与判定

[long-session-metrics.mjs](../../scripts/cli-efficiency/long-session-metrics.mjs) 分别汇总全部阶段、每个检查点累计值，以及窗口 `1`、`2–6`、`7–12`。报告 input、cached input、uncached input、output、已观察完成生成数、阶段耗时及同批 native 配对比例。启动成本始终包含在全任务总账中，同时单列，不能以“稳态”名义删除首轮。

所有已测成本都保留，包括错误工具调用、帮助读取、失败尝试、格式错误和恢复。累计主表不抵扣所谓业务差异；旧逐轮门禁如保留其合同口径，须单独列为诊断，不能替代累计真实总账。usage 归属、去重和完整性沿现有证据来源，不新建第二个 token 计数所有者。

完整比较要求同阶段长度、连续 session、有效交付/执行结果、记忆关闭和完整 usage 证据。字段缺失、usage gap、账本不一致、stage 重复/错序、session 更换均不得产生完整比较结论。已观察小计仍保留，未知字段不填零、不估算；完整且可比的窗口可以单独报告，不能由局部窗口推出全臂完整。零分母比例保留未知。

完成生成数不是供应商 HTTP 请求数，token 不是实际账单金额。回复前后归属仅沿可信时序/界限证据；usage 晚落盘或 Host preempt 均不能证明是否发生新的供应商请求。记录 Room final marker 的真实类型、ACK、Activation 完成和实际回复工具，与原生 terminal 分开。

旧合同逐轮结果、累计观察、任务质量、传输成功是独立结论。累计报告不新增“长任务预算通过”标签，不用累计均值抹掉旧逐轮失败，也不因某轮失败只保留后续成功样本。

## 资源边界与停止规则

每臂预注册资源 admission cap 为累计已观察 input **1,200,000 tokens** 或墙钟 **20 分钟**，任一达到后不再启动下一阶段；最多 12 阶段。此处数字仅是止损资源上限，不是目标合同效率预算。阶段在途请求保留已有超时机制；usage 在完成后才报告，可能越过观察阈值，因此这些上限不是硬账单保证或精确 provider 请求限额。

不因首轮超过旧预算提前截断本次长观察；仍在资源范围且可以安全继续时，按固定阶段完成。身份/权限/连续性安全条件失败、无法取得必要成本证据或达到资源上限时，停止受影响臂并保存已耗成本、失败原因与未完成阶段。其他臂若继续，仅报告仍有有效配对的阶段；无有效同批 native 分母的结果不得形成比较结论。不得自动付费重试、重采样或运行中增加资源上限。

## 解释限制与归档

固定顺序使后运行的臂可能受 provider 缓存、负载和时间影响；记录命中量，但不声称已控制这些混杂。三臂均只有一个连续样本，不能推出稳定平均收益、一般长任务能力或所有协作场景效果。历史 P111/P112 可用于解释为什么需要观察实际路径和恢复成本，不能作为当前分母，也不能证明某条提示修改具有单样本因果收益。

归档原始结果、每阶段回答与真实工具/usage 证据、源码/题面身份、资源停止记录、独立质量评审及脱敏摘要。失败与缺失保持原样。默认测试只用临时状态和 fake provider；真实付费实验由 lead 执行，本预注册不增加模型、实验臂、重采样或产品权限范围。
