# 纵向验收缺口修复（2026-09-29）

## 所有权与边界

1. **Daemon 备份**只排除 `warm-runtimes/instrt_<UUID>/turns`：它是 Host 0300 权限的每轮临时授权目录，不是会话持久信息。备份收据记录 `omittedRuntimeCredentials`，不改源权限，不跳过一般读取错误；校验拒绝备份内出现该目录。Provider session 绑定及账本仍备份。沿用现有空闲检查与运行时退休机制，不恢复旧工具授权。
2. **Kernel 草稿**把已保存的模型 `basedOnRoomSeq`/`final` 作为 `replyIntent` 返回；Worker CLI 的修改正文指引明确携带它们。普通新发言绝不自动继承旧草稿的 final，避免进度发言误结束工作。`send-draft` 仍只继承同 Activation 草稿意图。原序号可能触发再次 hold，仍须按原有确认路径发送，不绕过 freshness、ACK 或 Task 规则。
3. **验收脚本**按消息 → Activation → 回复核查额外接力：只豁免预期房间/实例里、由另一实例显式点名、单事件且已完成的独立 Activation 的唯一回复。未归属、合并区间、同 Activation 多条回复仍失败；不是增加允许回复数。旧证据保持原判，不追改历史 fail。
4. **Host 协议**明确唤醒已交付正文时不要重复 `message-read`，不检查 Worker 可执行文件；仍可按需查旧上下文，缺正文时仍先 check。协议版本更新走已有续聊通知，不靠修改 system prompt 就宣称旧 session 收到；不重置 session。压缩普通沟通措辞，原 10,500 字符总预算不变。

## 上游关系

沿用现有 Raft `getSavedDraft(agentId, target)` 的目标草稿与修改正文语义；本次修的是 Loom 的模型因果确认信息在该路径中的遗失，不修改 Raft 新鲜度/草稿寿命。唤醒携正文沿用现有移植，本次减少多余读取是 Loom 提示修正，不宣称逐字复制上游。0300 每轮句柄是 Loom 自身隔离要求，备份排除是本地适配。
