## 剩余额外消耗

1. A：先 message-check，再失败的 Git 探测、文件列表、实际读码、发帖、最终收尾，共六次生成。原生是读码和回答两次。A 首次输入 10,866，原生 8,810；固定差 2,056，不是主要乘数。
2. B：message-check、目录查询、分别读取两个文件、Git 探测、发帖，共六次。原生一次工具读取两个文件，再回答，共两次。这里既有协议重读，也有模型拆分工具工作的差异，不能全部算为调度强制开销。
3. A 初审虽有交接规则，仍显式用了 `--progress`，因此多一次收尾生成；它随后自然结束，未轮询等 B。B、修订、恢复三次均显式 `--final`。**此次没有覆盖省略 final 的真实模型发帖；该默认分支仍只有免费端到端证据。**
4. 两个续轮各一生成，输入仍是原生约 1.31 倍，因为 Loom 历史中已有更多工具输出和频道协议上下文。不能靠结束本轮清除这些历史，也不应因此静默换 session。

P64 Loom 512,918 输入、27 次生成；本次 227,892、14 次，数值下降约 55.6%。但 P64 原生含质量补做、Loom 恢复用了 SOS 且多唤醒 B，本次执行路径与输出不同；单样本无法归因全部收益，更不能宣称稳定成本倍率。
