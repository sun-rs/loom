# 默认 MCP 长期验证：波动、停止规则与后续设计

本次为 P119 后的免费设计审查，未改变产品、检查器、历史裁决或付费授权。目标是测出真实连续任务的全部成本及可靠性，而非通过筛选只保留一次成功的轨迹。

## 当前结论

真实模型输出会波动。当前检查器把质量、传输路径、证据完整性和安全停止合并成一次 assertion；单个可恢复调用错误会中断整批长期观测。这能检查严格的单次调用要求，却不能充分回答“首次额外成本能否在后续连续任务中摊薄”。这是验证设计需要修正的部分。

P118 产品 A 首轮一次 MCP 调用成功；P119 同位置第一次将频道名填进 threadId，拒绝后第二次调用成功。这两个实验的 final-output 开关和指令不同，不能当成相同条件下的随机重复样本，也不能据此估计参数错误率。两批各自只有一个已观察产品阶段；原生 36 阶段不能充当产品的样本量，同一 session 的十二轮也不是十二份独立重复。

P119 仍按冻结规则失败，不补跑、不改判。其两次调用与额外输入是真实成本，不能因“模型有随机性”而扣除。模型会误用工具是产品可靠性需要容纳的现象，而不只是测试噪声。

免费假模型验证只能证明：当模型产生给定调用时，真实 CLI、MCP、Kernel、回执与 ACK 链路正确。它不能证明真实模型会稳定选择该调用，也不能估计成功率或真实 token 倍率。之前“免费验收可靠”的结论仅在这个范围成立。

## 拆分停止和最终判定

后续使用新实验身份，保留旧 profile。停止规则在付费前冻结，不可见到结果后再改。

| 观察                                                                                         | 后续动作                                 | 结果如何记录                                                                           |
| -------------------------------------------------------------------------------------------- | ---------------------------------------- | -------------------------------------------------------------------------------------- |
| 真实越权、错目标写入、重复业务发表，执行围栏或隔离失效                                       | 立即停止                                 | 安全失败，保留全部用量                                                                 |
| 记忆关闭不可验证、换 session、模型或源码漂移、材料不一致、用量缺失、结果未知、无法关联回执   | 停止准入后续阶段；不由门禁重发           | 证据或比较条件不足，不宣称模型错误或效率合格                                           |
| 达到事先冻结的资源上限，或 Run 超时/未终止                                                   | 安全终止或停止下一阶段，保留在途超限     | 截断及已知成本，不填补缺失轮次                                                         |
| 受注册检查器识别的参数错误被确定拒绝、没有业务写入，原 Run 内随后正确唯一发表且 ACK/用量完整 | 记录恢复后继续原 session                 | 一次成功失败、最终送达成功；所有生成、工具返回、时间和 token 保留                      |
| 唯一合法回复后的跟随生成、首次开销偏高或单轮延迟超标                                         | 在资源上限内继续                         | 对应合同指标照样失败，完成长期观察不会把它变成合格                                     |
| 答案错误但送达完整                                                                           | 单列质量失败；可按预先冻结的诊断模式继续 | 后续必须保留实际错误历史，不能注入正确答案；不把错误链和正确链的成本比称为同等质量效率 |

对恢复调用的继续不是宽泛地捕获异常。必须关联每个 call id 和真实结果，核验拒绝无写入、成功回执与 Room event/唯一消息/Run/消费者 ACK 对应。未知结果仍停止；检查器不合成 ACK，不补发调用，不替模型重试。只放行受测试覆盖的确定性拒绝形态，不能为了继续观测假定任意错误都没有副作用。

当前 AST 校验只识别少数静态 wrapper 形态。等价但无法识别的写法属于证据提取限制，应报告为“未支持”，不能误报为产品协议失败；新增提取支持也要测试，绝不执行模型脚本来判定其意义。

## 分别报告哪些数据

1. **可靠性**：一次调用成功次数/实际阶段数、可恢复拒绝次数、最终正确送达次数、重复发表和错误目标次数，保留错误类别及发生位置。
2. **全部成本**：逐轮原始输入、缓存输入、输出、回复前/后的生成和耗时；首次及第 4/8/12 轮累计值，所有失败及恢复开销均包含。没有真实费率/账单依据时不称货币价格倍率。
3. **合同裁决**：逐条使用目标合同 §6；累计接近原生不抵消首次、单轮或安全指标失败。
4. **质量与可比性**：同题同材料、真实同伴历史，最终答案质量独立评分。质量不同则报告诊断成本及质量差，不认证等质量效率。
5. **重复性**：事先固定批次数和顺序；未来需要重复时，以完整独立配对为重复单位，跨批交替执行顺序，并披露缓存、日期、CLI 和模型绑定。连续轮次相关，不据此计算虚假的独立样本置信度。资源有限时明确“仅一批观察”，不能运行到通过才停止或挑选最好一批。

新设计不自动授权任何重复批次。首次完整长期配对可用于发现趋势，但不能单凭一批宣布稳定达标。重复研究必须在运行前固定计划、预算与授权，不因失败临时追加付费样本。

## 产品接口与验证同时收窄

P119 的具体风险在当前目标回复工具仍暴露无说明的 threadId。下一实现切片应先比较：补字段说明，或从当前目标 facade 移除模型选择目标的责任。倾向后者；目标来自可信执行上下文，Kernel 仍是权限、因果和写入的单一 owner。不能把任意频道名静默翻译为 thread ID，也不能自动选择模型“可能想要”的目标。

必须先查明频道顶层、Thread、private box、多目标投递及 held draft 各自的现有绑定来源。若不存在唯一可信目标，不得猜测；显式跨目标操作继续使用既有授权路径。尤其不能为了简化 MCP 把 Thread 回复错误送到频道顶层。

最低免费测试矩阵：顶层/Thread/private box 正确绑定；旧参数不能改变范围；stale hold 与 draft revision 保留目标；拒绝后恢复的全部用量保留；成功后跟随生成保留；重复发表/未知结果/未支持提取形态不冒充成功；末轮与中途规则一致；旧实验身份和历史裁决不变。先 TDD，再真实 CLI 加本地假模型正反例；之后才冻结新付费长期方案。

## 本轮审查依据与边界

检查了 `validateMcpInlineRound` 的单调用断言、`createRoundValidationFence` 的立即抛错、执行器对首个失败臂的退出、以及 P118/P119 已归档原始轨迹。P119 对应阶段终态是一条正确消息、一个完成的 Activation、真实消费者 ACK；参数拒绝没有导致重复发表，全部两次生成已保存。
