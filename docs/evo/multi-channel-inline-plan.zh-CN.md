# 三实例十二轮：首轮内联材料的传输成本对照

P117 在原生 A 首轮未读取材料便结束，尚未建立长期成本配对。本方案单独控制材料交付：把同一份材料直接放进首条公共消息，保留真实频道差额和连续 session。旧[文件读取方案](multi-channel-long-plan.zh-CN.md)与[P117 失败记录](evidence/2026-10-05-multi-channel-p117.md)不变；两种实验不能合并分母。**P118 已执行并封账：原生全通过，产品首轮走 MCP 而未走选定 final-output，长期配对未建立。见[结果](evidence/2026-10-05-multi-channel-p118.md)。**

## 输入与比较边界

两臂各三个独立、连续的 Codex session，每实例十二轮，每臂 36 阶段。问题、材料、业务要求与逐字期望答案分别冻结；复用旧十二道源码事实题，答案只供评估器。完整材料为 14,682 字节，只在全局第一个 Human 问题中以代码围栏提供一次。三个实例均在该消息之前创建，A 直接收到，B/C 从正常频道 catch-up 收到同一条消息。原生由确定性脚本搬运本臂真实消息，不使用协调模型。

每个 session 首轮的新 user 输入必须包含完整材料且仅一次，后续新输入不得重发完整材料。旧材料自然留在连续 session 上下文里；不把 provider 请求携带已有历史误算成平台新投递。全程禁止业务工具，包括补读文件；工作区 evidence.txt 仅保留作审计副本。验证器证明材料进入输入，不证明模型理解。平台身份、成员事件和协议外壳仍不同，不能称完整输入相同。

逐轮答案必须与冻结规范逐字一致；使用实际回复，不修改或用标准答案替换。后发实例能看到同伴回答，因此本题只测共享事实的规范交付，不代表三份独立审查、自然讨论、互相监督或多人协作收益。十二轮输出较短，不代表多日任务或压缩压力。

## 执行与停止

- 入口：[test-cli-multi-channel-inline.mjs](../../scripts/test-cli-multi-channel-inline.mjs)。`--plan` 只查版本及来源，不启动模型；`--paid` 要求干净已提交源码，命令参数不代替授权。
- 固定 Codex 0.160.0、`gpt-6-luna / low`，两侧关闭官方原生记忆；启动前检查实际 catalog，运行中核对模型、effort、cwd 和 session 连续性。
- native → final-output，单次配对，各三 session × 十二轮。只在隔离 daemon 开启 Codex final-output 候选，OpenCode 候选及 prewarm 关闭，正式服务不变。
- 每臂准入软上限 3,600,000 输入 token、40 分钟，产品最多 36 Run。单个在途阶段仍可能超限，不是硬计费限额。
- 材料缺失/截断/重复、任何工具或未知 response item、答案错误、额外 Run、用量缺证、session 更换等均停止，保留实际回复和成本。原生失败不启动产品；不追加提示、不换模型、不补跑。
- 累计观察首次及第 4/8/12 轮，按实例和全组分别展示。只有完整合格的配对前缀才给描述性倍率，早期前缀不能推翻整批失败。正式判定仍逐实例调用既有 compareArm；唯一预算依据为[目标合同 §6](target-contract.zh-CN.md#6-验收数字对照原生-cli-同一-session同模型同-effort)。
