# 频道与 Task 消息列：唤醒和差额读取

负责人 2026-10-02 批准重新设计并落地。本设计修订目标合同 §3 的“整个频道差额”规则。

## 产品合同

Task 是频道内的持久对话分区；负责人、状态与交付是附加信息。能读取不等于自动订阅。
频道正文默认参与；消息列普通投递按关注关系，直接 @ 可加入关注，自己发言加入关注，退出关注停止后续普通通知。Task 创建时的负责人、协作者、审核人、实例创建者，以及后续认领／指派者加入同一关注表；不另建 Task 通知订阅。schema 81 对历史成员补齐缺失的关注记录，已有取消关注优先，不回填任何已读证据。Task 不因闲置或完成而关闭讨论。实例自己的消息不唤醒自己。实例作者仍遵守显式 @ 唤醒规则；本批不改成实例互相广播。Human 在消息列不 @ 时只通知该列关注者；@all 保留显式频道广播语义。

## 唯一所有者与三种位置

Kernel owns Room ledger、关注关系、投递和读取证据。不得新建调度队列。

1. Room delivery cursor：一次消费者扫描/确认到哪个账本位置，用来结算 Activation；不代表所有消息列都被读过。
2. Target read position：实例+Room+消息列（频道正文使用独立 key）已经读取的位置，复用 worker_target_read_positions。
3. 逐消息呈现凭据：复用 worker_message_presentations，用于精确覆盖，不能由最高序号猜测。

差额不是时间差，而是每个目标内 `(lastRead, frozenHead]` 的消息集合。自动上下文只包含频道正文、已关注消息列及本轮明确投递的目标；其他消息列保留可搜索/显式读取，但不自动灌入。

## 读取和确认

- 唤醒正文和 message-check 共用 Kernel 自动选择规则；不能只过滤唤醒却由 check 全量灌回。
- 显式 room-read/message-read/search 保留原权限及分页，不因未关注拒绝读取。
- 每个目标独立下界；新关注旧消息列不能用频道已读位置跳过它的未读内容。首次窗口有界，根消息/历史按需补读，不承诺全部历史一次灌入。
- 窗口冻结选择范围及下界，重呈现不随关注/读取位置变化，避免 digest 漂移。后续轮次应用新的关注状态。
- 不相关账本位置可作为自动投递不适用项越过，但绝不能写入“正文已呈现/已读”的凭据。只对实际返回正文记逐消息证据。
- message-check 在分页和字节预算之前过滤无关消息列；没有正文的过滤尾段可推进扫描位置，不产生正文读取凭据。Task 后续状态事件随目标选择，Task 创建信息仍是频道事实。
- 超预算说明数量和序号，保留分页补读路径；未知业务事件不静默丢弃。Host 送达不构成 ACK。Task 完成仍需显式动作。

## 纵向落地与验收

先验证 Human 在旧 Task 发言：相关实例收到；无关实例无唤醒，并且后来在频道被叫醒时不会补进该 Task 正文。其次验证相关实例的频道/两条消息列各自差额、首次关注、取消关注、窗口重呈现、超限补读、重启及准确 ACK。私聊保持独立范围且不 steer 频道。
