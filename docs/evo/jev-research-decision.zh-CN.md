# Jev 研究结论与 Loom 取舍

日期：2026-10-01。负责人确认：不引入核心调度，继续优化确定性代码。
本文件记录研究经验，不修改目标合同，也不宣称 Jev 普遍无效。

## 结论

不让 Jev 创建、取消或完成 Activation，不让它解释自然语言后伪造 @，
不把 ACK、Task 完成、权限、记忆写入或 session 生命周期交给模型。
不默认过滤工具输出或频道历史。停止扩建通用 Jev 集成。

可保留的窄方向是用户按需使用的原文语义检索：先普通搜索，必要时才用
Jev 给文件/行号/片段排序；原文一直可读，排序不证明证据完整。
它应是普通外部 CLI 工具，不是新的 Loom 场景接口、托管 MCP 或必经拦截器。
当前只留实验，不建设关闭状态的产品框架。

## 研究经验

- 少给模型看字符，不一定减少整项工作的生成次数、费用或错误。
- 推荐入口可能遗漏辅助判断与反例；必须追踪依赖，不能把高相关性当作完整性。
- 对比必须包含免费的普通检索，避免把导航本身的收益算给 Jev。
- 未缓存输入、输出、检索开销、耗时和交付质量分开核算。
- 校准题、验收题和重复变体分开；不能只公布被阈值留下的正确项而隐藏弃答。
- 构建编号/状态、成员 ID 等已有结构字段的判断应直接由代码完成。
- P79 的多次读取发生在已运行的 session 内；唤醒前分类不能解决该轮内部轮询。

若将来重新评估检索工具，输入须限于用户允许外发的代码，避免私聊、凭据和
完整 transcript；输出保留原文位置及内容指纹，失败回退普通检索，缓存按
实际内容/问题/模型与问题模板版本区分。不能仅依赖 Git commit，工作树可能已改。
必须在重复配对任务上证明相对原生搜索的额外收益，且不退化关键正确性；
不因模型置信度高就扩大权限或取消投递。

## 上游参考（研究，不是移植）

- [TypeSafe intent routing](https://docs.typesafe.ai/patterns/intent-routing)：模型分类，代码决定处理策略；不是 Loom 因果链的替代。
- [wakegate](https://github.com/shitianfang/wakegate)：观测型轮询前筛选；不能直接套用到必须送达的频道消息。
- [winnow](https://github.com/GhalebDweikat/winnow/blob/main/docs/WRITEUP.md)：工具结果分块、原文召回；早期保守隐藏约 5%，标签与样本局限明显。
- [jev-harness 后续报告](https://github.com/Astro-Han/jev-harness/blob/main/TB4-CONCLUSION-2026-09-22.md)：49 个可评分配对中累计输入增加 11.78%，作者关闭当前集成；不证明 Jev 普遍无效。
- [jevgrep](https://github.com/thehumanworks/jevgrep)：按语义返回源码位置；P83 的 HTTPX 主题与其公开案例重叠，不宣称未见过的基准。
