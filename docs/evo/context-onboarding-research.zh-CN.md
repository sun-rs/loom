# 新实例与超长频道历史：现状核对和最小方案

2026-10-14，负责人要求补 Fork 身份说明，并研究超长 box 的新成员上下文。随后负责人同意实施首次有界接入，并同步修订目标合同；不引入自动总结、自动换 session 或新调度器。

## 先区分三件事

完整历史可访问，不代表已经送入模型；送入模型，不代表模型正确理解或记住了全部内容。频道账本是持久事实，CLI 上下文是有容量限制的工作材料。有界 box 投递限制的是新增材料，不能保证整个 CLI 会话永远不满：正常对话、工具结果与思考轨迹仍会增长，原生压缩继续由 CLI 负责，不应把正常历史携带一概解释成模型反复读取 box。

普通新实例的首次频道投递现在可以在现有预算内补入加入前的近期顶层消息。本次请求先占预算，再由近期背景填充余量；较早未展示项保留数量和序号，仍可授权搜索、分页或围绕指定消息读取。未关注的 Thread／Task 正文、其他频道与私聊不混入。补读不是新回复目标，也不会触发额外的模型初始化或总结轮。

Kernel `conversation-delivery.ts` 只扩展首次普通成员顶层正文的选择下界，复用既有窗口冻结和投递记录，没有新表或第二个游标。已有频道消费位置不回退；原生绑定与同频道 Host 送达记录共同阻止再次补灌。无绑定的失败重试仍可恢复材料；先私聊后进入频道也获得接入背景。Fork 通过创建事件的来源身份排除，Side 不走频道成员路径。显式重启的有界恢复保持原有独立语义。

现有消息数／字节预算并不承诺装下全部历史，逐消息读取证据只记录实际呈现正文。数据库省略量聚合仍可能随历史规模增长，本次不声称对任意规模恒定耗时。记忆轻索引沿用已有读开关、预算与 daemon 投递，无自动从对话提取长期记忆。

Fork 则复制源 CLI 保留的原生历史，并建立新身份。复制过程没有模型生成，不代表后续携带的大上下文没有输入成本；新实例不继承源的 Task 归属、凭据或消费位置。2026-10-14 身份说明见[分支实施边界](session-branches.zh-CN.md)。它可能继承源原生上下文中的旧私聊内容；“没有源私聊读取权限”不等于已复制内容被删除。

## 已采纳：首次有界接入，而非全文通读

本切片补普通新成员第一次被唤醒时的**加入前近期上下文**，复用现有窗口与授权读取。当前请求优先；剩余预算容纳当前频道近期正文，并携带已经显式维护的频道记忆轻索引。说明哪些历史未展示，并提供查询／消息定位入口；不要求先做自我介绍、全频道扫读或完成一轮初始化总结。Fork 已继承历史，不应再强制走同一全量恢复流程。

更早的约束与结论通过现有搜索命中、消息前后窗口、指定 Task／Thread 和记忆正文按需取回。已有成员也可以被正常点名交接，但不是每次加入必须新增的付费协作步骤。记忆若陈旧或缺失，保留未知并回查原始记录，不把摘要或“最新几条”当完整事实。

如果用户明确要求“审计全部历史”，那是独立的全量分析任务：冻结读取范围，分批遍历，记录已覆盖与未覆盖区间，结果附原始消息引用。分页并不会让有限上下文永久装下无限内容；需要阶段产物或显式摘要，其额外成本属于这项任务，不能隐含在每次新实例加入中。普通工作不要求做到全历史覆盖。

本切片的自动化、实际 CLI 合成模型链路及部署证据分开记录于[验收记录](evidence/2026-10-14-channel-onboarding/summary.json)。不由免费传输验证推断真实模型能正确找回全部约束，亦不宣称付费效率门禁通过。不要为此先建向量数据库、后台自动总结服务、第二套记忆或场景工作流；是否需要更复杂检索，以真实任务漏项与成本证据决定。
