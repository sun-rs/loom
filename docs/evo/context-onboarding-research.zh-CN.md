# 新实例与超长频道历史：现状核对和最小方案

2026-10-14，负责人要求补 Fork 身份说明，并研究超长 box 的新成员上下文。本文不变更目标合同，不引入自动总结、自动换 session 或新调度器。

## 先区分三件事

完整历史可访问，不代表已经送入模型；送入模型，不代表模型正确理解或记住了全部内容。频道账本是持久事实，CLI 上下文是有容量限制的工作材料。有界 box 投递限制的是新增材料，不能保证整个 CLI 会话永远不满：正常对话、工具结果与思考轨迹仍会增长，原生压缩继续由 CLI 负责，不应把正常历史携带一概解释成模型反复读取 box。

当前普通新实例的频道正文自动补读下界是实例创建／加入事件。关注消息列和明确投递目标仍按各自位置与规则补读，不能用频道加入下界概括旧 Thread 被明确交付的情况。所有补读使用现有消息数／字节预算，当前请求优先，较早省略项报告数量与序号。不会因普通加入自动回灌加入前的频道正文，但可在权限内显式检索、分页读取以及围绕指定消息读上下文。它目前**没有自动完成加入前的上下文重建**。

依据：`packages/kernel/src/activation-catch-up.ts`、`packages/kernel/test/instance-first-wake-catch-up.test.ts`（明确覆盖加入前排除、预算与省略范围），`packages/kernel/src/worker-read-tools.ts` 的 search/history。显式重启的近期历史恢复已有另一条有界路径，不能将其当成普通新成员行为。频道之外和别人的私聊不因加入而可读。

Fork 则复制源 CLI 保留的原生历史，并建立新身份。复制过程没有模型生成，不代表后续携带的大上下文没有输入成本；新实例不继承源的 Task 归属、凭据或消费位置。2026-10-14 身份说明见[分支实施边界](session-branches.zh-CN.md)。它可能继承源原生上下文中的旧私聊内容；“没有源私聊读取权限”不等于已复制内容被删除。

## 建议：首次有界接入，而非全文通读

最小下一刀应补普通新成员第一次被唤醒时的**加入前近期上下文**，复用现有窗口与授权读取。当前请求优先；剩余预算容纳当前频道近期正文，并携带已经显式维护的频道记忆轻索引。说明哪些历史未展示，并提供查询／消息定位入口；不要求先做自我介绍、全频道扫读或完成一轮初始化总结。Fork 已继承历史，不应再强制走同一全量恢复流程。

更早的约束与结论通过现有搜索命中、消息前后窗口、指定 Task／Thread 和记忆正文按需取回。已有成员也可以被正常点名交接，但不是每次加入必须新增的付费协作步骤。记忆若陈旧或缺失，保留未知并回查原始记录，不把摘要或“最新几条”当完整事实。

如果用户明确要求“审计全部历史”，那是独立的全量分析任务：冻结读取范围，分批遍历，记录已覆盖与未覆盖区间，结果附原始消息引用。分页并不会让有限上下文永久装下无限内容；需要阶段产物或显式摘要，其额外成本属于这项任务，不能隐含在每次新实例加入中。普通工作不要求做到全历史覆盖。

这一刀尚未实施；本批完成的是 Fork 身份投递。后续应先测试新加入前后历史、超预算省略、分页可达、不误报已读、频道／私聊隔离及失败重试，再接共享服务。不要为此先建向量数据库、后台自动总结服务、第二套记忆或场景工作流。是否需要更复杂的检索，用真实任务的漏项与成本证据决定。
