## 有限剩余队列

按以下顺序完成，不再将已通过的附件等细节重新列成无限待办。

1. **G1 已实现**：独立单聊创建／分类和频道内私密消息历史入口已贯通，见[语义和失败边界](standalone-chat-ui.zh-CN.md)。多步骤创建可能留下可管理的部分频道；不自动恢复跨刷新向导、不新增一种执行会话类型。后续不把这些明确边界重新扩成无限架构工程。
2. **G2 动态行为缺口**：手机首页数字徽标已收口。线程菜单现已惰性读取 `thread.followers`，接入 `activity.follow` 与未知结果读回；关注时显示读／未读，未关注或未知时省略；失败可重新读取，关闭菜单不取消已提交写入。桌面／手机尺寸定向验证通过，见[关注验收](evidence/2026-10-19-official-page-audit/activity-follow-verification.json)。取消关注使普通消息列退出动态资格，新精确提及仍可重新出现，不能用前端缓存保留行假装官方等价。官方双击动态是“待列表有首条未读后滚动并高亮约3秒”，不打开正文也不写已读；桌面双击手势已接入：先刷新既有有界列表，再定位首条未读；不写已读或打开详情，离开页面清除请求；手机仍为单击导航。正文“动态”标题另有官方双击循环下一条未读手势，现已接入：只在当前加载窗口定位，末尾回到第一条，不额外请求、不导航或写已读；见[标题定位](evidence/2026-10-19-official-page-audit/activity-title-verification.json)。见[定向验收](evidence/2026-10-19-official-page-audit/activity-focus-verification.json)。加入通知计入侧栏未读已核实为 Kernel 现有规则（`human-activity.ts`／`global-discovery.test.ts`），点击频道会确认；通知不生成动态消息卡片，故两种计数可不同。官方服务端是否排除此类通知尚无充分证据，保留原规则，不作为已复现缺陷修改。分组待办已按当前生产入口纠正：v1.21.22 的 `He` 未渲染旧版频道分组侧栏，`channelFilterId:null`；实际是 `Oe/Z/Q` 对已加载窗口稳定分成“已置顶／全部会话”，明确排除线程，不声称全局置顶优先分页。本批照此接入侧栏偏好与原生 SectionEyebrow／Pin，保持分页、时间顺序和未读状态；无需新增分组后端。见[置顶分段](evidence/2026-10-19-official-page-audit/activity-pinned-verification.json)。G2仍余取消关注后的历史保留差异；现有 Kernel 明确提及可覆盖取消关注的规则保留。进一步核实：`human_thread_follows` 只有关注布尔值，没有取消关注时的历史前沿；官方 `markThreadUnfollowed` 及测试保留原行／原最新消息并清未读。实现跨刷新等价需由 Kernel 保存历史保留前沿、独立于未来通知资格，不能直接放宽列表资格或用当前最大消息猜测既往记录；本批未修改此数据合同。
3. **G3 浏览器推送**：保留当前诚实的未接入状态。涉及订阅和安全上下文能力；不能把站内铃铛已经可用等同于浏览器推送可用。它不阻断当前站内聊天MVP。
4. **V1 验证缺口**：对发生改动的调用位置补验证；纯文本预览、成功外链跳转、低频查询错误与真正iOS/Android触摸保留边界。没有复现问题时不为追求“全部状态”无限添加门禁。逐像素跨站比较需要可访问的官方登录态，本次未完成。

主动排除：公开分享、多Human/云组织/账单、第三方MCP管理、音视频预览；远程Computer属于冻结后续范围。这些不作为本轮缺陷或延期修复项。
