# Loom 记忆与历史 v1 测试计划

先写失败用例，再实现对应接口。U 使用固定时钟、内存夹具和注入的 I/O，不启动 CLI 或进程。I 使用同一台机器上的两个真实 loomd，分别使用独立数据目录、套接字及临时项目，故障点通过明确屏障触发。L 使用绝对路径启动原生 CLI，隔离 HOME、应用数据和工作树，优先用本地模拟端点完成无需推理的握手。

标记「v0 部分」表示 Pilot 测过所列子项。其余断言仍须新增并先见红。每次重跑都应能凭回执、序号、偏移或测试计数判断结果，不靠肉眼判断进度。 [设计基准](MEMORY.md) · [Pilot v0 验收](/Users/sun/Code/loom-pilot/.worktrees/pilot-memory-0/tasks/PILOT-MEMORY-0/RESULT.md)

## U · 单元

1. **U01 · U · 决定 #1 · 固定提示和写入判断。** 准备四类条目样例与各角色模板。渲染提示并触发结卡、换班、预压缩和普通轮事件。断言提示含一事实一文件、更新、遗忘、使用前核验及完整禁存清单，三个触发点只发提醒。普通轮期间显式写入可达，事件本身不生成内容或调用模型。
2. **U02 · U · 决定 #1、#2 · 更新与遗忘。** 准备一条已验证事实和修正后的同一事实。提交修订，再以当前修订调用 `forget`。断言 ID 不变，修订递增，目前仅有一份生效条目，遗忘后按 ID 与关键词查不到正文，旧请求重放也不能恢复正文。
3. **U03 · U · 决定 #2 · 写权限及身份。** 准备 Super、Auditor、Leader、Worker 四个会话绑定。各尝试写类型表的所有组合，并伪造请求的作者、项目、角色、ID 和修订值。断言只有角色职责与项目范围内的写入成功，服务端身份和分配值来自绑定，Worker 只能调用 `propose` 产生候选。
4. **U04 · U · 决定 #2 · 候选和裁决。** 准备 Worker 候选、两条有替代关系的旧裁决和一个结卡事件。比对未审、晋升、并入、退回及拒绝状态，再导入旧裁决。断言未审批时自动索引为空，晋升保留提议者和审查者，重复结卡不会再创建，裁决原件和替代关系随 `ruling` 保留。
5. **U05 · U · 决定 #2 · 格式、去重和安全检查。** 准备合法条目、超限正文、畸形元数据、同层重复、不同层同文、真实与虚构 SHA、已不存在的路径、逃逸路径和符号链接。逐一提交并重建索引。断言只写入合规、可核验的事实，同层完全重复不新增，索引每条一行。**v0 部分**覆盖 Markdown、索引重建、超限和失效 SHA／路径，尚未覆盖 v1 身份、跨层与去重。
6. **U06 · U · 决定 #2、#7 · 外部来源与脱敏。** 准备已观测的 web／MCP 来源、伪造的 caller 来源字段和合成敏感标记。依次写入、晋升并查询派生历史。断言外部标记以可核实来源为准，能脱敏的字段替换后才可显示或晋升，无法可靠处理时拒收。记忆文件、索引、增量和错误信息均无标记原值。
7. **U07 · U · 决定 #3、#4 · 排名及按需读。** 准备旧的高优先级裁决、新的低优先条目、同档不同使用量的条目、私有项和超 400 tokens 的索引。生成启动前缀，再 `search` 和 `show`。断言先过滤权限，按重要度、种类、使用量、ID 排序，完整索引行在 400 tokens 内且注明截断，正文只由 `show` 返回，提示含背景笔记标识。**v0 部分**覆盖 400 tokens、标题／关键词匹配、索引和按需文件路径。
8. **U08 · U · 决定 #3、#4 · 增量及投递游标。** 准备冻结前缀和 31 条获准变更，含更新和撤回。生成下一次投递，模拟 ACK 丢失后重投，再确认接管并生成后续投递。断言原前缀逐字节相同，后缀至多 30 条且标截断，授权未变时旧 ID 复用同一批次，确认后续发遗漏项。另在重试前撤权，断言只对账，未接管证实后才重新调度，新的后缀无已撤权内容。
9. **U09 · U · 决定 #3 · 引用、排序和过期。** 准备注入、搜索、重复轮事件、未授权 ID 和真实引用，设置测试阈值 N。推进到过期前后并调用维护操作。断言只按授权根轮及 ID 去重计数，排序使用该计数，N 天后为 `stale` 且退出自动注入，Auditor 确认前正文未删除，明确遗忘后索引和后缀显示撤回。**v0 部分**覆盖显式过期与替代项过滤，没有引用统计和复核。
10. **U10 · U · 决定 #4 · 读取矩阵。** 准备本项目共享条目、Auditor 私人条目、Worker 候选、私有历史、同组及无依赖的卡片。以各角色对索引、增量、`show`、`search`、附件及 `hist` 运行同一权限表。断言 Super 可见全部，Auditor 可见全项目，Leader 读共享层及 Worker 但无 Auditor 私有信息，Worker 禁搜且只读附件和自己卡片血缘或已声明的依赖，Reviewer 只读显式授权。用户层 `preference` 和 `ruling` 对 Auditor 和 Leader 在 `index`、`search`、`show` 中只读可见，其余用户层条目及 Super 私人笔记和跨项目材料仍不对二者开放。Worker 和 Reviewer 不可读用户层。猜 ID 的响应与未知 ID 一致。
11. **U11 · U · 决定 #4 · 跨项目授权。** 准备 A、B 项目，B 含共享与私有材料，A 的 Worker 声明 B 依赖。分别测试无授权、有效期内、到期及撤销。断言只有 Super 能授予带理由和到期时间的共享只读访问，有效授权时结果含来源项目及 as-of，任何阶段均不暴露私有项或赋予写权。
12. **U12 · U · 决定 #5 · 稳定项目键。** 构造多个根 SHA 顺序不同、规范化后相同或不同的远端、同仓不同子路径、同一仓库的 worktree 和无 Git 的规范路径夹具。计算键。断言选择排序后的最小完整 SHA，规范化同一远端得到相同键，fork 远端和子路径区分项目，非 Git 路径仅供单 cell。规范化前后的回执均无合成 URL 凭据。
13. **U13 · U · 决定 #5 · 身份转移。** 准备就地路径转 Git、两个旧绑定竞争、绝对路径移动、浅克隆、fork 和历史重写夹具。提交识别结果及有无 Super 决定的 move、bind、split。断言仅一对一就地升级自动迁移且保持条目／修订／历史，其他情况保留 orphan 或待决策，移动提示不改变授权，确认拆分后历史与访问不串项目。
14. **U14 · U · 决定 #6 · CAS 与缓存。** 准备同一条目的两个写方，均持修订 r，并给一个 cell 缓存旧 seq。先后提交、重放首个请求、模拟断线读写。断言第一个更新成功，第二个仅得到冲突及当前修订，重放没有额外修订，缓存显示原 seq 和时间，离线写只在 outbox 成为候选。
15. **U15 · U · 决定 #7 · 字节偏移及连续范围。** 输入完整行、含 UTF-8 多字节的半行、后缀、乱序批次、重复范围、同偏移不同字节及文件换代。断言只发完整行，续行补全后只收一次，ACK 不跨缺口，冲突保留原始记录，换代后的同偏移是独立记录。
16. **U16 · U · 决定 #7 · OpenCode 适配。** 给导出/API 夹具三份分页快照，第二份全重复，第三份包含同一原生 ID 的完成状态更新及新条目。投影两次。断言重复不新增，状态更新保留为同会话的后续稳定记录，使用已有记录 ID／版本生成追加流，过程中无数据库文件读取。
17. **U17 · U · 决定 #7 · 历史发布和清理状态机。** 输入完成事件、部分 ACK、完整 ACK、重复 ACK 和待清理意图。推进状态。断言完整范围确认前无证据卡、DONE 或清理动作，确认后只产生一个稳定发布 ID 和一项可重试清理动作。
18. **U18 · U · 决定 #7 · 派生重建和保留。** 准备可重放 raw、一个缺 Git 对象的轮次、独立记忆条目和测试年龄／体积上限。删除并重建派生视图，再运行到期扫描。断言可用轮次重建一致，缺对象有缺口标识，两种上限都能触发清理，未确认数据和记忆不随历史剪裁，查询标明保留边界。
19. **U19 · U · 决定 #8 · 启动配置。** 给 TUI、OAR、恢复和切换的启动构造器注入用户启用记忆的配置。断言 Claude 实际子进程启动设置指定 env，Codex 三项有效覆盖均为 false，agy 报未覆盖，OpenCode 报无需关闭，`CLAUDE.md` 和 `AGENTS.md` 仍可加载。仅确认构造参数，实际生效由 L01–L04 验收。

## I · 真实 loomd

20. **I01 · I · 决定 #2、#5、#6 · 权威存储及候选链。** 使用 home 和 cell 两个 loomd 启动绑定的 Worker、Leader 和 Auditor。Worker 通过 CLI 提案，Leader 或 Auditor 在结卡审查，重启两端后执行 `search` 与 `show`。断言唯一正式修订在 home 外置 Markdown 目录，cell 不拥有正式修订，repo 无 ID 或原始历史文件。再用单进程模式跑同一断言。**v0 部分**覆盖本地 Markdown、CLI 搜索和角色启动索引，覆盖范围不含双进程、授权或晋升。
21. **I02 · I · 决定 #2、#6 · CAS 冲突与 home 重启。** 两客户端读同一修订，屏障放行两次改写，在获胜提交落盘但未 ACK 时杀 home。重启后用相同 ID 重试并提交落败请求。断言只加一个修订，获胜者取回原回执，落败者收到冲突且可重读，索引 seq 与持久条目一致。
22. **I03 · I · 决定 #2、#4、#6 · 离线、撤权及候选重放。** 同步项目与跨项目缓存后断开 home，在 cell 多次读取和提案。让一项授权过期，另一项在 home 撤销。重连并重启 cell，再读并重放 outbox。断言缓存注明 seq／时间，过期即隐藏，重连先落实撤权，获准提案以原 ID 至多导入一次且仍须审查，拒绝的提案不生效。
23. **I04 · I · 决定 #3 · 继任、切换和压缩。** 给受管会话注入初始索引，修改一条、遗忘一条，交付业务消息，依次触发换班、CLI switch 和模拟的原生压缩边界。断言老会话前缀不变，增量附在正文后且只发送应有批次，新一轮重新取得当前获准快照，压缩前仅提醒、压缩后才补注入。原生边界实测见 L06。
24. **I05 · I · 决定 #4、#7 · 查询入口一致。** 两个项目各生成共享、私有与 Worker 轮次，设置跨项目授权和 Worker 依赖。用 `hist` 的会话地址、角色、搜索、分页及证据详情查询，同时查询记忆。断言每种入口都用同一权限，分页总量和详情不泄露隐藏材料，授权结果标来源项目与截止时间。
25. **I06 · I · 决定 #5 · 路径升级及迁移。** 用临时目录登记无 Git 项目并写一条记忆和历史，在原处初始化 Git 后再移动路径。先不确认，再由 Super 执行 `loom project move`。断言一对一升级保留 ID，移动先保留 orphan 并给建议，确认后新绑定可读原有数据，仓库中无项目 ID。
26. **I07 · I · 决定 #7 · 半行、重复发运、偏移。** 向 cell 绑定的 JSONL 写一整行加一截半行，flush 并记录 ACK。补齐半行，重复发送第一批并从旧检查点重扫。断言半行不入 home、不推进偏移，补全后每行只入一次，raw 字节及连续 ACK 与源一致。
27. **I08 · I · 决定 #7 · 发运途中杀 cell。** 用故障点分别在 home 写前和写后但 cell 保存检查点前杀进程。重启 cell 并补发。断言 home 最终有且只有一份完整原件，cell 不越过确认范围，发布 ID 和 DONE 均无重复。
28. **I09 · I · 决定 #7 · home 重启和顺序。** cell 已观察到轮末，分别在 home raw 落盘前后杀 home。记录证据归档和收件箱边沿，重启并继续。断言只在 home 持久 ACK 完整范围后第一次公开证据卡／DONE，重放不重复。单 Mac 单进程用同一故障顺序复验。
29. **I10 · I · 决定 #7 · 先确认再清理。** 让 Worker 结束后阻断最后一批 raw 的 ACK，随后请求 teardown 并重启 cell。断言 worktree、日志及采集检查点仍可读取且显示待清理。解除阻断后补发、确认，再清理已登记的该 Worker 路径，其他文件保留。
30. **I11 · I · 决定 #6、#7 · 在线 flush 与离线答复。** 建立仍在运行的会话，先令 cell 按查询屏障及时发送，再用门控模拟在线超时和掉线。断言在线返回屏障范围，慢或离线时在配置上限内返回此前落盘范围且注明 as-of 与运行态。恢复后截止时间前进并可查到遗漏行。
31. **I12 · I · 决定 #7 · 限定的批量追赶。** 构造缺尾部的 Loom 管理文件、非管理文件和 home 独有文件。执行批量追赶和退出扫描并记录 rsync 参数。断言只扫 Loom 管理文件，只用 `--append-verify`，没有 `--delete` 或活动 DB 副本，补传内容需经完整行与范围校验才取得 ACK。正常逐行发运不调用 rsync。

## L · 原生 CLI

每个场景保存版本、启动模式、配置生效证据和脱敏回执。用本地模拟端点验证协议时只判断可观测配置和注入。模型行为用例需要真实推理，优先用可用的免费端点，凭据不进入夹具或记录。同一秒产生的文件和消息按 ID、偏移或受控事件次序判断。

32. **L01 · L · 决定 #8 · Claude TUI 及 OAR。** 用原生绝对路径，在相同版本的隔离 HOME 放入合成原生记忆和 `CLAUDE.md` 指令探针。运行启用基线及 Loom 禁用路径。TUI 观察 `/memory` 生效状态，OAR 核对实际进程 env 和本地端点收到的握手及首轮。断言禁用时请求不带原生记忆探针，启用对照能检出它，指令探针仍加载，捕获证据能归到所测版本与会话。
33. **L02 · L · 决定 #8 · Codex TUI 及 OAR。** 为同一原生版本准备三项开启的合成用户配置和原生记忆探针，用 TUI argv 覆盖及 OAR app-server/thread 配置各启动一次。捕获 TUI 生效状态、app-server `config/read` 与线程启动或恢复握手，必要时核对首轮请求。断言三项都关，进程级读回与实际线程覆盖相符，无原生探针注入，`AGENTS.md` 仍加载。未获得生效证据记为未验证，不能仅用 argv 判通过。
34. **L03 · L · 决定 #8 · agy 的覆盖边界。** 用绝对原生路径和隔离应用目录读取当前版本配置及 ACP 握手。记录可观察的有效设置。若版本没有可验证的长时记忆开关，断言覆盖报告保留 `not covered`；若出现新开关，先用启用／禁用对照证明实际生效再更新覆盖。避免触发需要账号的步骤。
35. **L04 · L · 决定 #7、#8 · OpenCode 导出及覆盖边界。** 在隔离 XDG 的原生 standalone 会话生成合成记录，保持会话活动，分别查询导出/API 并重复读取。断言 home 有对应完整记录及更新，采集未复制活动 SQLite，结果标有会话状态及水位。原生记忆开关按 L03 的证据门槛报告覆盖，独立服务或压缩配置本身不计作关闭。
36. **L05 · L · 决定 #1、#3、#4、#8 · 记忆的因果对照及换 CLI。** 用已验证关闭原生记忆的两个 CLI、同一项目绑定、四个空白新会话。准备一条含随机值的合成事实，工作树和问题里都没有该值。依次让条目生效、遗忘、经授权重建、换另一 CLI。每阶段问同一句，并核对有效索引、按需读取和根轮引用。断言结果依次为正确引用当前 ID、答未知且无旧 ID、正确引用重建后的 ID、切换 CLI 后仍正确引用。缺少可用真实推理时记未运行，本地固定假回复不能证明这项因果关系。
37. **L06 · L · 决定 #2、#3 · 原生压缩和注入成本。** 为每个可观察压缩边界的版本准备无记忆对照、近 400 tokens 的启动索引及 31 条会中变化。用同一有效模型和业务正文走启动、普通交付、增量、原生压缩及压缩后交付。断言可观测时预压缩提醒一次、压缩后补注入当前索引，后缀至多 30 条且标截断。记录发送的索引和增量 token、输入总量、缓存命中量与对照差值，区分估算和原生计量。没有可归属的原生边界时记录缺口。
