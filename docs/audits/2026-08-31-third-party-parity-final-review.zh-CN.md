# Raft ↔ RAH OS 第三方对照审计：主审最终结论

## 裁决

**不能签署“核心页面、鼠标行为与 Raft 已一致”，也不能签署“正式版本已经可交付”。** 本轮取得真实反例，不是单纯缺少截图：Activity 存在两条未读时没有导航粉点；Computer 状态取错数据来源；工作区刷新会折叠目录；另发现正式静态资源被普通构建覆盖、导致新开页面要求 Human token 的交付问题。

已有功能并非全无效：头像悬停/Escape/点击侧栏、姓名插入提及、本地 Room/DM/Thread Enter、InputRequest 取消与回答生命周期、全局 Activity 精确打开 Thread，均通过下述限定实测。不能用这些通过项抵销其他失败项，也不计算未经完整枚举的“全站一致率”。

本轮只审计，新增报告/证据并纠正文档；没有修复产品代码、提交、重启正式服务或调用付费 CLI。发现的问题按后续修复优先级列出。未确认 P0 安全或数据完整性缺陷，不等于完成安全认证。

3. [双边真实浏览器审计](./2026-08-31-third-party-bilateral-browser.zh-CN.md)：已登录官网与两个隔离本地环境，逐项记录动作和结果。

主审重新检查关键官方分支、本地连接/已读/导航接线及部署代码，实际查看关键截图（官方 O01–O04、本地 L03/L04/L08/L10/L11、正式 P01），归并重复问题并纠正证据边界。浏览器审计员保存且查看了全部20张截图，主审没有把自己的复看范围写成全部20张。

## 粉点、灰点不能共享一种含义

| 位置                  | Raft 官方语义及消失条件                                                                                                        | 本地现状 / 本轮证据                                                                                                                       |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Activity 左导航粉点   | 当前 Human 的进行中 Activity 未读，来自 inbox/服务器未读摘要。进入 Activity 仅因导航选中而隐藏，离开可恢复；不是自动全部已读。 | **浏览器反例：**4195处理 InputRequest 后有2条新消息，Activity未读筛选仍列出该项；切 Computer 后 Activity 无粉点。UI没有接入已有未读投影。 |
| Computer 头像灰点     | 在没有升级优先状态时，`status !== online` 显示灰色；本次 title 为“离线”。升级可让头像点变粉，而详情连接状态仍可离线。          | 本地以混合 Runtime `available` 推断连接；无CLI会显示离线，只有未配置但被发现的CLI也能显示已连接。是数据源问题，不只是配色。               |
| Computer 左导航粉点   | 机器离线、升级/版本注意事项的汇总；进入当前页隐藏，不代表修好或读完。                                                          | 本地没有对应接线。浏览器只有在线 fixture，**未双边实测**离线/升级生命周期；来源与本地缺线由代码确认。                                     |
| Room / DM / Chat 未读 | 独立频道读取水位；提及、静音、是否加入、分组折叠有不同呈现。弱灰计数不是 Computer 离线灰点。                                   | Kernel已有 Human read frontier；Room/DM行和主入口没有对应提示。逐类开关/静音生命周期尚未双边验收。                                        |
| 通知铃铛              | 系统通知集合，例如机器问题、升级、PWA等；显示/关闭不等于 dismiss。不是单纯 Human待答数量。                                     | 当前只显示 pending InputRequest 数字。通知1→打开/取消仍1→回答后0已实测通过；不能称全通知中心与Raft一致。                                  |

外观测量：官方 Activity 粉点10×10 CSS px、`rgb(254,125,168)`、黑边；官方 Computer 灰点10×10、`oklch(0.707 0.022 261.325)`、title“离线”。本地在线绿点9×9、向右偏1px且无独立title；由于状态不同，**不能把灰与绿的颜色不同当成同状态配色失败**。本地通知的16×16数字badge也不是同一种10px状态点。

本轮确认的状态链为：

`待答InputRequest=1 → 打开/取消仍1 → 提交回答=0 → Worker产生回复 → Activity未读=2 → 切其他页无粉点（失败） → 打开具体Thread → 未读为空（该读取路径通过）`

因此“看过”“已读”“处理完通知”“Activity done”“Task完成”“回答InputRequest”必须分开；不能统一在点击入口时清零。

## 按优先级修复的缺口

### P1-R0：普通验证构建覆盖正式资产，影响新开页面【交付阻断】

**这是主审在第三方浏览器发现之上新增核实的问题，也需要纠正我上一轮的交付说明。** 正式4173新页实际显示 Human access token 连接表单，不能按用户预期直接进入本机工作台。`/_rah/health` 返回 online 只证明进程活着，不证明产品入口可用。

证据链：

1. 浏览器 P01 与磁盘 `apps/web/dist/index.html` 都指向 `/assets/index-CX0OnzN3.js`。
2. [启动脚本](../../scripts/run-local-workbench.mjs:13)将生产静态目录直接设为仓库 `apps/web/dist`。
3. [静态网关](../../packages/daemon/src/local-workbench-gateway.ts:244)在每次请求从当前目录读取文件，不冻结启动时版本。
4. [Vite配置](../../apps/web/vite.config.ts:6)仅在 `RAH_WEB_TRUSTED_PROXY_AUTH=1` 或带开发token的serve环境下编译可信代理模式；[App](../../apps/web/src/App.tsx:134)据此决定是否直接创建同源客户端。
5. 普通 `npm run build:web` 和带flag的 `build:web:workbench` 写入同一个dist。上一轮我运行了普通构建作为门禁，覆盖了运行服务正在读取的资产。

所以“未重启，因此正式页面未受影响/代码只是待部署”不成立。**我此前这项说明有误。** 本轮保留现场，未读取用户token、未绕过认证、未再构建或擅自重启。既有已加载标签页可能仍保留旧代码，本轮未验证其全部状态，不能推断全部用户会话都失效。

最小修复顺序：先在获准修复时恢复正确可信代理产品构建；再把验证输出和正式产物分开，正式服务引用版本化只读资产目录，显式部署时切换。新开页验收必须同时核对资产版本、认证模式和登录后主页面，不能仅看health或进程PID。并发执行两种构建也不能成为隐式部署。

### P1-R1：Computer在线、Runtime就绪与Agent启停混为一谈【真实缺陷】

[Computer组件](../../apps/web/src/components/workspace-catalog-panes.tsx:34)使用 `runtimes.some(available)`；inventory混合配置/Offer可用性与仅找到可执行文件的 discovered结果。[App](../../apps/web/src/App.tsx:352)只在client变化时加载此目录，后续Host/Offer状态也不会及时刷新。列表里的Agent绑定统一绿色“在线”，资料头像也可能在“已暂停”文字旁仍绿色。

独立SSR已经执行原组件证实两种错误输入；本轮没有故意停止正式Host做心跳实验。应由现有Kernel Host状态、lastSeenAt及Agent状态提供授权且有新鲜度的Computer读模型，Runtime readiness另列。不能改成无CLI就离线，也不能直接相信过期的persisted online字符串。

### P1-R2：已有持久未读，导航与侧栏不显示【真实缺陷 / 浏览器反例】

不是要再造通知数据库。[HumanActivity owner](../../packages/kernel/src/human-activity.ts:55)已经计算非本人消息、read_seq、done_seq；`activity.list({filter:'unread',limit:1}).total`可提供全范围“是否有未读”，不是只数已加载第一页。先将此读模型接入Activity粉点，再在同一owner补Room/DM/提及所需轻量摘要。

验收必须包含：非当前对话收到消息、进入Activity仅隐藏点、离开恢复、看到具体消息后按水位清读、又来新消息重新出现。不能用运输ack、Task状态、待答数量代替Human阅读。

### P1-R3：Notifications仍只是待答InputRequest【合同覆盖缺口】

已验证的pending交互可保留。需要在同一通知呈现层区分系统注意事项与“需要你回答”，使用各自owner与稳定身份；本机无计费/中央账号的类型明确排除，不复制无意义的Raft云端通知。查看、关闭、dismiss、提交回答不能共用一个删除动作。官网本轮只有空通知，非空关闭/dismiss属于源码确认，仍需双边样本。

### P1-R4：全局Activity点击晚返回可能强行拉回旧页面【函数反例】

[global-discovery](../../apps/web/src/components/global-discovery.tsx:703)等待 `message.context` 后无导航generation校验，仍调用打开旧位置；[App](../../apps/web/src/App.tsx:212)会强制切回Room。审计员运行抽出的原mark函数，以受控Promise证明“点Activity→先去设置→旧请求完成→跳回Room”。这是函数级反例，**未在真实浏览器限速下复现**。修复应复用导航身份/epoch与Abort，读取状态更新和导航结果分离；不能把已有查询hook的取消能力算给这条独立请求。

### P1-R5：Agent动态只有来源Room，缺精确任务/消息列target【合同覆盖缺口】

官网本轮点击动态中的 `#channel:shortid` 能定位完整消息并打开对应Thread。本地Agent动态只显示Run所属“对话”；这不一定是工具实际操作的目标。[Agent动态组件](../../apps/web/src/components/agent-directory-pane.tsx:1607)尚无等效resolver。

本地**全局Activity**精确打开Thread已经实测通过，是另一个入口，不能拿它补算Agent动态。最小改造应沿Raft“引用候选→授权目录/context→稳定ID→过期导航校验”，复用现有消息context，不把任意日志文字升级为业务状态或授权。

### P2：文件树、资料与布局仍有差距

- 工作区本地能列目录/看文本/显示隐藏文件/把HTML当文本；刷新后展开状态丢失已实测。选中文件是黄色且无官方2px右边，拖宽/复制反馈复位/compact返回仍有缺口。
- 官方Computer离线导致非空文件树未双边验证。这不阻碍本机按冻结合同开发，也不意味着需要依赖Raft中央服务器。
- Agent“编辑角色”官方存在，本地仅角色说明且禁止Agent管理员。这是明确的权限产品差异，需先作安全/产品裁决，不能用人设编辑充当角色管理，也不能为外观一致擅自扩大ACL。
- Computer缺完整OS/名称描述/创建者/心跳等信息；Agent restart/reset、报告问题仍disabled，“已创建Agent”计数投影未接。CLI安装与账号配置不属于缺口，仍由用户负责。
- hover卡片主要信息类别与入口通过，不代表所有字段、权限、长内容排版和鼠标边界已完全对齐。

## 旧合同需要纠正，避免修错方向

1. **Computer不是无条件自动首选。** 官网rail可恢复记忆详情；直接访问`/computers`本轮显示未选择空态。本地首选可作为明确产品选择，不应标为无条件复制官方。
2. **头像点击的默认tab受配置顺序影响。** 当前账号确实打开动态；源代码不是永远硬编码动态。用户已明确要求本地头像点击默认动态，保留此产品要求，不因源码默认顺序包含资料就自动改回。
3. **不是所有用户都能看管理诊断。** 官网hover操作信息/轨迹取决于manageAgents或Agent创建者等条件；不要为补卡片绕过本地管理授权。公开身份摘要与受保护资料分开。
4. **Agent Chat中的Agent-to-Agent DM是活动摘要，不自动授权Human进入。** 不能看到入口就推导所有私聊可读。
5. **Raft文件树并不具备完整请求竞态保护。** 部分根/子目录成功响应检查Agent身份，但同Agent代次、错误/finally、文件选择的晚返回不全；旧预览是被loading遮住而非清空。移植可见行为时应保留本地更可靠的取消/身份保护。
6. **不把官方缺少的a11y当目标。** 官方该角色说明弹层有Escape/backdrop/初始focus，但未见完整Tab trap/还原焦点；本地更强的键盘保护可作为明确增益保留。Enter发送、Shift+Enter换行仍遵守用户裁决。
