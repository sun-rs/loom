## 单一 owner 与实现

- Kernel `task-history-projection` 在现有冻结分页和权限边界内，补充
  `previousWorkflowStatus` 与事件当时的 `workflowStatus`。优先使用事件保存的前后值，
  旧事件依据前一条明确的 canonical Task 状态操作恢复；不读取当前 Task 状态代替历史，
  不读取 Provider 输出，不改变持久事件。Protocol 增加可选字段，共享 Worker 读接口保持兼容。
- UI `task-history-presentation` 只把创建、负责人、状态和任务编辑映射为操作时间线，
  每页按 Room seq 升序；保留50条的有界分页及较早/较新入口。进度/提交摘要不作为
  历史正文展示，底层 Worker 完整记录仍保留；认领同时改变负责人和状态时分别展示。
- 使用12px圆点、12px内容间距、16px条目间隔、细竖线、灰色12px元数据和彩色状态标签。
  当前页之外的历史继续分页读取，不伪造未加载的记录。
- Task 负责人从 `activeMemberIds` 过滤候选；原 `members` 实为含频道外 Agent 的已知
  身份集合，仍保留它解析历史作者，不再用它单独决定候选资格。后端既有
  `human-task-edit` 的 `requireRoomMember` 仍为最终权限检查，不使用消息列关注者名单。
- Task 弹窗初次载入回复后滚至最新，复用 Thread 的滚动容器；不因后台轮询反复跳底，
  不影响用户向上阅读历史。外部根消息定位不覆盖 Task 弹窗的初始位置。
