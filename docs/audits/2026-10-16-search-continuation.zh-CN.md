# 搜索追加加载、键盘与浮层预览

本批以已取得的官方 v1.21.16 发布文件为锚点，继续复用 `frontends/raft`，不改变后端或冻结官方源文件。授权、URL、发布提交与 SHA256 沿用[发布代码证据](../evo/evidence/2026-10-16-native-topbar/upstream.json)；负责人授权非商用复用，原许可证与声明保留。

## 来源与落点

- 官方快照 `MessageSearchPage.tsx` 的加载更多 footer（2580–2610 行），与发布 JS 对应 footer 一致：结构移植为 `SearchLoadMore.tsx`，保留 Button 参数、错误框 class 和翻译键；不是逐字复制整个页面。
- 官方 selectableResults／handleRailKeyDown（1592–1720 行）：`useSearchRail` 接通完整搜索页，鼠标与键盘共享结果身份；选中项追加后保持，键盘只作用于搜索区域，详情 composer 和筛选控件保留自己的行为。修复浮层首行向上会错误跳入消息的问题。
- 官方 `OVERLAY_MESSAGE_PREVIEW_LIMIT = 5` 与发布 JS `eSt = 5`／`Jt = e ? eSt : Infinity`：浮层只显示五条预览，不显示加载更多；完整页保留全部已加载结果。
- `search-pages.ts` 是 Loom 本地数据适配：使用现有服务端 cursor，追加时按稳定消息 ID 去重，不建立第二套服务端分页状态。单窗口最多200条，达到上限提示缩小范围，不伪造服务端已经结束。读取失败保留已有结果，重试原 cursor；查询／筛选变更与卸载会取消未完成请求。

## 验证

先确认新增追加单测因缺少实现失败、浏览器因缺少“加载更多”失败；再实现并验证。浮层20条而非5条、首行向上选择错误均先由浏览器复现。检查限于搜索／动态定位和顶栏专项、来源适配测试、前端类型与构建，不运行全仓或付费 CLI。

隔离 Core 的1440×1000与390×844覆盖：追加40条、追加失败保留20条、重试去重、上下键／Enter定位、线程分组、旧消息定位、动态完成精确 frontier 与新消息重新出现，以及桌面详情／手机导航。顶栏专项覆盖五条预览、首行上边界、筛选菜单、IME、关闭、原页面草稿和响应式切换。部署与真实页面结果记录在[本批证据](../evo/evidence/2026-10-16-search-continuation/summary.json)。

## 动态页核对与剩余边界

官方 `ThreadsInbox.tsx` 有独立 doneItems／doneLoading／doneHasMore 集合与恢复操作；Loom `HumanActivityRequestSchema` 目前仅 all／unread／mentions，没有已完成集合查询。因此“完成此条动态”已有真实能力，但“已完成”页面不能由浏览器缓存或全量抓取模拟。本批保持后端冻结，不新增假入口；这项需单独的后端能力决策。

搜索实体候选（频道／实例）、最近访问与可拖动浮层仍未接入。动态精确来源返回及菜单仍有待逐项对照的路径；本批通过的是现有消息定位与返回，不宣称整页完全等同官方。下一批优先实体候选的原生排序、匹配与跳转闭环，再整理动态原生交互可接与缺后端的清单。
