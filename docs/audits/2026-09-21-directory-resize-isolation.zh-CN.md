## 源码依据与单一 owner

沿用[前一批](2026-09-20-resize-render-isolation.zh-CN.md) Raft W0/Tft 的局部宽度和拖动结束保存策略，版本、SHA 和 Multica 对照记录仍有效。
文件树参考[工作区源码合同](2026-09-17-agent-workspace-surface.zh-CN.md)：Raft v1.16.0，AgentDetailPanel-CW_VMZT6.js，SHA256 `918921bbb932ed020285d2f3639c0a5511249f4bca1d2468628da995078a37e3`。
这些发布物仅分析，不复制或分发 bundle。本次是本地所有权提取，非逐字移植 Raft，未引入新第三方代码。

`DirectoryWidthLayout` 只持有宽度及 CSS 变量，稳定 children 保留正文、选择、文件预览和查询 owner。
`DirectoryWidthResizer` 只订阅该局部状态；原事件逻辑收归 ui-web `usePanelResize`，原 `PanelResizer` 也使用同一 hook。
保留各家 DOM/CSS，避免把文件树的相对定位换成全高侧栏定位。
成员180–320/默认240、8px键步及Shift32；Computer继续使用原尺寸/保存 owner；文件树160–600/默认256、16px键步。
Computer仅在结束/键盘操作保存，成员和文件树不新增持久化。
捕获取消和丢失统一清理，避免取消后继续改变宽度；没有拖动节流或额外导航状态。

## TDD 和验收

先记录测量，再执行失败断言：成员40步拖动84次内容渲染，超过允许异步更新的8次阈值。
实现后成员/Computer拖动0次，文件树0–2次；一次采样脚本耗时约197→22ms、140→19ms、122→39ms。
时间受开发模式和轮询影响，非帧率保证；性能断言针对重复渲染，不以机器相关耗时作为硬阈值。

- 新隔离门禁：非空任务、三处拖动、尺寸、键盘/Shift、取消、Computer reload、390×844及放大通过。
- 原 Computer/成员边栏边界门禁通过。
- 原文件工作区门禁1440/390通过：读文件、预览/原文、隐藏项、刷新、权限与失败分支。
- 搜索/动态/聊天原隔离门禁通过，共享指针 hook 无高频内容更新回归。
- 类型检查及迁移后的 owner 断言检查。
- 全仓 check 的存量 worker 接口登记缺项、format 的五文件存量问题仍另列，不放宽守卫。

没有正式业务写入、付费 CLI、提交或推送。正式构建、重启和页面证据见下方后续记录。
