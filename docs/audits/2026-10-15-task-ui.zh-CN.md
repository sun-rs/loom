# 官方任务页接入：已有任务管理与讨论

本切片接通全局任务页的看板／列表、有界分页、频道筛选、原生任务详情、Human 状态修改及讨论回复。Raft 全局任务页没有新建按钮，因此不另造创建入口。消息转任务、频道内创建、指派修改及历史展示留给后续频道任务切片；不把某种多人协作安排固化为系统流程。

来源：[Raft 官方源码](https://github.com/botiverse/raft-source/tree/a98ae003246a0360872a77d76dec2fccd0347ef7)，版本 `a98ae003246a0360872a77d76dec2fccd0347ef7`，FSL-1.1-ALv2；沿用 Owner 授权和 notices。

- **直接复用** `TasksPanel.tsx` 的 `TaskSection`／`DroppableColumn`、`TaskCard`、`VirtualizedTaskStack`／`TaskVirtualLayout`、`TaskModalHead`、`InlineBadgeEditor`、`SelectionPopover`、Modal、ThreadPanel 与 raft-ui recipes。只导出原生展示函数；显式关闭 TaskCard 的未接状态写入口，避免上游权限默认值启用失效按钮，不启动 TasksPanel 的上游 store／网络控制器。
- **结构移植** TasksPanel 标题／工具栏组合、MainLayout 的 TaskModalBar 与弹层壳、TaskProperties 属性行。弹层尺寸直接沿用原生 `min(86vh,900px)` 高、`min(960px,calc(100vw-2rem))` 宽；手机为原生整页返回结构，不压缩字体或卡片。
- **构建适配** 唯一源码边界检查后追加展示函数导出；仅 TaskModalHead 的 TaskProperties 引用替换为本地数据接线；只读 ThreadPanel 补用原生已有的 `parentSlot`／`hideParentMessage`，任务标题与来源消息不重复。磁盘中的官方组件源码不改。
- **本地所有者** Task 的状态／权限仍由 Kernel 决定；global discovery 提供任务及管理权限，`task.get` 确认 Room／Task 身份，RoomSession 管因果基准，WriteIntentSlot 管一份未决写入。ThreadWorkspace 延用已验收的 MessageSession 与线程发送链路，不创建第二个讨论队列或任务状态机。

原生看板拖动和卡片内状态编辑本批未开启，状态操作统一从已接好的任务属性入口进行；不会显示能拖动却不能保存的卡片。负责人暂为只读；创建者／负责人展示名称，不以 ID 冒充名称。创建者／指派筛选、任务历史、审核记录、修改描述及消息转任务尚未接入。列表当前按进入页面、筛选及本页面写入后刷新，不声称其他客户端变更已实时推送；详情轮询。全局页范围沿用后端 discovery，私聊任务不混入频道看板。

验收使用真实临时 Core、53项任务、双尺寸浏览器，无模型执行：分页、视图切换、原生弹层、修改状态已提交后丢失响应、同键核实、未决后退保护、讨论不改变已完成状态、刷新／关闭、跨房间拒绝和读取失败隐藏／恢复。正式数据仅只读打开既有任务，不修改用户任务，不发送验收消息。当前结果见[验收与部署证据](../evo/evidence/2026-10-15-task-ui/summary.json)。

正式截图首次检查发现 TaskCard 的上游权限默认值仍会显示编辑图标；已补先失败的适配断言和浏览器只读徽标检查，并在唯一源码边界显式关闭该入口。任务属性中的正式状态写路径保持。此前完整检查通过；此项仅前端适配修正，之后重跑前端类型、构建、源测试、完整双尺寸浏览器和正式页面验证，后端源码未变。
