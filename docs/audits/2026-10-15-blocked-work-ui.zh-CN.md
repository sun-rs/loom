# 实例阻塞处置接线

按纵向优先级，频道急停／恢复和实例启停之后，补齐原本仅在 console 的单 Activation 放弃入口。后端语义、调度、提示词与会话均不改。

来源：[Raft 官方源码](https://github.com/botiverse/raft-source/tree/a98ae003246a0360872a77d76dec2fccd0347ef7)，版本 `a98ae003246a0360872a77d76dec2fccd0347ef7`，FSL-1.1-ALv2；沿用 Owner 授权和 notices。直接复用 `components/ui/Banner.tsx`、`components/ConfirmDialog.tsx`、`components/channel/ChannelMemberList.tsx` 和 raft-ui Button，在现有原生实例动态侧栏中呈现；冻结官方源码不变。此为 Loom 特有阻塞语义的本地接线，不声称 Raft 有相同业务。

| 触发／状态                                 | 内容与所有者                                                                                                                               | 关闭／异步规则                                                                   |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------- |
| 点击聊天成员头像或成员列表的实例行进入动态 | 既有 `room.agent.activity.list` 返回选中成员的 blocked；显示原因、是否占执行通道、来源频道或私聊；没有阻塞不添加按钮                       | 成员及对话绑定不变；读取失败移除过期状态                                         |
| 处理阻塞工作                               | 原生 warning Banner 与 ConfirmDialog；确认前冻结 Activation 和实例身份                                                                     | 取消／Escape 不写入；阻塞身份变化或状态读取失败不允许首次提交                    |
| 确认放弃                                   | 既有 `instance.activation.abandon`，通过所属 Channel 的 RoomSession 和 WriteIntentSlot 提交；即使阻塞来源是私聊也使用所属 Channel 因果基准 | 未知结果保留原键／原目标核实，不静默换新目标；未决时阻止关闭与站内后退丢失所有者 |
| 成功／拒绝                                 | Kernel 决定是否可取消；仍有运行未终止会拒绝。成功刷新投影并提示发送新请求                                                                  | 不自动重跑、重发旧稿、重置 session、修改 Task；已结束 Run 保持                   |

成员列表直接使用原生 `ChannelMemberRow.onRowClick` 打开同一动态侧栏，私聊按钮仍为独立操作。没有发过回复的实例也能进入；侧栏关闭后焦点返回成员列表入口。

held 的当前恢复方式仍是显式放弃旧工作，再由 Human 在对话中发出新的请求。本批不提供旧草稿编辑／重新发表，也不自动发送恢复指引。业务义务型阻塞不占通道时如实显示，不宣称所有阻塞都会卡住其他工作。

验证区分：适配层单测验证私聊来源使用 home Channel 与未知结果冻结；临时真实 Kernel／HTTP 验证提交成功丢回复后的幂等核实，且会话／结束 Run 保持；双尺寸浏览器使用显式异常响应夹具验证确认、取消、后退、核实与空态，不伪称实际模型执行。现有 Kernel 的 held 恢复测试继续覆盖旧稿不重发和新请求续接。正式页面只读查看／取消，不放弃用户的实际阻塞工作。验收与部署见[证据](../evo/evidence/2026-10-15-blocked-work-ui/summary.json)。
