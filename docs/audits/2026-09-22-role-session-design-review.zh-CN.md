## 尚未闭合，但不必继续让用户凭空选择的问题

1. **四家 fork 能力合同**：Codex/Claude 有直接依据；Kimi/OpenCode 需要完成具体协议、持久性、截止点和认证恢复核查。Side 无原生可靠路径时不可用，不能偷偷降级为摘要。
2. **Side 记忆禁写落实**：用户后续已确认可读已授权记忆、不可写记忆。政策不再待选；剩余是验证工具、原生自动记忆、shell 和后台路径均不能绕过。
3. **真正的记忆隔离**：同 OS 用户运行 CLI 且拥有广泛 shell 权限时，单独保护 API 不够。先做不调用模型的越权文件访问实验，确认可行隔离边界，再承诺 UI 开关。
4. **身份重绑定**：恢复/fork 的旧 system prompt、动态工具、凭据及权限继承必须逐 Provider 实证。只加一句“你是 no.2”不够。
5. **读取与 freshness**：等待的公共 Agent 消息仍可能被主动读到；私聊必须不可提前读。交付窗口与新鲜度保护需联合测试，不能以冻结读取为由忽略更新事实。
6. **迁移可逆性**：旧混合 session 的权限和上下文已经含跨频道信息。fork 不会自动去除这些信息；迁移说明必须显式保留来源事实，不宣称新建架构天然洗净旧上下文。

## 施工前门槛与验收场景

建议先批准身份/调度合同，再做隔离技术验证；无需再问一轮抽象偏好，也不应现在全仓重构。

每个行为先写可失败的确定性测试，再实现。最小集合：

1. 同 Role 两个频道同时工作，instance/native ID 不同；各自关闭恢复 ID 不变。
2. 同实例连续三轮及模型/effort 修改保持 session；配置不支持时不偷偷换模型或新建。
3. 频道忙时来私聊，私聊不进入当前 turn；空闲后按 target 回复，不串发到公共频道。
4. Guide 开/关、Provider 不支持、turn 恰好结束、压缩中、重连重投：不漏义务、不重复发帖。
5. 持久 fork 新 ID、不继承任务，旧凭据不能使用；失败一半不出现有效幽灵成员。
6. Side 不通知主频道、不写共享记忆/文件；主 session 历史不增加 Side 正文。
7. session 文件丢失/认证错配/旧进程晚回：有限恢复、旧 epoch 拒写、最后等待用户重建。
8. 记忆权限绕过、并发修改、撤销后旧材料化、来源删除、长索引和无结果。
9. 频道加人不自动加消息列/task 关注；移出频道后不能继续发帖/接任务；同名身份不混淆。
10. daemon 崩溃恢复、重复 hint、私聊与频道同时排队、持续多实例负载：公平且无模型空轮询。

以上全部尚未作为新架构运行测试。完成确定性测试后，再按明确授权运行真实 CLI 和同条件 Raft/原生 CLI 项目审查。观测包含回复延迟、生成次数、未缓存输入、上下文细节保持和实际审查质量，不能只验“有回复”。
