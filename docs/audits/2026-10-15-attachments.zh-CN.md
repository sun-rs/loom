# 附件与计算机文件引用接线

Owner 本批裁定：暂缓任务描述／审核新入口；先完成附件链路。默认加号引用计算机文件，统一文件窗口内保留系统上传按钮，同机偏好置灰、异机偏好可将访问设备文件传入 Loom。路径引用与上传附件是不同操作，不把选中路径冒充成已发布 Artifact。

## 端到端行为

| 行为           | 当前接线与边界                                                                                                                                                                        |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 加号 → 文件树  | 调用 computer.files.list，后端负责授权根与路径校验。目录切换中止旧请求；读取失败清空旧内容。文件可多选，未选文件时引用当前目录。确认只插入正文，不发送、不上传。                      |
| 计算机选择     | 使用官方 Select；当前接口实际只连接本机文件浏览器，因此只列本机，不编造可用远端。远端机制继续冻结，远端选机浏览未验收。                                                               |
| 手机／平板上传 | 与桌面共用文件窗口内的系统上传入口，同机偏好置灰、异机偏好可用，不依赖屏幕宽度或输入设备判断。真实 input 支持多选，选择后清空其值；取消不上传。同一文件可再次选择。保留按钮键盘入口。 |
| 桌面上传       | 默认加号打开统一文件窗口；窗口内上传按钮调用浏览器设备的系统文件选择器。拖入、粘贴和选择文件进入同一附件草稿。                                                                        |
| 草稿           | 既有单文件上限与每条最多10个附件；空文件拒绝。上传／失败不能发送，可移除后重选。切换对话不混用草稿，内存草稿不写浏览器持久存储。刷新未发草稿不承诺恢复。                              |
| 消息           | 频道／私聊／消息列支持仅附件或正文＋附件，显式发送。未知结果保留提交，核实同一幂等键／Room seq／附件集合，不重复发表。任务创建仍不支持附件，可先发消息再转任务。                      |
| 展示与下载     | 已发表附件来自 canonical Message 投影。常见栅格图片使用官方画廊、大图与下载，文件使用原生 AttachmentChip 下载。图片资源 URL 仍走本地鉴权文件路由，未改鉴权或公开文件。                |
| 未接范围       | 复杂文档、音视频的专用预览／批注、频道文件管理页、转发、远端文件树；不以下载可用冒充上述能力完成。SVG 等非白名单图片作为文件下载。                                                    |

## 验证和保留的失败

先验证缺少上传 owner 的单测失败、旧构建缺少加号入口，再实现。旧“附件未接入”投影断言按新契约替换为 ID／名称／MIME／大小精确映射，并在旧实现上确认失败。迁入 main 的三项上传状态回归覆盖删除后晚到响应、成功提交快照及 Room／Thread 草稿隔离。

临时真实 Core 使用关闭执行的 Fake CLI；无付费或真实模型调用。桌面1440、手机390×844、平板820（DPR1，手机／平板真实 touch）验证引用路径、原生 filechooser 多选／取消、附件-only 发送、丢响应同请求核实及刷新后字节一致下载。补验同文件重选、上传失败阻止发送、消息列首次创建＋附件回复未知重放、私聊附件不进入频道、官方图片画廊／大图。

初轮错误保留：文件树错误使用无 Dialog 根的子组件，改回完整官方 Dialog；透明 input 被按钮图标层挡住，真实 tap 回归先失败后修复；夹具最初在初始读取未完成时直接 setInputFiles，改为先通过真实控件可操作性检查；夹具读取刚发送图片前未等待消息落地，改为等待实际消息再核验。失败未通过放宽业务断言掩盖。

截图与完整检查、WebKit 和正式只读页面的最终结果见[验收记录](../evo/evidence/2026-10-15-attachments/summary.json)。浏览器 filechooser 自动化不等于 iOS 真机系统菜单验收。正式服务不发送测试附件；业务写入只在临时状态中验收。

## 文件选择器布局修正

官方同一版本 packages/web/src/components/agent/AgentWorkspace.tsx 的 TreeNode 是 Agent 工作区浏览器：递归展开目录、单文件预览，依赖 Raft Agent API。已审阅其树区域独立滚动和目录状态处理；本次没有复制或改写该模块。加号选择器仍是 main 路径引用语义与官方 Dialog／Select／SelectionPopover 的本地组合，不宣称它是官方现成文件树。

上一级置于列表第一行，授权根处禁用；隐藏文件开关移到列表下方。列表保持 256px 浏览区域（沿用官方 max-h-64），弹窗使用本地组合最小尺寸 512px、受 80dvh 限制；小视口正文滚动，页脚仍可操作。这两个组合尺寸不是从官方文件选择器提取的规格。多文件、两个文件、空目录均保持弹窗与列表高度，空目录仍可引用当前文件夹。

文件树读取 Loom 所在计算机的授权路径；上传读取当前浏览器设备经用户选择的文件并传入 Loom 附件存储。LAN 客户端上传不依赖远端 AgentHost 浏览能力，也不表示任意计算机文件树已经开放。本批不改变权限、后端或跨机执行协议。

回归测试 scripts/official-web/attachments-browser.mjs 先在旧版复现失败，再覆盖三种目录规模、根目录禁用、返回、控件上下顺序、三种视口和桌面／触屏系统选择器；原附件发送、未知结果核实和重新加载后下载字节校验保留。

## 导航加载修正与多机入口建议

上一批只测试目录切换完成后的几何尺寸，漏掉了请求进行中的 UI。原 ComputerFiles 每次请求调用 setData(undefined)，连同主机／路径／列表一起卸载，产生闪烁。该批曾保留最近一次成功显示的完整视图，读取期间局部提示且禁用旧内容引用（已被下方 Owner 批准的“只保留导航、清空文件列表”方案取代）；成功后一次替换，失败保留视图与重试，10秒超时终止该请求的前端等待，迟到结果不得覆盖。取消会中止读取。不增加目录内容缓存或放宽后端授权校验。DialogBody 改为内容驱动，不再填满人为固定高度；按钮与隐藏文件开关之间回归官方间距。计算机标签改称 Loom 主机，避免与浏览器设备混淆。

正式只读 API 抽样：初始目录17ms、上一级3ms、根目录6ms。该样本未复现用户报告的长延迟，不能证明所有目录都快，也不能把闪烁问题等同于服务端性能问题；本批修复明确存在的卸载闪烁及无界 UI 等待，保留后端逐路径权限检查。

此处为此前待 Owner 选择的提案，已被下方统一窗口裁定取代：不按 localhost、屏幕尺寸或指针类型隐藏功能。建议仅保留一个＋，内含“引用计算机文件”和“上传此设备文件”，减少常驻图标；这不是已实现的菜单。上传即使同机仍有保存文件快照的用途，应降级为次级入口而非删除能力。旧 main 的 loopback 偏好不能作为设备身份或访问权限证明。

未来设计（提案，不修改当前目标合同、不解除远端机制冻结）：

- 区分浏览器设备、Core／daemon 服务主机、Instance 执行主机。Role 定义与配置不代表文件位置；由 Instance 的执行主机决定本地可读路径。
- 计算机引用应由 protocol 承载来源 hostId、授权根与相对路径，显示计算机名称及可读路径；当前仅插入裸绝对路径的文本不具备跨主机定位能力。前端不创造另一套授权状态。
- 同机实例按既有执行权限读取；其他主机不能直接解释为自己的同名路径。明确选择共享文件快照时复用既有 RoomFiles／Kernel 附件权限与 Worker 下载契约；AgentHost 负责执行机上的保存路径。下载完成和可读验证前不能宣称文件已可用。后续自动传输应由 Loom／AgentHost 在模型执行前完成路径解析与可读验证，不要求模型反复猜路径或搬文件；仅交付必要引用，不把整个目录正文自动注入模型上下文。
- 上传始终来自浏览器设备，经用户系统选择进入频道附件存储；浏览器不提供真实本地绝对路径，不能据文件名反推出源路径。多机权限按频道成员／实例及既有 Worker 凭证判定，不按 Role 名称共享权限。
- 目录引用代表工作位置，不默认打包整个目录、自动同步或复制项目。跨机工作目录挂载／同步、主机身份引用和远端传输须作为独立纵向能力验收；现在不新增其 API。
- 文件选择器保留位置说明、稳定单列目录、上一级、明确选择动作及取消。单主机时主机位置可呈现为说明而非只有一项的下拉；多主机时再提供真实可用计算机选择。文件搜索／路径面包屑可后续按需求增强，不把完整 Workspace 预览页搬进 composer。

参考：官方 [VS Code Remote SSH](https://code.visualstudio.com/docs/remote/ssh) 区分本地与远端工作区；[Chat context](https://code.visualstudio.com/docs/chat/copilot-chat-context) 支持文件／目录上下文引用；[Slack 添加文件](https://slack.com/help/articles/201330736-Add-files-to-Slack) 展示上传与分享流程；[MDN file input](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/input/file) 说明浏览器不暴露真实路径。以上用于比较和方案推导，不代表当前窗口是这些产品的复制，也不能据此宣称所有主流产品采用相同界面。

## Owner 批准统一窗口后的实现

2026-10-15 Owner 批准并排模拟图：同机和异机使用同一窗口，同机上传按钮灰色而不隐藏；删除“文件来自所选计算机”说明。此前“统一＋菜单”提案作废，采用＋直接开统一窗口。ComposerFiles 不再常驻回形针，DeviceFileUpload 在 DialogFooter 中复用官方 Button 和原生多文件 input，取消不关闭窗口、不上传；非空选择进入原 FileUploadStore 并关闭窗口。移动端响应式换行，不缩小按钮。

按 Owner 最新裁定，导航保留的是计算机／路径／上一级／底部操作，文件列表在 pending/error 时清空，不再保留旧文件行。固定上一级使用官方 SelectionPopover 的单项行，与下方文件滚动区分离；两者通过官方 Card 组合，不改官方源码。回归明确检查慢请求期间父行 DOM 身份保持、旧文件行不存在、滚动不带走父行、超时后重试和三尺寸布局。

普通 Web 的物理同机无法可靠证明。实现使用准确回环主机名匹配作为默认偏好，不把 mac-studio.local、LAN IP 或 localhost.example.com 当成回环；URL fileDevice=local／remote 显式覆盖并在当前标签页 sessionStorage 保存。它只控制上传入口，不是权限／设备认证。端口转发需选 remote，同机 LAN 地址可选 local；默认未覆盖时上述情况会呈现与真实物理位置不一致的状态，此限制保留。远端计算机文件树和跨主机文件引用身份仍未实现。

原生 input 保留在上传按钮触点上层，真实 pointer/tap 调用当前浏览器系统选择器；不读取设备真实绝对路径，不从主机树上传。Task mode、发送中、同机偏好同时阻止按钮和 change 回调；已有拖放／粘贴未撤销。本批没有后端、调度、模型上下文变更或付费 CLI 调用。

验证中保留一次测试选择器错误：可访问窗口名称已随模拟图改为“引用文件或文件夹”，旧浏览器脚本仍查“引用计算机文件或文件夹”而超时；按真实可访问标题修正脚本，未放宽业务断言。

## 隐藏文件勾选框修复

回归先确认旧实现缺少官方 checkbox 标记而失败；修改后检查刷新再打开、未选中／选中状态、点击标签、键盘空格、两次 computer.files.list 的 includeHidden true／false，以及原文件引用、上传和目录导航链路。布局检查改为测量实际可见的 role=checkbox 控件，不测量组件内部隐藏表单 input。Chromium 与 WebKit 覆盖桌面1440、手机390和平板820；正式页面证据见[勾选框修复](../evo/evidence/2026-10-15-file-checkbox/summary.json)。无后端或付费模型变化。
