# 频道消息列接线

按既定纵向顺序，先完成频道消息打开消息列、分页读取、回复、关闭／手机返回及刷新恢复。后端线程、调度、会话与模型提示词不变；下一项是任务页，不新增协作工作流。

来源：[Raft 官方源码](https://github.com/botiverse/raft-source/tree/a98ae003246a0360872a77d76dec2fccd0347ef7)，版本 `a98ae003246a0360872a77d76dec2fccd0347ef7`，FSL-1.1-ALv2；沿用 Owner 授权与 notices。磁盘中的官方组件源码保持原摘要。

- 直接复用 `ThreadPanel.tsx` 的 `ReadOnlyThreadPanel`、`MessageTimeline`、`ThreadRepliesBadge`、`MessageInput`、`useResizablePanel`、`panelBounds` 及原生 `thread-layout-container` CSS。不启用上游账户、消息 store 或 API。
- 结构移植 `MainLayout.tsx` 的 `ThreadPanelWrapper`；默认400、最小360和动态上限直接取原常量，桌面／手机显示由原生 CSS 决定。`ThreadToolbar.tsx` 是 `MessageHoverToolbar` 的已接入回复按钮子集，沿用相同 recipe、图标、字号与 hover 参数，非完整原样复制。
- 构建期适配通过唯一源码边界检查：只读消息投影启用调用方提供的线程入口／原生手机点击；只读 ThreadPanel 加调用方 footer 插槽；读取失败隐藏旧父消息，保留原生 warning 与输入框所有者。其余反应、收藏、右键、Task 等未接操作继续隐藏。
- `MessageInput` 原生触屏竖屏 Enter 换行与 Loom 工程约定不同。本地 `onSendOverride` 路径统一 Enter 发送，保留 Shift+Enter 换行、IME 确认不发送；原始官方实现及非 Loom 发送路径不改。这是明确的合同适配，不宣称该键盘规则与上游一致。

| 入口／状态                               | 内容与单一所有者                                                                                                                   | 关闭、键盘与异步规则                                                                                         |
| ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 频道消息悬停回复／触屏点击／已有回复徽标 | 官方 MessageItem 和 ThreadRepliesBadge；本地仅提供 root Message ID 与 Kernel 元数据；已有消息列根消息使用官方 standalone 分组      | URL 保留 room 与 thread 根消息 ID，刷新重新校验房间／根消息归属；私聊本批不开放线程入口                      |
| 打开／空态／历史                         | `message.context` 校验父消息，`thread.list` 读元数据；MessageSession 独占回复游标，每页50、每次最多2页同步，沿用原生滚动与更早分页 | 打开不创建线程、不新增关注、不标记线程已读。只读失败隐藏旧正文，原输入不丢；恢复后重新读取                   |
| 首次回复                                 | 第一次发送时通过 WriteIntentSlot 调用 `thread.create`，确认成功后提交同一份正文到 `thread.reply`；RoomSession 提供因果基准         | 创建或回复结果未知时，各自保留原目标、原键、原基准；显式核实后接续原发送 Promise，不恢复成新的可重复发送草稿 |
| 后续回复                                 | 既有 `thread.reply`；Kernel 保持权限、归档、提及、关注与调度语义                                                                   | 未决时阻止关闭和站内后退卸载；已知拒绝由原生 composer 恢复正文；不自动换键重试                               |
| 关闭／手机返回／调宽                     | 原生 ThreadPanel Header、侧栏 CSS 与 resize hook                                                                                   | Escape 在无菜单／对话框时关闭；未知结果保持原输入所有者。线程与频道草稿使用不同稳定键                        |

边界：线程关注管理、独立未读／阅读位置、线程搜索、附件和消息反应尚未接入；不显示虚构未读数字。`thread.list` 是既有未分页元数据接口，长回复正文仍严格有界；大量线程元数据的性能未在此批验收。任务页尚未接入，console 保留。不同窗口同时首次创建同一消息列时，Kernel 冲突是已知拒绝，保留原稿，刷新发现既有线程后由用户重新发送，不自动重写请求。

测试先验证创建／回复丢失响应的冻结请求和跨房间拒绝，再补真实临时 Core 双尺寸浏览器。触屏 Enter 与读取失败保留旧父框均保留先失败后修正记录。浏览器不执行模型：验证桌面拖动、真实触屏点击、IME／Shift／Enter、两个写入分别丢响应后的幂等核实、站内后退阻止卸载、读取失败仍可核实原请求、已发草稿清空、刷新、56条回复分页及跨房间拒绝。正式服务仅只读打开既有线程，不在用户频道发测试消息。
