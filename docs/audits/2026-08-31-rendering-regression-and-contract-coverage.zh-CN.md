## 2. 闪动根因与修复

owner：`apps/web/src/components/message-markdown.tsx`。之前 `MessageMarkdown` 每次 render 都创建新的 `components.a/img/pre/code/table` 函数。React 将它们视为新的组件类型，卸载并重建整段内容，包括 Mermaid 的 sandbox iframe、图片、高亮结果和源码/图表选择。

状态轮询和虚拟列表尺寸重测会触发上层 render。新 presence 读取前台每秒更新，使旧的组件身份缺陷更容易暴露。图表/图片反复从占位到完整尺寸也扰动虚拟行测量；用户截图中的覆盖现象与这一链路相符，但本轮独立夹具没有稳定重现一次单独的重叠断言失败，不把推断写成独立复现。

浏览器原页先后读取到同一图表的 `aria-labelledby` 为 `_r_2g4_`、`_r_2k9_`；点击“源码”因持续变化超时。它不是状态圆点正常的2秒呼吸动画。

修复只做两件事：

- 将 Markdown renderer 类型固定在模块级，保留实例和局部状态。
- 用 React Context 传递最新 `onOpenFile`，避免固定 renderer 后捕获旧回调。

没有关闭状态轮询来隐藏问题，没有修改 Room/Task/记忆状态机，没有改用不受限制的 SVG，也没有另造滚动算法。原 sandbox、CSP、链接策略保留。

## 3. 行为指南究竟整理到了哪里
