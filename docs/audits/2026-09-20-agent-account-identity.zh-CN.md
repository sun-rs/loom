# Agent 账号、显示名及历史身份绑定

## 合同与来源

本批按用户 2026-09-20 明确规则实现：名称创建账号时保留大小写；存活账号精确唯一；显示名可重复；删除后账号可复用，不追加序号。`agentId` 为身份字段，`participantId` 为 Room Principal 外键，两者均不由账号或显示名推导。新旧同名 Agent 的 ID、私聊、任务、活动及私有记忆互相独立。

Raft Computer 1.0.32 发布源码 `main.js:15175` 的 `agentMigrationUpdatedPayloadSchema.agentId` 是独立 UUID；SHA-256 `531f41e2ee626d729c92933fbc753008af42380c5745c54b5d0af9901e43d170`。原始发布包仅作分析证据；未复制 bundle 或假称取得云端唯一索引实现。Web 发布 bundle 的 `pages.identitySetup.usernameHelper` 明确区分提及账号与可变显示名。大小写和删除后复用规则以用户本次要求为准，不声称双边服务端验收。创建失败提示按用户截图置于字段上方，采用内部对话框边框与字体、柔和错误色；这是本地样式适配，不是字节级 CSS 复制。

## 单一 owner 与兼容

- Protocol：当前字段 `agentId`；Kernel/SDK/Web/Host 使用同一字段。SQL 存储列和已有 ID 字符串保留，避免重建身份和私有记忆路径。HTTP 接收旧顶层 `agentDefinitionId` 及旧导航 target；冲突双字段拒绝。旧 revision、event JSON 和执行重置 receipt 读取兼容，持久历史原文不改写。旧版本客户端须随本地工作台升级。
- Kernel schema 57：移除 `principals.handle` 永久 UNIQUE；事务内按 BINARY 精确查重，数据库 trigger 同步兜底，tombstone 不占账号。配置、底层创建和工作台创建共用该规则。Human 的已有账号仍占用统一账号目录；不扩展多人 onboarding。
- Message：`mentions_json` 持久记录 Principal ID、可选 Agent ID、原提及拼写与 UTF-16 范围。新消息与事件在原事务内绑定，已绑定记录不按当前账号重新解析。迁移先固定旧消息（保留旧版不区分大小写的解析结果），再开放账号复用。无法唯一确认的旧提及保存为空解析，不猜测或绑定到后来创建的 Agent。保留正文，不替换聊天中的自我介绍等历史文字。转发携带来源绑定；无可确认来源时保留不可寻址文字。附件评论复用消息绑定。
- UI：正文、列表主标题使用显示名；资料页、悬浮资料和选择器中明确的 `@账号` 使用真实账号，用于区别重复显示名。这取代此前“所有带 @ 的辅助文字也改为显示名”的过宽约定。
- 私聊寻址：新写的 `dm:@账号` 精确解析到存活身份；历史私聊继续按原 Room ID 和原身份读取，账号复用不会合并会话。

不自动改写已存在的 `kimi-2` 或恢复旧账号大小写：那会改变现有寻址事实。本规则用于后续创建，旧身份保持可追溯。
