# 身份显示名称入口核查

展示使用显示名称，缺失时才回退 handle；账号、参与者 ID、提及提交值不被显示名称
替换。用户输入的历史原文、代码块、诊断原始载荷不改写。资料卡中展示的 @名称
现与显示名一致；显式账号编辑字段仍编辑真实账号。新旧 Agent 按 ID 独立解析。

依据：沿用[动态身份审计](2026-09-20-activity-identity-labels.zh-CN.md)的源码证据与
用户明确要求。未声称完成 Raft 每个页面的双边浏览器验收。

| 入口                                           | 核查/修复                                                 | 验证边界                              |
| ---------------------------------------------- | --------------------------------------------------------- | ------------------------------------- |
| 频道、私聊、消息列作者/头像                    | 使用 entities 按 ID 解析；补齐 App 成员与回复预览的显示名 | 身份与 entity 单测、既有浏览器回归    |
| 提及 tooltip、补全菜单                         | 标签改用显示名；插入值仍用 handle                         | 源码核查、类型检查                    |
| Agent 资料、悬浮卡、关系图、创建者摘要         | @展示名一致，配置提交不变                                 | 改名 fixture 先红后绿、正式悬浮卡     |
| Human 资料、悬浮卡、成员列表                   | 已使用 displayName 优先，保留                             | 身份回归测试                          |
| Task 审批、负责人选择、任务标识、任务筛选/历史 | 已通过 entity 解析显示名，保留                            | Task 身份回归测试                     |
| 动态、搜索、已保存摘要                         | Agent 与 Human 提及都按显示名展示；代码/歧义引用保留原文  | 摘要测试先红后绿                      |
| 搜索/已保存私聊结果                            | 后端按私聊 peer ID 取显示名，不依赖旧会话名称             | Kernel owner 与 discovery/social 回归 |
| 附件评论、推送发言人/停止重试通知              | 后端共享 identityDisplayName                              | 评论与 push 回归                      |
| Computer 工作区扫描/删除提示                   | 按 Agent ID 使用当前显示名，不保留扫描时旧 handle         | 源码核查、类型检查                    |

Kernel 抽取 identity-display-name 作为投影显示 owner；调用方先完成原有 ACL，
helper 不扩大查询范围。Agent revision 显示名优先于 principal 显示名/handle，
包含已删除身份。directRoomDisplayName 只为该私聊参与者解析对方身份。
Web workspace-entities 继续作为渲染身份 owner，未增加第二份身份存储。

边界：这是上述入口的源码核查和相关门禁，不是“所有界面所有状态 100%”的声明。
不存在显示名的数据仍合理显示 handle；不把聊天正文里的自然语言自我介绍自动改名。

本批验收：84 项相关单测/集成测试及 5 项 push 测试通过；改名资料页 fixture、
Human/Agent 任务负责人实时名称浏览器回归通过。正式实例完成备份和安全重启，
当前 4 个私聊动态卡片/标题，以及已删除 Gemini/Kimi 悬浮卡的 @显示名均经新
浏览器核对。首次浏览器检查碰到重启尚未监听，服务就绪后重新验证通过。
类型检查、正式构建、本批格式和 diff 检查通过；全仓库 check 仍受既有
worker/message-present 未登记阻断，format:check 仍报告原有 5 个文件。

正式截图复查进一步发现私聊 Composer 仍使用旧 Room 名称，现补齐同会话输入框、
附件目标标签、消息列及任务详情的标题。改名 fixture 通过成员列表双击进入私聊，
断言输入框为显示名；正式已删除 Gemini 的旧 @OpenCode 提示先复现失败，再修复。
最终构建重新备份重启后再次检查实际输入框。
