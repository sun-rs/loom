# 显式刷新有界等待与 Provider 标题修正

用户要求移除展开 Provider 标题的不满行黄色背景，保留白色标题与卡片原有 hover。移除此前本地新增的展开黄底规则，并更新桌面/窄屏断言。

刷新路径由 `apps/web/src/web-build-recovery.ts` 单独持有。原实现无限等待 Service Worker getRegistrations/update/register 以及 CacheStorage 清理；任一操作不结束，location.replace 永远无法执行。浏览器故障注入 getRegistrations 永不返回，旧代码导航超时；现在整个清理最多等待 1500ms，再导航至保留路由的恢复 URL。清理仍仅针对 RAH shell/assets 缓存，没有删除业务数据或新增投递状态。

刷新浮层独立于产品 shell，原来未继承通用按钮 hover，另写了黄色 focus outline。本次显式使用黑色焦点提示，按钮采用已有 Raft btn-brutal-sm 的 2/4/1px 硬阴影及 hover 上移 1px、active 位移 1px 参数；这是恢复 UI 的本地适配，不宣称 Raft 同路径实现。来源见冻结 `docs/evidence/raft-web-20260908-current/index-D8Neh8lc.css` 的 btn-brutal-sm 规则。

验证：刷新浏览器门禁的原故障先失败后通过，包含正常刷新、继续使用、路由保留、窄屏、两个按钮 hover 和无黄色 focus；Provider 卡片浏览器门禁通过。类型检查、400 项 Web 单测、格式、diff 与正式构建通过。全量 check 仍被正在施工的 sq-btn 预算基线和匹配报告阻挡，未放宽门禁。无付费 CLI、提交或推送。

正式实例在验收期间已被并行工作重启，本次重启脚本因旧 PID 已退出而安全拒绝，未重复停止新实例。随后确认新实例服务的 build ID 与上述通过门禁的构建一致，并在新 Chrome 页面验证 Provider 展开白底通过。

## 二次修正：直接原生导航

用户再次报告刷新无效。现场能读取到仍在显示版本横幅，但未复现该内置浏览器的原点击因果；不把此前 Service Worker 超时实验当作现场唯一根因。现在彻底移除异步清理后 location.replace 的刷新入口，改为携带恢复 nonce 的原生链接，清理仅尽力执行、不阻塞导航。浮层初始聚焦容器而非刷新控件，避免自动画出按钮外框；键盘 Tab 仍显示焦点提示。

浏览器测试先确认旧元素不是原生链接而失败，修改后桌面、手机、正常导航、永不返回的 Service Worker、路由保留、hover 均通过。类型检查、400 项 Web 单测、格式和 diff 检查通过，全量检查仍有独立规格登记阻挡。

## 移除页内版本横幅

按用户要求删除“仍然继续”后的横向版本提示及其独立样式。继续操作仍解除页面 inert、释放等待的请求，并记住已忽略的服务器构建，避免同版本在 focus 探测时反复弹出；刷新弹窗及其原生导航入口保留。浏览器回归先复现旧版横幅仍存在，再验证继续后无横幅、页面可操作、重复 focus 不重弹和手动刷新恢复。

## 现场根因：历史响应版本头触发刷新循环

在用户实际内置浏览器中点击后文档发生重新加载，但仍弹窗。新增 DOM 诊断记录明确显示 trigger=fetch_response，clientBuild 是当前正式构建，serverBuild 却是更早的 fad81ccb 构建。点击“仍然继续”可以正常加载帮助。此前原生导航与缓存清理超时测试没有覆盖这个误判，不能作为原故障根因已经消除的证据。

普通 fetch 的历史响应可能带有旧构建头，不能据此确定服务端当前构建。现在遇到差异时通过不经过包装器的 originalFetch，以唯一 nonce、no-store、3秒超时向 shell 发 HEAD 探测。仅当探测成功且当前服务器编号确实不同，才提示；失败或当前编号相同时返回原响应，不阻塞页面。唯一 nonce 单独并未修复现场问题，权威确认才是关键修改。

新增浏览器回归：当前文档接到 cached-old-build 资源响应，必须完成请求且不弹窗。修复前失败，修复后通过；真实升级、继续使用及原生刷新既有用例仍通过。

现场验收：更新正式构建并备份重启后，在用户原内置浏览器标签页直接点击“立即刷新”，页面进入帮助正文、弹窗消失，DOM 确认帮助标题及三个正文段落。此次验收没有依赖“仍然继续”绕过。401 项 Web 单测、类型/格式/diff 检查通过；全量门禁仍受独立组件规格基线阻挡。
