# 官网页面差异复核（2026-10-26）

本报告前半部分记录修复前差异，不是全站对齐验收；后续施工状态见文末。

## 版本和证据边界

- Loom main 8481d850；部署产品 6c2d5480；组件包 @botiverse/raft-ui 0.35.1。
- 官网 Web 1.21.34；可取得的选取源码基线 db5e399（Web 1.21.23）。两者不是同一版本。
- 实际页面：已登录 Firefox 的 app.raft.build/s/hakasemac；本机 Chrome 的 127.0.0.1:4176。不同浏览器，仅用来证明入口、状态和组合差异，不据此声称像素尺寸差异。
- 官网动态：从聊天切换动态，恢复上次详情；点击关闭后仍有列表分隔条与“没有打开的对话／从列表里选一个。”。因此准确规则不是每次进入都清空详情，而是宽屏无选择时仍保留空正文。
- 官网 settings/theme 和 settings/appearance 均通过可访问性树现场检查；没有更改任何主题、通知、账户配置。

## 进一步核验，尚不作缺陷结论

1. 分栏最大宽度和折叠：组件包新版提供布局能力，Loom 动态仍固定 min400/max720/default560；需要取得官网当前页面参数并在相同容器尺寸验证，不能直接用包变更日志当网页参数。
2. 移动动态滑动、下拉刷新：包支持不等于官网每页启用；需双端手势验收。
3. Loom 动态 DOM 中具名 radio 后还有无名 radio，需检查新旧 SegmentedControl 组合是否重复暴露语义。未操作键盘，尚未判定功能缺陷。
4. 消息、任务、成员、计算机、搜索的当前样式与交互仍需逐页矩阵；本轮没有全站像素验收结论。

## diff 漏洞根因

scripts/official-web/upstream-diff.mjs 的 inventory/inventoryDependency 均从既有锁清单 Object.entries(files) 遍历：

- 已锁定文件的字节比较有效，但不枚举候选中新加入的页面/组件。
- 90 个选取源码不变只证明这90个文件完整，不代表官网1.21.34没有改变。
- loom/ 下的页面组合没有官方相同路径，工具仅在 limits 中说明，不会给出行为差异。
- 包升级验收覆盖既有消息、表单、移动与分栏的回归，未验证新版新增页面功能。
- 工具明确写了“Not evaluated”，但交付表述没有始终保持这个边界。这是比较覆盖和结论外推的问题，不是哈希算法失效。
