# 分栏宽度与拖拽记忆实施

## 范围与来源

本批只改搜索、动态、聊天的分栏几何、拖拽和本地宽度偏好；不改导航按钮、返回路径、任务审批、加载状态或调度。任务列表／看板及审批弹窗不采用本批发现列表规则。

来源为 [Raft v1.17.3 源码与官方页面测量](2026-09-21-raft-width-render.zh-CN.md)，该报告及关联 JSON 记录 URL、SHA、符号与测试前提。采用来源参数与记忆分组，继续复用 RAH 自有布局 owner 和共享拖动原语；未复制发布 bundle、未新增上游代码或许可材料。Multica 对照沿用[共享导航合同](../product/shared-conversation-navigation.zh-CN.md)已记录的版本与边界，其桌面路由不提供这里的跨大页三栏规则。

## 几何合同

| 类型             | 默认  | 拖动范围                             | 偏好分组               |
| ---------------- | ----- | ------------------------------------ | ---------------------- |
| 聊天列表         | 240px | 180–320px                            | 独立                   |
| 搜索／动态宽档   | 560px | 400–720px                            | 两大页共享             |
| 搜索／动态紧凑档 | 320px | 320–480px                            | 两大页共享，与宽档分开 |
| 消息列           | 400px | 360px 至 max(400px, floor(视口×60%)) | 独立                   |
| 人物资料         | 380px | 300–600px                            | 独立于消息列           |

发现列表视口不足 1024px 或继续打开子面板时切换紧凑档。拖动上限同时为正文保留 320px（相比此前 400px 是有意调整），最低列表宽度不变。第三栏先受剩余空间约束，正文低于 320px 时隐藏中间内容：消息列需要 680px，人物资料需要 620px；均指扣除导航条和列表后的空间。低于 768px 沿用单屏规则。高度、横竖屏、PWA 标志不参与折叠判断。

## 单一 owner 与记忆

`ConversationLayoutShell` 管理连续宽度，只把离散折叠模式通知 App；不会因每个拖动事件重建消息内容。搜索／动态使用同一个 hook 实例。CSS 使用独立人物资料宽度变量，避免误读消息列偏好。

继续使用浏览器本地存储，不同步到服务器／其他设备。已有合法 search 宽度优先，缺失或无效时读取旧 activity 值；宽／紧凑分别迁移，读取不写回、不删除旧值。保存仍用 search 键作为共同键。聊天、消息列和人物资料沿用各自原键。

窗口压缩只限制实际显示，不写回偏好。手机宽度刷新后再放大，消息列重新读取可用桌面偏好。拖拽以实际可见栏宽为起点，避免偏好栏宽被 CSS 压缩后首次拖动跳变；最终位置在 pointer ref 中同步保存。单击分隔线不应提交临时压缩值。双击分隔线，或聚焦后按 Enter，恢复当前类型／档位的默认值。
